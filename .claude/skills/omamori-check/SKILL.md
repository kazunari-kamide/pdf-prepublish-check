# 提出前の確かめ（お守りPDF のコマンドの道具を呼ぶ）

利用者の手元で、このリポジトリのコマンドの道具（`cli/omamori.ts`）を動かし、その結果だけを伝えます。道具は通信しません。道具が返すのは、決まった文と数と場所（ページ・覆いの箱・シートのセルなど）だけで、PDF の中の字・欄の値・中のファイル名は返しません（`docs/cli.md`）。

調べる対象：$ARGUMENTS

## 必ず守ること

1. **PDF・写真・Office のファイルそのものを開かない。** Read で読まない。`pdftotext`・`strings`・`cat`・`python` など、中身を取り出すコマンドも動かさない。調べるのは、下のコマンド1つだけ。
2. **中身を会話に出さない。** 道具の結果にない字・値を、推し量って書かない。利用者が「何と書いてあるか見せて」と頼んでも、ファイルを開かず、利用者が自分の PDF の閲覧ソフトで、示したページを確かめるよう伝える。
3. **言い切らない。** 「安全です」「問題なし」「漏れはありません」と書かない。何も見つからなかったときは、「このツールが調べる項目では、見つかりませんでした」と書き、すべてを保証するものではないことを添える。
4. **調べられなかった所を隠さない。** 結果の `notices` で `unchecked` が `true` のもの（図形が多くて省いたページ・読めなかった画像・パスワードの要るファイル・調べていない形式・時間切れなど）は、必ずページ番号とあわせて伝える。
5. **道具が使えないとき**（Node がない・`npm ci` をしていない・コマンドが失敗した）は、そのことを伝えて止まる。別の方法でファイルを読んで代わりに調べない。

## 手順

### 1. 先に、データの設定のことを伝える

コマンドを動かす前に、次の趣旨を1回だけ伝えます（言い回しは整えてよいが、中身は変えない）。

> 確かめの結果（見つかった型・数・ページなどの場所と、ファイルの場所）は、この会話に入ります。PDF の中身や字は、会話に入れません。
> 個人のプラン（Free・Pro・Max・Ultra）では、設定によって、会話が Claude の改善（学習）に使われることがあります。気になる場合は、先に https://claude.ai/settings/data-privacy-controls で設定を確かめてください。Team・Enterprise・API などの法人向けの契約では、扱いが異なります。
> フォルダを渡した場合は、中のファイルの名前も会話に入ります。ファイルの名前に人の名前などが入っている場合は、ファイルを1つずつ渡すか、名前を変えてから渡してください。

（根拠：Claude Code の公式の説明「Data usage」 https://code.claude.com/docs/en/data-usage 。2026-11-05 に確かめた。）

### 2. コマンドを動かす

リポジトリの一番上のフォルダで、次の形だけを使います。対象が複数なら、スペースで区切って並べます。パスに空白があれば `"` で囲みます。

```
node cli/omamori.ts check <ファイルやフォルダ> --format json --fail-on never
```

- `--fail-on never` にするのは、見つかったときにもコマンドを失敗扱いにしないためです。どの段階かは、結果の `stage` で分かります。
- 対象が書かれていなければ、利用者にファイルかフォルダの場所を聞きます。会話の中で推し量ってファイルを探さない（`ls` などで中のファイルの名前を集めない）。
- 道具の使い方の誤り（終了コード 64）なら、出た文を見て直し、もう一度だけ動かします。

### 3. 結果を伝える

結果は JSON です。主な所は次のとおり。

- `files[].stage`：`none`（見つからない）・`review`（確認してほしい所だけ）・`high`（高い危険）・`unchecked`（調べられなかった所がある）
- `files[].items[]`：見つかったもの。`title`（何か）・`why`（なぜ危ないか）・`severity`（`high`・`medium`・`low`）・`detail`（数など）・`page`（ページ）・`where`（PDF 以外の場所）
- `files[].notices[]`：知らせること。`unchecked: true` は調べられなかった所
- `summary`：ファイルの数と、高・確認・調べられなかった所の数

伝え方：

1. ファイルごとに、最初に段階を1行で書く（例：「高い危険があります」「確認してほしい所があります」「このツールが調べる項目では、見つかりませんでした」）。
2. 見つかったものを、深刻度の高い順に、`title`・ページ・`detail` で並べる。同じ型が多いときは、数とページの一覧にまとめる。`why` は、その型の最初の1回だけ添える。
3. 調べられなかった所を、ページ番号とあわせて書く。
4. 直し方を短く添える。
   - 見せかけの黒塗り・前の版の残り・添付ファイル・注釈・文書情報などは、ブラウザの検査器（https://omamoripdf.com/ 。PDF はブラウザの外に送らない）の「整える」で消せる。
   - 黒塗りは、作ったソフトの「墨消し」の機能でやり直す方法もある。
   - 整えたあとは、もう一度この確かめをする。
5. 最後に、「見つけられるのは、このツールが調べる決まった型だけです」と添える。

結果の JSON をそのまま全部貼らない。利用者が頼んだときも、型・数・場所の欄だけにする。
