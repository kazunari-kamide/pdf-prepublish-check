# <img src="design/logo/mark.svg" alt="" width="48" height="48"> お守りPDF

**公式の URL は `https://omamoripdf.com/` だけです。** この URL 以外で公開されているものは、改変されている可能性があります。

PDF を公開・提出する前に、作った本人が自分で確かめるための検査器です。黒塗りの下に残った文字、作成者の名前、前の版の残り、添付ファイル、見えない文字など、**見た目では分からない情報**を見つけて、整えて、消えたことを確かめます。

**検査のページ：`https://omamoripdf.com/check`**

- PDF は、お使いの端末のブラウザの中だけで読みます。どこにも送りません。
- 無料で、ログインは要りません。
- 見つけられるのは、下に並べた種類だけです。すべての漏れを見つけられるわけではありません。

**誰のための道具か**：資料を PDF で公開・提出する担当の人です。黒塗りしたつもりの字や作成者の名前は、画面で見ても気づけません。公開したあとで、ほかの人に取り出されて初めて分かります。

**試し方**
- ブラウザ：`https://omamoripdf.com/check` に PDF を入れます。手元に無ければ「見本の PDF で試す」（架空の申請書）を押します。
- コマンド：リポジトリで `npm ci` のあと、`npx omamori-pdf check <ファイルかフォルダ>` を打ちます。フォルダごとまとめて調べ、型・数・場所だけを出します（[docs/cli.md](docs/cli.md)）。

**Claude の使い方**：検査器の中では、Claude は動きません。Claude を使うのは、検査のルールを育てるループ（Ratchet）だけです。
- Claude が、事前に集めた公開 PDF を読み、今のルールで捕まらない漏れ方を挙げます。別の Claude が反証します。
- 残った候補は、Claude がルールと合成のテスト用 PDF にします。ルールとは別に作った検証器が採点し、基準を満たしたものだけが PR になります。
- マージするかは人が決めます。これまでの PR は 4 本で、3 本をマージし、1 本は理由を書いて却下しました（[下の「検査のルールの育て方」](#検査のルールの育て方)）。

## 使い方：見つける → 整える → 消えたことを確かめる

1. **見つける**：検査のページに PDF を入れると、ブラウザの中で調べ、種類ごとの結果（何が・何件・どのページに）を出します。手元に PDF がなければ、「見本の PDF で試す」（架空の申請書）で試せます。
2. **整える**：「整える」を押すと、見つけた情報を消した PDF を作ります。何を消すかは、押す前に「整える内容」で確かめられます。
   - 見つかった種類ごとに印があり、印を外した種類は整えずに残します（外せるのは、注釈・添付ファイル・写真の位置情報など・フォームの入力値・スクリプトの 5 つ）。最初は、深刻な物（高・確かめる）を含む種類と、スクリプトに印が入っています。外した種類は、結果の画面に必ず並べます。
   - 押すと、整える前の確かめが出ます。
   - 氏名・電話番号など、個人情報らしい字は、黒塗りにするかをあなたが決めます（自分で黒塗りする所を選べます）。お守りPDF が勝手に消すことはありません。
3. **消えたことを確かめる**：整えた PDF を、整えた仕組みとは別の読み方で、最初から読み直します。種類ごとの数を「整える前 → 読み直したあと」で並べ、残っていた所・消せなかった所があれば、場所と一緒に出します。

提出先に容量の決まりがあるときは、整えたあとに、ファイルを小さくすることもできます（画像の細かさを選びます）。

「見つかりませんでした」「残っていません」は、**この道具が調べた項目についての結果**です。PDF が安全だという保証ではありません。

## なぜ要るか

PDF は、画面に見えている中身のほかに、いろいろな情報を持っています。

- 黒い四角を上に重ねただけの黒塗りでは、下の文字がコピーや検索で取り出せます。黒塗りした資料の下の文字を取り出せた、という事故は、これまでに何度も報道されています。
- Word などで作った PDF には、作った人の名前が自動で入ることがあります。
- 上書きで保存した PDF には、直す前の版が残ることがあります。

どれも、画面で見ただけでは気づけません。公開・提出の前に、決まった手順で確かめられるようにするのが、この道具の役目です。

## 何を調べるか（型の一覧）

型の番号は、検出ルール・テスト用の PDF・記録で共通に使います（用語は [docs/glossary.md](docs/glossary.md)）。

| 番号 | 型 | 何が残るか |
|---|---|---|
| P1 | 文書情報 | 作成者・タイトル・作成ソフトなどの欄 |
| P2 | XMP メタデータ | 埋め込まれたメタデータの中の作成者・編集の履歴 |
| P3 | ほかの団体の名前 | 流用した様式の、元の団体の名前 |
| P4 | ファイルの保存先 | 作ったパソコンの利用者名・職場のサーバーの場所 |
| P5 | 旧版の残存 | 上書きの前の版 |
| P6 | 見せかけの黒塗り | 黒い四角の下の文字・画像 |
| P7 | 隠れたテキスト | 白い文字・ページの外の文字・表示を切ったレイヤー |
| P8 | 注釈・コメント | コメントの中身と、付けた人の名前 |
| P9 | 添付ファイル | 埋め込まれた元の Excel・Word など |
| P10 | 画像の位置情報など | 写真の撮影場所・機種・日時 |
| P11 | フォームの入力値 | 入力欄に入ったままの値 |
| P12 | スクリプト・外部動作 | 開いたときに動くスクリプト（漏れではなく、安全上の注意） |
| P13【仮】 | 個人情報らしい字 | 見える文字の中の、氏名・住所・電話番号などらしい字。**黒塗りの候補**として示すだけで、「整える」では消しません |

型ごとの説明と正しい直し方は、サイトの[記事の一覧](https://omamoripdf.com/articles/)にあります。

## 測った数字

数字は、すべてこのリポジトリの合成した PDF（架空の名前・番号で作ったもの）で測った値です。**実際の PDF でも同じとは限りません。** 手元で同じ数字を出す方法は、下の「誰でも手元で、同じ数字を出せます」にあります。

### 型ごとの採点（`npm run eval`）

合格基準は、検出率 95% 以上・誤検知率 5% 以下・整えたあとに残る情報 0 件です（`rubric/`）。

| 型 | 検出 | 誤検知 | 整えたあとに残る情報 |
|---|---|---|---|
| P6 見せかけの黒塗り | 32 件中 32 件 | 21 件中 0 件 | 0 件 |
| P1 文書情報 | 22 件中 22 件 | 20 件中 0 件 | 0 件 |
| P9 添付ファイル | 21 件中 21 件 | 15 件中 0 件 | 0 件 |
| P5 旧版の残存 | 24 件中 24 件 | 20 件中 0 件 | 0 件 |
| P7 隠れたテキスト | 20 件中 20 件 | 17 件中 0 件 | 0 件 |
| P13【仮】個人情報らしい字 | 48 件中 48 件 | 76 件中 0 件 | 測らない（整えるでは消さないため） |

「整えたあとに残る情報」は、**整える種類のすべてに印を入れたとき**（どの種類も外さないとき）の値です。印を外した種類は、整えずに残ります。

この採点の正解データは、ルールを書く側が作ったものです。ルールの作り方に合わせた正解になっていないかを確かめるため、次のテスト集でも測っています。

### 見ないで作ったテスト集（`npm run eval:blind`）

ルールのコードを見ないで、型の説明だけから作った合成 PDF（246 個・98 の型）です。

- 型ごとに全部が期待どおりだった型：98 の型のうち 98
- 隠しのある PDF で見つけた数：140 件中 140 件
- 対照（出てはいけない PDF）で出てしまった数：101 件中 0 件
- 整えたあとに、仕込んだ目印の字か、覆いの下の画素が残った数：126 件中 6 件（重ね描きした字・代わりの説明 /Alt・フォームの説明・注釈の見た目の中だけにある字・フォームの値）

整えたあとの数も、整える種類のすべてに印を入れたときの値です。

最初に測ったとき（2026-11-04）は、140 件中 73 件・対照 101 件中 7 件でした。そのあと、このテスト集で落ちた型を見て、ルールを直しています。そのため、上の数字は「初めて見る PDF での値」ではありません。

改善のたびの数字は [docs/evolution.md](docs/evolution.md) に残しています。

| 型 | 検出（作品／1回の指示の版） | 誤検知（作品／1回の指示の版） | 整えたあとに残る情報（作品／1回の指示の版） |

| P6 見せかけの黒塗り | 32 件中 32 件／32 件中 23 件 | 21 件中 0 件／21 件中 0 件 | 0 件／扱えない（整える機能がない） |
| P1 文書情報（その版が出した欄すべて） | 22 件中 22 件／22 件中 22 件 | 20 件中 0 件／20 件中 7 件 | 0 件／扱えない |
| P1 文書情報（その版が「要確認」とした欄だけ） | 22 件中 22 件／22 件中 12 件 | 20 件中 0 件／20 件中 0 件 | 0 件／扱えない |
| P9 添付ファイル | 21 件中 21 件／21 件中 18 件 | 15 件中 0 件／15 件中 7 件 | 0 件／扱えない |
| P5 旧版の残存 | 24 件中 24 件／扱えない | 20 件中 0 件／扱えない | 0 件／扱えない |
| P7 隠れたテキスト | 20 件中 20 件／扱えない | 17 件中 0 件／扱えない | 0 件／扱えない |

- 「扱えない」は、その版が場所や理由を出さないため、同じ決まりで照らし合わせられないものです（P5 は前の版のオブジェクトの番号・場所、P7 は見えない理由と場所）。点を作らないよう、その版が出したものだけを写しています。
- P6 の内訳：その版は、字の上の黒塗りは 24 件中 23 件を見つけましたが、スキャン画像の上の黒塗りは 8 件中 0 件でした。
- P1 は、その版が欄を「要確認」と「参考」に分けて出すので、2 通りで数えました。

- 作品の側は、このテスト集で落ちた型を見てルールを直してきました（上の「見ないで作ったテスト集」）。1回の指示の版は、このテスト集を一度も見ていません。そのため、この差には、作品がテスト集に合わせて直した分が入っています。
- テスト集の対照 1 個（黒い帯の上の白い見出し）は、前の版では、その下の本文まで白で描いていました。直したあとに、両方とも測り直しています。
- 型の定義だけでは当てる型を決めきれなかった、その版の出力が 3 種類あります（縮小画像・編集用データ（/PieceInfo）・XFA）。この 3 つは「当てない」にしました。当てた場合は、出したものすべての数え方で、型が 48 → 49、見つけた数が 98 → 100、誤検知が 14 → 16 になります（前に当てて測ったときの差〈+1・+2・+2〉を足した値。今回は当てて測っていない）。

## 検査のルールの育て方

検出ルール（`rules/`）は、Claude が少しずつ育てています。

1. **見つける**：事前に集めた公開 PDF を読み、今のルールで捕まらない漏れ方の候補を出します。別のエージェントが反証します。
2. **ルールにする**：検出ルールと、合成したテスト用 PDF・正解データを書きます。実在の PDF はテストに入れません。
3. **確かめる**：検証器（`verifier/`）が、ルールとは別の読み方で採点します。合格基準と検証器は、Claude には書き換えさせません。
4. **配る**：基準を満たしたら PR を出して止まります。マージするかは人が決めます。マージされたものだけが検査器に入ります。

利用者の PDF は、このループに一切入りません。検査器は Claude なしで動きます。

- **Claude の呼び方**：ループ（`npm run ratchet`）は、運営の Claude API（Messages API）で下読み・判断・反証を呼び、ルールと見本を書く段は Claude Code（`claude -p`）で動かします。ルールを育てた実物の回（実物の束での 3 回と、3 回目の候補をルール書きからやり直した 1 回）は、どれも `claude -p` で呼びました。Claude API では、2026-11-07 に試しの 1 回を最後まで回しました（候補は 0 件）。詳しくは [`docs/ratchet.md`](docs/ratchet.md)。
- **これまでの結果**：ループが出した PR は 4 本です。人が確かめて、3 本をマージし（#175・#176・#182）、1 本を理由を書いて閉じました（#177。根拠にした件数と、実物の束にかけて当たった数が合わなかったため）。
  - #182（黒塗りのそばに塗られず残った、郵便のバーコードのような記号）は、3 回目の候補をルール書きからやり直したものです。根拠にした実物 53 件のうち 7 件で当たり、当たった 7 件は人が画像で確かめました。別の束 100 件では、当たったのは 1 件（下調べで見つけた本物と同じ PDF）で、残り 99 件は 0 件でした。
- **定時に回す設定**：毎日 5:00・20:00 に、手元の束だけを、費用の上限 5 ドルで回す設定があります（[`ratchet/schedule.json`](ratchet/schedule.json)、手順は [`docs/ratchet-schedule.md`](docs/ratchet-schedule.md)）。まだ定時で回したことはありません（タスクスケジューラへの登録もしていません）。

## ほかの入口

- **コマンドの道具（`cli/`）**：フォルダごとまとめて確かめます。PDF のほか、写真（JPEG・PNG・WebP・HEIC）と今の Office（docx・xlsx・pptx）も調べます。型・数・場所だけを出し、通信しません。使い方は [docs/cli.md](docs/cli.md)。
- **Claude Code のスキル（`.claude/skills/omamori-check/`）**：あなたの Claude に「提出前にこの PDF を確かめて」と頼むと、手元で上のコマンドの道具を動かし、型・数・場所だけを伝えます。PDF の中身や字は、会話に入れません。こちらのサービスは何も受け取りません。使う前に、あなたの Claude のデータの設定（会話が改善に使われるか）を確かめてください。
- **通信を数える拡張機能（`extension/`）**：お守りPDF のページが、PDF を入れたあとに送ったデータの大きさと要求の数を、検査器の外側から数えて見せます。入れ方は [extension/README.md](extension/README.md)。

## 通信について

- ブラウザから外への通信は、最初の表示でも、PDF を入れた後でも、0 件にしています。アクセス解析のスクリプト・広告・外の書体は入れていません。Cookie も使いません。
- 開いた回数などは、配信先のサーバーがふつうに残す記録（IP アドレス・参照元・ブラウザの種類・時刻・求められた場所）だけで数えます。PDF の中身・ファイル名・画面の操作は、サーバーに届きません。説明は[プライバシーについて](https://omamoripdf.com/privacy)。
- 確かめ方は [docs/no-network.md](docs/no-network.md)。ビルドしたファイルの確かめ（`npm run build`）と、本物のブラウザで要求を数える確かめ（`npm run check:browser`）を、配信のたびに動かします。
- 配信するファイルごとの SHA-256 の一覧は、配信のたびに GitHub のリリース（`deploy-<コミットの短い印>`）に載せています。
- 公開中のサイトが、このリポジトリのコードと同じものかは、手元で確かめられます（くわしくは [docs/deploy.md](docs/deploy.md)）：
  1. リリースのコミットを、行の終わりを変えずに取り出す（Windows では `git clone -c core.autocrlf=false …`）
  2. Node 24.19.0 で `npm ci --ignore-scripts` と `npm run build` をする
  3. `cd dist && find . -type f -print0 | LC_ALL=C sort -z | xargs -0 sha256sum` の出力を、リリースの一覧と比べる
- CSP（ページの読み込み先と送り先を絞る決まり）も使っていますが、これは被害を減らす層の1つで、送れないことの保証ではありません。

### SNS などにリンクを貼るとき

どこに貼ったリンクから来たかを数えるため、`https://omamoripdf.com/check?utm_source=x` のように、貼る所の名前を `utm_source` に付けます（ページのスクリプトでは読まず、サーバーの記録に残る URL として数えるだけです）。

## 誰でも手元で、同じ数字を出せます

検出ルールの採点に使うテスト用の PDF（`fixtures/`）は、すべて架空の名前・番号で作った合成の PDF です。ソースコードと一緒に公開しているので、手元で同じ数字を出せます。

```sh
npm ci                  # package-lock.json のとおりに入れる（Node 22.12 以上）
npm run eval            # 型ごとに、検出率・誤検知率・整えたあとに残る情報を採点する
npm run eval:blind      # 見ないで作ったテスト集で、型ごとの合否表を出す
npm test                # テスト
npm run build           # ビルドと、ビルドしたファイルの確かめ
npm run check:browser   # 本物のブラウザ（Chrome か Edge）で開き、外への要求を数える
npm run dev             # 手元で検査のページを開く（/check。/ から開いても移ります）
```

## 質問・不具合・脆弱性の知らせ

- 窓口は、公式のサイトのお問い合わせのページ（`https://omamoripdf.com/contact`）のフォームだけです。
- **業務の PDF の中身や、実在の人名・団体名、見つかった字の中身を書かないでください。**
- 脆弱性（セキュリティの弱点）は、種類で「セキュリティの弱点」を選び、何が起きるか・再現の手順・ブラウザの種類と版を本文に書いて送ってください。追加で聞くことがあるので、メールアドレスは必ず書いてください。直すまでの間は、中身を公開しないでください（[SECURITY.md](SECURITY.md)）。
