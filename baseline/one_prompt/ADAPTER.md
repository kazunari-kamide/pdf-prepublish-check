# 「1回の指示で作った版」を、今の採点で測る

「1回の指示で作った版」（本人が別のセッションで、1回の指示で作らせた PDF の検査ツール）を、`fixtures/` の合成 PDF にかけ、型ごとに検証器と同じ形の報告（`<合成PDFの名前>.json`）にして、`npm run eval:pN -- --reports <フォルダ>` で採点するための手順と道具です。

- **その版のフォルダは読むだけ**で、直しません。置き場所はリポジトリに書きません（手元のパスのため。CLAUDE.md §2-9）。`--app` か環境変数 `ONE_PROMPT_APP_DIR` で渡します。
- その版のコードは、このリポジトリに写していません。道具が、その版のファイルをそのまま読み込んで動かします。
- 書き出すもの（生の結果・報告）は、合成 PDF の字（架空の名前）を含むので `.tmp/` の下に置き、コミットしません。
- ライブラリは足していません。Chrome（か Edge）と、Node 22 以上の標準の WebSocket だけで動きます。

## その版の作り（読んで分かったこと）

- ブラウザの中で動くページ（`index.html`・`app.js`。PDF.js を同梱）。PDF を入れると `analyze()` がページを描画し、画素と字の位置を突き合わせて、結果を画面に並べる。
- 結果は画面の表示だけで、ファイルには出さない。位置は描画した画像の座標（画素）で、印（`marks`）として持っている。
- **片付ける機能はない。** 保存のボタンは、添付や前の版を取り出すだけ。

## 道具

| ファイル | すること |
|---|---|
| `run-baseline.mjs` | その版を頭なしの Chrome で動かし、合成 PDF ごとに、その版の生の結果を `<out>/raw/<型>/<名前>.json` に書く |
| `to-reports.mjs` | 生の結果を、型ごとに検証器と同じ形にして `<out>/reports/<型>/<名前>.json` に書く |

`run-baseline.mjs` のしくみ：

1. その版のフォルダのファイルを、道具の中の小さな配信（127.0.0.1 だけ）でそのまま返す。
2. **`app.js` だけは、末尾に「結果を取り出す口」を足して返す**（ディスクのファイルは変えない）。口は、その版の `analyze()` をそのまま呼び、終わったあとの状態（`current`）を写すだけ。判定には手を入れない。あわせて、`analyzePage()` と同じ式で描画の倍率を作り直し、画素の座標をページの座標に戻すのに使う。添付の名前は、その版と同じ `getAttachments()` から取る。
3. 合成 PDF は1つごとにページを開き直して、前の結果を持ち越さない。
4. パスワードを聞く窓が出たら「キャンセル」する（利用者が入力しないのと同じ）。そのときは「開けなかった（`encrypted`）」と数える。

## 手順（PowerShell。リポジトリの根で、1行ずつ）

```powershell
$env:ONE_PROMPT_APP_DIR = "<その版のフォルダ>"
node baseline/one_prompt/run-baseline.mjs
node baseline/one_prompt/to-reports.mjs
npm run eval:p1 -- --reports .tmp/one-prompt/reports/p1
npm run eval:p1 -- --reports .tmp/one-prompt/reports/p1-high-mid
npm run eval:p9 -- --reports .tmp/one-prompt/reports/p9
npm run eval:p6 -- --reports .tmp/one-prompt/reports/p6
```

- `run-baseline.mjs` の書き出し先は、`--out <フォルダ>` で変えられる（`to-reports.mjs` にも同じ `--out` を渡す）。型を1つだけにするなら `--only p6`。
- 道具が動いているかは、その版に付いてきた試しの PDF で確かめられる：`node baseline/one_prompt/run-baseline.mjs --file "<その版のフォルダ>\tests\out\leaky.pdf"`（`<out>/raw/file/leaky.json` に書く）。
- 片付けたあとに残る情報（`--sanitized`）は測らない。その版に片付ける機能がないため。

## 型ごとの写し方

その版が**出したものだけ**を写します。出していない位置・種類・理由を、推して足しません。

| 型 | 写せるか | その版の何を写すか |
|---|---|---|
| P1 文書情報 | 写せる | PDF.js で読んだ Info の欄のうち、その版が報告に出した欄。`p1/`：出した欄すべて（「参考」の Title・Subject・Keywords・Creator・Producer を含む）。`p1-high-mid/`：「要確認」として出した欄だけ（Author と独自の欄） |
| P9 添付 | 写せる | 名前の木の添付（`where: names`）と、ページの添付ファイルの注釈（`where: annotation`）。名前はその版が出したファイル名 |
| P5 前の版 | **扱えない** | その版は「前の版にだけある字の行」を出すが、オブジェクトの番号・種類・場所を出さない。P5 の照らし合わせ（同じ番号・種類・場所）に使えない |
| P7 隠れた字 | **扱えない** | その版は「見えない文字」を出すが、見えない理由（白い字・透明・レイヤーなど）を分けない。「ページの外」「小さい字」は理由が分かるが、位置を出さない。P7 の照らし合わせ（同じ理由・箱の重なり）に使えない |
| P6 見せかけの黒塗り | 写せる | 「黒塗りの下に文字」の印 → 字の層。「画像の上に黒い図形」の印 → 画像の層。箱は印の四隅を、描画の倍率の逆でページの座標に戻したもの。覆っているものの種類は出さないので `cover: "unknown"`（照らし合わせには使わない）。字数は、その版が出した字の数 |

写さなかったもの（数だけ `to-reports.mjs` が出す）：

- P6：「適用されていない墨消し注釈」の報告。その版はページ番号だけを出し、位置を出さないため。
- P5・P7：上の表の理由。その版が出したものの数（前の版を出した PDF の数、見えない文字・ページの外・小さい字の件数）だけを、参考に出す。

## 確かめたこと（2026-11-04、Node 24.19.0、Chrome、Windows）

- 合成 PDF 124 個（P1 18・P9 20・P5 25・P7 25・P6 36）にかけた。開けなかったのは p5-25（パスワードつき。その版がパスワードを聞いてきたので、キャンセルした）だけ。
- 2回かけて、写した報告は1バイトも変わらなかった。
- その版に付いてきた試しの PDF（`leaky.pdf`）では、「画像の上に黒い図形」の印が3つ出た。頭なしの Chrome でも、その版の画像の判定は動いている。
- 座標の戻し方：p6-t01 で、その版の印の箱 [108, 697.6, 156, 711.4] と、正解の覆いの箱 [106.5, 697.06, 157.5, 712.05] が重なった。

測った数字は、この道具を足した PR の本文にある。
