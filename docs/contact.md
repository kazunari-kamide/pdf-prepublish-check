# お問い合わせのフォーム

お問い合わせは、サイトのお問い合わせのページ（`/contact`）のフォームだけで受け付ける（2026-11-05 本人が決定）。GitHub の Issues・非公開の脆弱性の報告は、窓口として案内しない（本人が見ていないため）。

## 作り

```
/contact を開く（GET。/contact.html で来たら、.htaccess が /contact へ 301 で移す）
   │  .htaccess が中で contact-send.php へ回す（アドレスは変わらない）
   ▼
contact-send.php：フォームのページを返す。隠れた欄 t に「開いた時刻と、secret で作った署名」を入れる
   │  「送る」：ブラウザのふつうのフォームの送信（POST）。同じサイトだけ。スクリプトなし
   ▼
contact-send.php：確かめる → 迷惑防止 → 運営者へのメール 1 通 → 「受け付けました」のページ
   │  入力の誤り・早すぎる送信のとき：同じフォームを、書いた中身・誤りの一覧・新しい印つきで返す
   ├─ 読む：../contact-config.php（届け先などの本物の設定。public_html の外。本人が置く）
   └─ 書く：../contact-data/rate.json（迷惑防止の記録。鍵つきのハッシュと時刻だけ。最長 24 時間）
```

| ファイル | 置き場 | 中身 |
|---|---|---|
| `server/contact-send.php` | リポジトリ | PHP のもと。ビルドで、フォーム（`contact.html` と同じもの）・受け付けた・送れなかったのページの HTML を差し込む（`site.ts` の `contactSendPhp`） |
| `dist/contact-send.php` | 配信で `public_html/` | ビルドで作ったもの。直接書き換えない |
| `dist/contact.html` | 配信で `public_html/` | 静かなフォームのページ。本番では `.htaccess` の書き換えで PHP が返すので、ふつうは使われない（手元の確かめ・`.htaccess` が効かないときの控え。印の欄が空なので、そのままでは送れない） |
| `server/contact-config.sample.php` | リポジトリ | 設定のひな形。本物の値は書かない |
| `contact-config.php` | 配信先の `public_html` の **1 つ上**（本人が置く） | 届け先・送信元・鍵 |
| `contact-data/` | 同じく public_html の 1 つ上（PHP が作る） | 迷惑防止の記録 |

- 検査のページ（`/check`）と、そのほかのページの CSP は変えない。お問い合わせのページと `contact-send.php` だけ、CSP の `form-action` を `'self'` にし、参照元の決まり（`Referrer-Policy`）を `same-origin`、`Cache-Control` を `no-store` にする（`csp.ts` の `contactHeaders`。`.htaccess` の `<FilesMatch>` で上書きする）。`connect-src 'none'` などはそのまま。
- **ヘッダーは `.htaccess` だけが付ける。** PHP の `header()` でも同じ名前を付けると、Apache の `Header always set` と重なって 2 つになるおそれがあるため。PHP が付けるのは `Content-Type` と、`Allow`・`Retry-After` だけ。`X-Powered-By` は外す。2 つになっていないことは `check-live` が確かめる（値が 1 つずつ同じであること）。
- 参照元の決まりを `same-origin` にするのは、同じサイトへの送信に `Origin` を付けさせるため（`no-referrer` のままだと、フォームの送信の `Origin` が `null` になる）。ほかのサイトへは、これまでどおり何も送らない。
- 動かすには PHP 8.0 以上と、`mbstring` が要る（Xserver のサーバーパネルの「PHP Ver.切替」で、`omamoripdf.com` の版を確かめる）。

## 受け付けの決まり（`server/contact-send.php`）

上から順に確かめる。

| 確かめ | 合わないとき |
|---|---|
| GET・HEAD はフォームを返す。POST のほかは受けない | 405（`Allow: GET, HEAD, POST`） |
| 送った中身が 64KB まで | 413 |
| フォームのふつうの送り方（`application/x-www-form-urlencoded`）で、ファイルがない | 400 |
| 設定（`contact-config.php`）があり、形が合う | 503（「いまは受け付けられません」）。メールは出さない |
| 同じサイトのページから送った：`Sec-Fetch-Site: same-origin`（今のブラウザ）か、それがない古いブラウザでは `Origin` が公式のサイト。`Origin` が付いていて違えば止める（CSRF の対策。Cookie は使わない） | 403 |
| 人には見えない欄（`hp_x7q`）が空 | **送ったふりをする**（200 の「受け付けました」）。メールは出さない。その接続元の続けての数には入れるが、1 日の上限には数えない |
| 開いた時刻の印が、本物で、開いてから 4 秒以上・2 時間以内 | 400。書いた中身つきのフォームを、新しい印で返す（もう一度押せば送れる） |
| 種類が 4 つのどれか・本文が 10〜4000 字（前後の空白を除く）・本文の URL が 2 つまで（全角の英字も数える）・メールアドレスは空か正しい形（254 字まで）・種類が「セキュリティの弱点」ならメールアドレスがある | 400。欄ごとに「どこをどう直すか」を全部出し、書いた中身つきのフォームを返す。誤りのある欄には `aria-invalid` |
| 同じ接続元から、60 秒に 1 通・1 時間に 5 通・24 時間に 3 通まで（送ろうとした回数で数える。1 つの接続元だけで、1 日の上限をどちらの枠も使い切れないように） | 429（`Retry-After` は、また送れるようになるまでの秒数） |
| 同じ本文（空白・英字の大きさの違いは同じとみなす）を、24 時間のうちに送っていない（ほかの接続元からでも） | 409 |
| 24 時間に実際に送った数が、ふつうは 50 通・「セキュリティの弱点」は別の枠で 20 通まで | 429（`Retry-After` は、いちばん古い分が 24 時間の外に出るまでの秒数）。上限に達したら、運営者に 24 時間に 1 通だけ知らせる（中身は入れない） |
| 迷惑防止の記録を読み書きできる | 503。受け付けない（止まる側に倒す） |
| メールを送れた | 503。1 日の上限にも、同じ本文にも数えない |

- **1 日の上限は、実際にメールを送れた分だけを数える。** ボット（見えない欄・印がない・早すぎる）、入力の誤り（URL が多すぎるなど）、同じ本文、送れなかった送信は数えない。たくさんの接続元を持つ人が、ボットの送信でフォーム全体を止めにくくするため。「セキュリティの弱点」は別の枠なので、ふつうの枠が埋まっても届く。
- 記録は、ロックしたまま「確かめる → 送る → 書き足す」をする（ほかの送信と重なって、上限を超えないように）。記録は種類ごとに 1000 件までに縮める（古いものから捨てる）。壊れた記録は読み飛ばす。
- 本文から、制御の字（U+0000〜001F の改行・タブ以外、U+007F〜009F）、見えない字・字の向きを変える字（U+061C・U+200B〜200F・U+2028〜202E・U+2060〜2069・U+FEFF）を除く。改行は `\n` にそろえる。
- **運営者へのメールの本文は、前後を区切りの行で挟み、区切りに毎回でたらめの印（8 字）を入れる。** 本文の中の行が、区切りや決まった欄（返事の宛先など）に見せかけられないようにするため。
- **メールのヘッダーに入力を入れない。** 宛先・送信元は設定の値（決まった形だけを通す）、件名は決まった字と種類の名前（4 つの決まった名前）だけ。利用者のメールアドレスと本文は、メールの本文にだけ入れる（`Reply-To` にも入れない。返事は、本文のアドレスを写して送る）。
- **入力をページに戻すときは、必ずエスケープする**（`htmlspecialchars`。本文・メールアドレス・誤りの一言）。種類は決まった 4 つの値のときだけ選んだ形に戻す。
- **エラーのときに中身を出さない。** `display_errors` を切り、全体を `try`/`catch (Throwable)` で囲み、設定のファイルが壊れていても「いまは受け付けられません」のページだけを返す（`tests/contact-php.test.ts` で確かめる）。設定・記録の場所に入力は使わない。
- 封筒の送信元（`-f`）も、設定の送信元にする。
- 接続元と本文は、`secret` を鍵にした HMAC-SHA256 の前の 32 字にして残す。**鍵がなければ元に戻せない形**で、鍵が漏れると IPv4 の接続元は総当たりで戻せる（そのときは `secret` を作り直す）。IPv6 は前の 64 ビットでまとめ、IPv4 が IPv6 の形（`::ffff:…`）で来たときは IPv4 として扱う。記録は 24 時間で消す（書き込むたびに古いものを除く）。
- 開いた時刻の印は、`secret` を鍵にした署名つき。同じ印は 2 時間まで何度でも使えるが、続けての送信は上の決まりで止まる。
- 種類の値と名前、字数・URL の上限、見えない欄の名前は、`src/site/pages.ts` と同じ（`tests/contact-php.test.ts` で照らす）。画面にも同じ決まりを出す（`required`・`minlength`・`maxlength`・`type="email"` と、欄の下の説明）。
- 大きな送信は、PHP が読み込んでから断っている（PHP の `post_max_size` の既定は 8MB）。`.htaccess` の `LimitRequestBody` で先に断る形は、配信先が `.htaccess` でそれを許していないとサイト全体が 500 になるおそれがあるため（`Options` を外したのと同じ理由）、まだ入れていない。本番で確かめてから入れるかを決める。

## 本人がすること（初めの 1 回）

1. **送信元のメールアドレスを作る**：Xserver のサーバーパネルの「メールアカウント設定」で、`omamoripdf.com` のアドレスを 1 つ作る（例：お問い合わせ専用）。届かなかったときの知らせ（バウンス）が、ここに戻る。
2. **届きやすくする設定**（届け先が Gmail などのとき、送信元のドメインの認証がないと、迷惑メールに入るか、受け取りを断られることがある）：
   - SPF：サーバーパネルの「DNSレコード設定」で、`omamoripdf.com` の TXT に `v=spf1 …` があり、Xserver のサーバーが含まれているかを確かめる【Xserver の DNS を使っているときは、初めから入っていることが多い（推測）。DNS をほかで管理しているときは、Xserver のマニュアルの値を足す】。
   - DKIM：サーバーパネルの「DKIM設定」で、`omamoripdf.com` を有効にする【Xserver のマニュアルで手順を確かめる】。
   - DMARC（任意）：TXT `_dmarc.omamoripdf.com` に `v=DMARC1; p=none;` から始める。
3. **設定のファイルを作る**：`server/contact-config.sample.php` を手元で写して `contact-config.php` にし、【 】を書きかえる。`secret` は 32 字以上のでたらめな字（作り方はひな形の中）。**このファイルはコミットしない。**
4. **置く**：サーバーパネルの「ファイル管理」か、メインの FTP アカウントで、`omamoripdf.com/` のフォルダ（`public_html` と同じ所。`public_html` の中ではない）に `contact-config.php` を上げる。権限は `600`（持ち主だけが読める）にする。
   - 配信用の FTP アカウントは `public_html` の中だけに入れるので、配信（`mirror --delete`）でこのファイルが消えたり上書きされたりすることはない。
   - `public_html` の中に置くと、次の配信で消える。また、外から開かれても PHP として動くだけで中身は出ないが、置かないこと。
5. **確かめる**：配信のあと、公式のサイトのお問い合わせのページから、種類「その他」で 1 通送り、届くこと・迷惑メールに入らないこと・本文が読めること（字化けしないこと）を確かめる。続けてもう 1 通送り、「続けて送ることはできません」が出ることを確かめる。

PHP が `public_html` の外のファイルを読めない設定（`open_basedir`）になっていると、送ると「いまは受け付けられません」になる【Xserver で外に置けるかを、5. で確かめる。読めないときは、作りを考え直すので知らせてほしい】。

## 届いたメールの扱い（プライバシーのページの約束）

- 返事と、不具合・弱点を直すことにだけ使う。公開しない。ほかの人に渡さない。
- 対応が済んだら消す。長くても、届いてから 90 日で消す。
- 返事を書くときは、本文にある利用者のアドレスを宛先に写す。返事の中に、相手が書いた中身を引用しすぎない。

## 手元での確かめ

- `npm test` の `tests/contact-php.test.ts` が、ビルドで作った `contact-send.php` を手元の PHP で動かし、上の表の決まりを確かめる（メールは送らず、設定の `send` で受け取る）。PHP がない環境では、そのテストを省いたと表示する（GitHub Actions の Ubuntu には PHP がある）。PHP は、環境変数 `PHP_BIN` で場所を渡せる。
- Apache の `.htaccess`（`<FilesMatch>` でヘッダーを上書きする）は手元では動かしていない。配信のあと `check:live` が、お問い合わせのページと `contact-send.php` の CSP を確かめる。
