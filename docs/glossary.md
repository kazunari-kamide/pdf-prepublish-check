# 用語集

画面・コード・`docs/` の記録では、この表の言葉を使う。「使わない言い方」の欄の言葉は使わない。新しい用語が必要になったら、使う前にこの表に追加する。

## 1. 漏洩パターン（検出の対象）

番号は検出ルール・正解データ・`docs/evolution.md` で共通に使う。

| 番号 | 用語 | コード上の名前 | 意味 | 漏洩の例 | 使わない言い方 |
|---|---|---|---|---|---|
| P1 | 文書情報 | `docinfo` | PDF の Info 辞書にある作成者・作成ソフト・タイトルなど | Author に職員の個人名、Company に委託先の社名 | 「プロパティ」とだけ書く（P1 と P2 の区別がつかない） |
| P2 | XMP メタデータ | `xmp` | PDF に埋め込まれた XML 形式のメタデータ。編集履歴や元ファイルの情報を含むことがある | `xmpMM:History` に編集の履歴、`dc:creator` に作成者 | — |
| P3 | 他組織名の混入 | `foreign_org` | タイトルやメタデータに、その文書を出した団体以外の自治体名・組織名が残っている | 他の自治体の様式を流用した痕跡 | 「他県名」（市町村や企業の場合もある） |
| P4 | ファイルパス・内部ホスト名 | `internal_path` | 作成した PC や庁内サーバーの場所を示す文字列 | `C:\Users\yamada\…`、`\\fileserver\…`、`file://` | — |
| P5 | 旧版の残存 | `incremental_update` | 増分更新で保存されたため、修正前の版を取り出せる状態 | 差し替え前の金額や氏名が復元できる | 「履歴」（P2 の編集履歴と紛らわしい） |
| P6 | 見せかけの黒塗り | `fake_redaction` | 黒い四角を上に重ねただけで、下の文字がテキストとして残っている状態 | 黒塗りしたつもりの氏名をコピーできる | 「黒塗りミス」「黒塗りの不備」 |
| P7 | 隠れたテキスト | `hidden_text` | 白い文字、ページの表示範囲の外、非表示レイヤーなど、見えないが検索・コピーできる文字 | 白文字で残った下書きの文章 | — |
| P8 | 注釈・コメント | `annotation` | PDF の注釈。作成者名（`/T`）と内容（`/Contents`）を持つ | 校閲コメントとレビューした人の名前 | — |
| P9 | 添付ファイル | `attachment` | PDF に埋め込まれた別のファイル | 元の Excel や Word がそのまま入っている | — |
| P10 | 画像の位置情報など | `image_exif` | 埋め込まれた JPEG の EXIF 情報（GPS・機種・撮影日時） | 写真の撮影場所 | 「GPS」とだけ書く（機種や日時も含む） |
| P11 | フォームの入力値 | `form_value` | PDF のフォーム欄（AcroForm）に入ったままの値 | 記入例のつもりで入れた実在の値 | — |
| P12 | スクリプト・外部動作 | `active_content` | JavaScript、外部プログラムの起動、URL を開く動作 | 漏洩ではないが、安全上の注意として示す | 「ウイルス」（断定になる） |
| P13【仮】 | 個人情報らしい字 | `pii` | 見える文字の中の、氏名・住所・電話番号・マイナンバー・口座番号・生年月日・メールアドレス・カード番号らしい字。**黒塗りの候補**として示すだけで、「整える」では消さない（黒塗りにするかは利用者が決める）。番号は【仮】（2026-11-04） | 申請書の写しに残った申請者の氏名と携帯電話の番号 | 「個人情報が漏れています」（断定になる。「らしい字」「候補」と書く） |

- **黒塗りの候補**：P13 で見つけた所。公開の前に黒塗り（墨消し）が要るかを、利用者が確かめる所。整えたあとの読み直しの「残っている所」には数えない。
- **確からしさ**：P13 の候補の強さ。「高」＝前後の語（「氏名」「住所」など）や表の見出しが型を指している、「確認」＝形は合うが手がかりが弱い。深刻度（高・中・低）とは別のもの。

## 2. PDF の仕組み

| 用語 | 意味 |
|---|---|
| Info 辞書 | PDF の末尾の trailer から参照される、文書情報（P1）の入れ物 |
| XMP | Adobe が定めたメタデータの形式。PDF の中に XML として埋め込まれる（P2） |
| 増分更新 | PDF を書き換えるとき、元のデータを残したまま変更分を末尾に追記する保存方式。`%%EOF` や xref が複数あるのが目印（P5） |
| xref（相互参照表） | PDF の中の各オブジェクトの位置を示す表 |
| オブジェクト | PDF を構成する部品（ページ、フォント、画像など）。番号で参照される |
| コンテンツストリーム | ページに何をどこに描くかの命令の列。文字や黒い四角もここに書かれる |
| 表示範囲（MediaBox・CropBox） | ページの大きさと、実際に見える範囲。範囲の外に置いた文字は見えないが残る（P7） |
| 非表示レイヤー（OCG） | オン・オフを切り替えられる層。オフにした層の中身もファイルには残る（P7） |
| 注釈 | ページの上に重ねる付箋・コメント・ハイライトなど（P8） |
| 注釈の作成者欄（`/T`） | 注釈を付けた人の名前が入る欄。Acrobat などでは、付けた人のログイン名が自動で入る（P8） |
| 画像の層 | P6 のうち、スキャン画像などの画像の上に覆いを重ねただけで、覆いの下の画像の画素がそのまま残っている型（`layer: "image"`）。字の層（`layer: "text"`）と分けて数える |
| 見える範囲 | ページの中で、実際に見える所。ページの箱（CropBox と MediaBox の重なり）と、切り抜きの外枠の箱の重なり。P6 は、この外の覆いを数えない（1.6.0 から） |
| 形の詰まり具合 | 塗りの形の面積を、その形を外から囲む凸の形（凸包）の面積で割った値（0〜1）。四角・楕円は 1 に近く、アウトライン化した字は小さい。P6 は、これが小さい塗りを覆いとして数えない（1.6.0 から） |
| 部品の XMP | 文書全体の XMP とは別に、画像・部品（フォーム XObject）などに1つずつ付いた XMP。作成者・元のファイルのパス・GPS が残ることがある（P2・P4・P10） |
| 編集用データ | Illustrator で「編集機能を保持」のまま書き出したときに、ページに入る元のデータ（`/PieceInfo`）。作ったパソコンの利用者名や、使ったファイルのパスが残る（P2・P4） |
| 横につぶれた字 | 横の伸縮を 0% や 1% にして、幅がほぼ 0 になった字。見えないが取り出せる（P7。`squashed`） |
| 画像と同じ色の字 | 画像の上に、その場所の画像とほぼ同じ色で置いた字。読めないが取り出せる（P7。`same_color_image`） |
| 見えない文字コード | 幅 0 の字・向きの制御の字・タグ文字など、画面には出ないが、コピーや検索で取り出される文字コード（P7。`hidden_codepoint`） |
| 字の対応表（ToUnicode） | 字の形と、コピーで取り出される字を結ぶ表。書き換えると、見た目と違う字が取り出される（P7。`remapped`） |
| 違う字の重ね描き | 同じ所に違う字を重ねて描き、片方を読めなくしたもの（P7。`overdrawn`）。太字のための同じ字の2度描きは含まない |
| 文字認識の層 | スキャン画像の上に置いた、検索やコピーのための見えない字。危険の発見には数えず、お知らせとして出す |
| 消せる残り | どこからも使われていないフォントなど、字の中身を持たない部品の残り。「整える」で消せる。前の版の残り（P5）の項目にはせず、お知らせとして1行で出し、「整える」へ案内する（`cleanupOnly`） |
| ハイブリッド xref | 古い形の xref の表に、xref ストリームを混ぜた保存の形。Word などが使う。前の版の残りではない |
| 濃くない覆い | 白・灰・薄い色の不透明な塗り、型抜きのない画像、白い四角の注釈など、黒くない覆い。下の字は消えていないので、黒い覆いと同じく見せかけの黒塗り（P6）として出す（P6 1.11.0 から） |
| 描かれない部品 | ページの部品（Form XObject）として登録されているのに、どこからも描かれない部品。画面には出ないが、中の字を取り出せる（P5 1.3.0 から） |
| 見えない所の画像 | ページの外に置いた画像や、切り抜きで大部分を隠した画像。見た目には出ないが、取り出すと中身が見える（P7 1.2.0 から） |
| AcroForm | PDF のフォーム機能（P11） |
| 暗号化 | パスワードで開けないようにした PDF。提出条件で「パスワードなし」と指定されることが多い |
| ブラウザ内で完結 | PDF の読み込みから処理・保存まで、利用者のブラウザの中だけで行うこと。このプロジェクトの基本の約束 |

## 3. 処理と提出

| 用語 | コード上の名前 | 意味 | 使わない言い方 |
|---|---|---|---|
| 診断 | `scan` | PDF を調べて、漏洩パターンの候補を見つけること | 「スキャン」（紙のスキャンと紛らわしい） |
| 除去 | `sanitize` | 見つけた情報を PDF から実際に消す・書き換えること。画面では「整える」と書く（2026-11-05 本人が決定。あとでプロパティを直す機能も入るので、「消す」に絞らない語にした）。整えた中身の内訳は「見えない情報を消す」「プロパティを直す」などと書く | 「片付ける」（何をどうするのか伝わらない。2026-11-05 まで使っていた）、「クリーニング」「削除」（「削除」はファイルを消す意味に取られる） |
| 墨消し | `redact` | 黒塗りの下の情報まで実際に消す、正しい黒塗り。見せかけの黒塗り（P6）の反対 | — |
| 再検査 | `verify` | 除去した後の PDF を検証器で読み直し、本当に消えたかを確かめること | 「確認」とだけ書く |
| 提出条件 | `submit_profile` | 電子入札・電子申請の「○MB 以下」「パスワードなし」「PDF/A」などの条件 | — |
| 圧縮 | `compress` | 画像の再圧縮などで、ファイルを小さくすること | — |
| 深刻度 | `severity` | 見つけた項目の危なさの段階。高・中・低の3段（2026-11-02 決定）。安全上の注意（P12 など）は「低」にする | 「危険度」と混ぜて使う |

## 4. このプロジェクトの仕組み

| 用語 | フォルダ・名前 | 意味 |
|---|---|---|
| 検出ルール | `rules/` | 漏洩パターンの候補を見つけるルール。Claude Code が書き、直す |
| 検証器 | `verifier/` | 除去後の PDF をゼロから読み直して採点するプログラム。検出ルールのコードを使わない。Claude は変更しない |
| 合格基準（基準表） | `rubric/` | 機械で採点できる合格の条件（検出率・誤検知率・除去後の残存ゼロなど）。人が決め、Claude は変更しない |
| テスト用 PDF | `fixtures/` | 正解が分かっている合成 PDF。実在の自治体 PDF や個人名は使わない |
| 正解データ | `fixtures/<名前>.expected.json` | テスト用 PDF ごとに、どの漏洩パターンがどこにあるかを書いた正解 |
| 改善ループ（4段） | — | 見つける（公開 PDF を読み、今のルールで捕まらない漏れ方を探す）→ ルールにする（検出ルールと正解データを書く）→ 確かめる（検証器で採点する）→ 配る（人がマージしたものだけを検査器に入れる）、の繰り返し |
| 採点用データ | — | 採点にだけ使う実データ。非公開でリポジトリの外にあり、ループには読ませない。件数だけを記録する |
| 一致率 | — | Claude の判断と、人が確かめたラベルが一致した割合。「人が確かめた N 件中 X 件で一致」と書く |
| 改善の記録 | `docs/evolution.md` | 改善ループの1回ごとの記録（ルール、検出率と誤検知率の前後、理由、捨てた案） |
| 検出率 | `recall` | 正解データにある漏洩のうち、見つけられた割合 |
| 誤検知率 | `false_positive_rate` | 漏洩ではないものを漏洩と判定した割合。分母は「漏洩でない項目の数」（2026-11-02 決定）。そのため正解データには、紛らわしいが漏洩でない項目も明示して入れる |
| 見逃し | `false_negative` | 正解データにある漏洩を見つけられなかったもの |
| 誤検知 | `false_positive` | 漏洩ではないものを漏洩と判定したもの |
| 検査器 | `src/` | 診断・除去・再検査・圧縮を、Claude なしでブラウザ内だけで行うアプリ。無料・ログイン不要・送信 0B |
| 入口 | — | 検査器の使い方。① ブラウザの検査器、② Claude Code のスキル／MCP（利用者自身の Claude から使う。こちらのサービスは何も受け取らない） |
| ループ | — | 決まった時刻に4段を回す仕組み。運営の Claude API はここでだけ使い、利用者の PDF には触れない |
| 事前調査 | — | 11/2 より前に行った、公開 PDF の実態調査。統計だけを公開する |
| コマンドの道具 | `cli/` | フォルダごとまとめて調べる道具（`npx omamori-pdf check`）。画面と同じルールの一覧で調べ、型・数・場所を人が読む形・JSON・SARIF で出す。通信しない（docs/cli.md） |
| 確かめのスキル | `.claude/skills/omamori-check/` | Claude Code から「提出前にこの PDF を確かめて」と頼むと、コマンドの道具を手元で動かし、段階・型・数・場所だけを伝える入口（入口の②のスキル）。ファイルそのものは開かない（docs/cli.md） |
| 段階 | `stage` | コマンドの道具の結果のまとめ。見つからない（0）・確認してほしい所だけ（1）・高い危険（2）・調べられなかった所がある（3）。終了コードの数と同じ |
| 調べられなかった所 | `unchecked` | PDF でない・大きすぎる・ルールが止まった・省いたページ・読めなかった画像など、調べていない所。「問題なし」には数えない |
| 2つの PDF の比べ | `compare/` | 元の PDF と公開する PDF（整える前と後）を比べ、消したはずの字が残っていないか（数と場所）、文書情報・XMP の違い、版・添付・注釈の数の違いを出す |
| 消したはずの字 | — | 公開する PDF の濃い覆いの下に、覆いより先に描いた字として残っている、元の PDF の字。覆いのあとに描き直した字（上に見えている字）は数えない |
| PDF 以外の形式 | `formats/` | 写真（JPEG・PNG・WebP。HEIC は有ると知らせるだけ）と今の Office（docx・xlsx・pptx）。いまは知らせるまで（消すのは後） |

### PDF 以外の形式の型（`formats/`）

PDF の P1〜P12 とは別に、`image.*`・`office.*` の名前で呼ぶ。深刻度はどれも【仮】。

| 型 | 意味 | 深刻度【仮】 |
|---|---|---|
| `image.gps` | 写真の EXIF・XMP に、撮った場所（緯度・経度）が入っている | 高（位置のない GPS の欄だけなら低） |
| `image.thumbnail` | EXIF の中の縮小画像（見本）。本体と縦横の比が違えば、切り取る前の写真かもしれない | 中（比が違えば高） |
| `image.exif_person` | 撮った人・著作権者・カメラの持ち主・カメラの番号などの欄 | 中 |
| `image.exif_text` | 写真の説明・コメント・タイトルなどの欄 | 中 |
| `image.exif_device` | カメラの機種・撮った日時・ソフトなどの欄 | 低 |
| `image.xmp` | 写真の XMP（作成の記録） | 人をたどれる項目か編集の履歴があれば中、なければ低 |
| `image.iptc` | 写真の説明の記録（IPTC） | 中 |
| `image.png_text` | PNG の文字の欄 | 中 |
| `image.heic_meta` | HEIC・HEIF に EXIF・XMP の項目が有る（中身は調べていない） | 中 |
| `office.person` | プロパティの作成者・最後に保存した人 | 中 |
| `office.organization` | プロパティの会社名・管理者 | 中 |
| `office.property` | プロパティのタイトル・件名・キーワードなど | 低 |
| `office.custom_property` | 独自のプロパティ | 中 |
| `office.template_path` | ひな形の場所（パス） | 中 |
| `office.link_base` | リンクの基準の場所 | 中 |
| `office.external_link` | 外のファイルへのつながり（手元のファイルへのリンク・外のブック・リンクした画像など。ウェブのリンクは数えない） | 中 |
| `office.embedded` | 中に埋め込まれたファイル | 中 |
| `office.comments` | コメント（書いた人の数も） | 中 |
| `office.tracked_changes` | 変更履歴（Word）・共有ブックの変更履歴（Excel） | 高（書式の変更だけなら中） |
| `office.hidden_text` | 隠し文字（Word） | 高 |
| `office.fake_redaction` | 字と同じ色の蛍光ペン・網掛け・セルの塗り・図形の塗り（見せかけの黒塗り） | 高 |
| `office.same_color_text` | 背景と同じ色（白）の字 | 高 |
| `office.hidden_value` | 値を見せない書式（`;;;`）のセル（Excel） | 高 |
| `office.hidden_sheet` | 隠したシート（Excel） | 中 |
| `office.hidden_rows` | 隠した行・列（Excel） | 中 |
| `office.hidden_slide` | 表示しないスライド（PowerPoint） | 中 |
| `office.notes` | 発表者のメモ（PowerPoint） | 中 |
| `office.cover_shape` | 字のある図形の上に重ねた濃い図形（PowerPoint は高）・本文の上の濃い図形（Word は中） | 高・中 |
| `office.off_slide_text` | スライドの外に置いた字（PowerPoint） | 高 |

## 5. 自治体・入札

| 用語 | 意味 |
|---|---|
| プロポーザル | 価格だけでなく企画の提案内容で委託先を選ぶ、自治体の契約方式 |
| 仕様書 | 委託する業務の内容や条件を示した文書。PDF で公開されることが多い |
| 様式 | 応募のときに提出する書類のひな形。自治体どうしで流用されることがあり、P3 の原因になる |
| 電子入札・電子申請 | 書類をオンラインで提出する仕組み。ファイルの大きさや形式に条件がある |
| 質問書 | プロポーザルで、仕様の内容を自治体に問い合わせる書類。回答が全参加者に公開されることが多い。資料の不備の指摘には使わない |
| 責任ある開示 | 見つけた問題を、公表する前に当事者に知らせること |

## 6. 書き方の決まり

- 画面の文章は、PDF に詳しくない自治体職員が読んでわかる言葉にする。§2 の用語（xref、OCG など）は画面に出さず、「何が起きるか」で説明する。
  - 例: 「増分更新が検出されました」ではなく「修正する前の版が、ファイルの中に残っています」
- 断定しない。作成者名などは意図して残している場合もあるので、「〜が残っています。意図したものでなければ消してください」と書く。
- 実在する個人名・自治体名は、例文・テスト用 PDF・記録のどこにも書かない。例には「山田太郎」「○○市」などの架空の名前を使う。
