# 計画（PRD）：最初の版

- 状態：**案（承認待ち）**。承認されるまで、コードは書かない。
- 対象の期間：2026-11-02 〜 2026-11-08 20:00（提出の締切）
- 数字は測ったものだけを書く。まだ測っていない数字は【 】のままにする。
- 漏洩パターンの番号と名前は、用語集（`docs/glossary.md` §1）に合わせる。

## 1. ユーザーストーリー（1つだけ）

> 書類を作った本人として、PDF を公開・提出する前に、ブラウザでこの検査器に入れたい。黒い四角の下に残った文字や、作成者の名前・前の版・添付ファイルのような見えない情報が残っていないか確かめたい。残っていればその場で片付け、消えたことを確かめてから出したい。PDF はどこにも送らないでほしい。

検査器でできることは、2つの柱に分ける。

| 柱 | 中身 | 4段のループ |
|---|---|---|
| A. 見せかけの黒塗りの検出 | P6（見せかけの黒塗り）のうち、**文字の層の型だけ**。黒い四角の下に、テキストとして選べる・コピーできる字が残っているもの | **回す。** 最初の検出ルールはこれだけ |
| B. 隠れた情報の確認と片付け | P1（文書情報）、P2（XMP メタデータ）、P4（ファイルパス・内部ホスト名）、P5（旧版の残存）、P8（注釈・コメント）、P9（添付ファイル）、P11（フォームの入力値）、P12（スクリプト・外部動作） | まだ回さない。ファイルの構造を見れば決まるので、まず決まった手順で作る。検証器での再検査は A と同じく行う |

今回、入れない型は次のとおり。

- P6（見せかけの黒塗り）のうち、スキャン画像の上に黒い四角を重ねた型（画像の層。下の画像が残っている）
- P6（見せかけの黒塗り）のうち、黒い注釈（四角の注釈・未適用の墨消し注釈）を重ねた型
- P3（他組織名の混入）、P7（隠れたテキスト）、P10（画像の位置情報など）

## 2. 4段との対応（柱 A）

```
見つける ─→ ルールにする ─→ 確かめる ─→ 配る
（公開PDF）   （rules/ と     （検証器で     （PR → 人がマージ
              正解データの案）  採点）         → 検査器に入る）
```

### 2-1. 見つける

- **入力**：事前に集めた公開 PDF の、次の束。置き場所は環境変数で渡す（パスはコミットしない）。
  - **1回に読む数は、まず 50件で始める。** 1回にかかる時間と費用を測ってから決め直す（2026-11-02 決定）。
- **すること**：今の検出ルールを束に当てる。そのうえで、ルールが拾わなかったが「黒い四角の下に字がありそう」なページを、Claude が候補として挙げる。
- **反証**：別のエージェントが、候補ごとに「本当に漏れか（デザインの黒帯、表の見出しの塗り、白い字が上に載っているだけ、などではないか）」を確かめる。
- **出力**：決めた JSON スキーマで受け取る（CLAUDE.md §5）。スキーマに合わない出力は捨てる。
  - 項目は、候補の型、なぜ怪しいと見たか、反証の結果、除いた理由。
  - 中身（氏名など）と、団体をたどれる語は入れない。
- **記録**：件数・1回にかかった時間・費用だけを `docs/evolution.md` に書く。

### 2-2. ルールにする

- **検出ルール**：`rules/p6-text/`。判定はルールが行い、Claude だけに任せない。
- **正解データの案**：漏れ方を、架空の内容の**合成 PDF**で再現する案。実在の PDF・名前は使わない。
  - 漏れている例を入れる。
  - 「紛らわしいが漏れでない例」も必ず入れる。誤検知率の分母になるため（用語集）。
- **置き場所**：案は `proposals/` に置く（§7 の1）。

### 2-3. 確かめる（`npm run eval`）

- 検証器（`verifier/`）が、`fixtures/` の正解データと照らし合わせて採点する。
- 検証器は、検出ルールのコードを import しない。片付けた側の報告も信じず、出来上がった PDF をゼロから読み直す。
- **合格基準**（`rubric/`。2026-11-02 決定）
  - 検出率 95% 以上
  - 誤検知率 5% 以下
  - 片付けたあとに残る情報 0 件
- **数え方**
  - 1件は「黒い四角1つと、その下に残った字のまとまり1つ」。
  - 検出率の分母は、正解データにある漏れの件数。
  - 誤検知率の分母は、正解データにある「漏れでない黒い四角」の件数。
- **採点用データ（非公開）**：ループには読ませない。採点は人が手元で回し、件数だけを記録する。

### 2-4. 配る

- 基準を満たしたら、`claude/` で始まるブランチから PR を出して止まる。
- 説明文に書くもの：採点表（何件中何件、誤検知の件数、前回との差）、判断の中身、捨てた案。
- マージは人が決める。マージされたルールだけが、次のビルドで検査器に入る。

## 3. 検出ルール P6（見せかけの黒塗り）の文字の層の考え方

PDF のページは、描く命令を上から順に並べたもの（コンテンツストリーム）である。**あとに描いたものが上に重なる。**

1. 命令を順に読みながら、次の2つを拾う。図形を全部組み立てることはしない（CLAUDE.md §5 の重いページ対策）。
   - **濃い色の塗り**：位置・大きさ・何番目に描いたか
   - **文字**：1字ごとの位置・大きさ・何番目に描いたか
2. **文字のあとに、その文字を覆う濃い塗りがあれば**、候補にする。
   - 文字が塗りの**あと**に描かれているなら、上に見えているので漏れではない（黒地に白い字の見出しなど）。
3. 判定に使う値は、合成 PDF で測ってから決める。推測では決めない。
   - 「濃い」とみなす明るさ：【 】
   - 覆われているとみなす重なりの割合：【 】
4. 次の場合も追いかける。
   - 回転・拡大されたページ
   - フォームの中身（Form XObject）の入れ子
   - 1つの文字列の一部だけが覆われている場合
5. 結果は、ページ番号・場所・残っている字数・深刻度（高）を返す。
   - **画面に字の中身を出すかどうかは、利用者が選ぶ。** 既定は字数だけにする。
6. **片付け方**（2026-11-02 決定）
   - 覆われた字だけを、命令の中から消す。見えている所は変わらず、ページのほかの字も選べるまま残る。
   - 読めない作りの PDF では片付けを止め、「このページは自動で片付けられません」と出す。
   - 捨てた案：そのページ全体を画像にする。確実に消えるが、ページの字がすべて選べなくなり、読み上げにも使えなくなる。

## 4. 隠れた情報の確認と片付け（柱 B）

ファイルの構造（Info 辞書・XMP・xref・添付・注釈・フォーム・動作）を読めば有無が決まる。そのため、Claude の判断は使わず、決まった手順で確かめる。

| 型 | 見せるもの | 片付け方 |
|---|---|---|
| P1（文書情報） | 作成者・作成ソフト・タイトル・会社名などの欄と値 | 欄ごとに「消す」か「書き換える」（例：課の名前）を選ぶ |
| P2（XMP メタデータ） | 作成者・編集の履歴・元のファイルの情報があるか | XMP をまるごと消す。P1（文書情報）で書き換えた値だけを入れ直す |
| P4（ファイルパス・内部ホスト名） | P1（文書情報）・P2（XMP メタデータ）の値の中にある、PC のユーザーフォルダのパス・`\\サーバー\…`・`file://` など | P1（文書情報）・P2（XMP メタデータ）の片付けで一緒に消す |
| P5（旧版の残存） | 修正する前の版がファイルの中に残っているか（保存が何回追記されたか） | ファイルを1つの版として書き直し、前の版を残さない |
| P8（注釈・コメント） | 注釈の数・種類・書いた人の名前の有無 | 注釈を消す（種類ごとに選べる） |
| P9（添付ファイル） | 添付の数・ファイル名・大きさ | 添付を消す |
| P11（フォームの入力値） | 値が入ったままの欄の数 | 値を空にする。フォームそのものを消すかは選べる |
| P12（スクリプト・外部動作） | JavaScript・外部プログラムの起動・URL を開く動作があるか | 動作を消す |

- 結果は確認の一覧で見せる。片付けたあと、検証器が読み直して全部緑になる。
- 作成者名などは意図して残している場合もあるので、断定しない（用語集 §6）。「〜が残っています。意図したものでなければ消してください」と書く。
- 正解データ（合成 PDF）と検証器の項目も、柱 A と同じく `proposals/` を通して人が入れる。

## 5. 検査器（画面）でできること

1. PDF を選ぶか、画面に落とす。ファイルはブラウザの中だけで読む。
2. **重さを先に測る**：ページごとに、内容の大きさと命令の数を数える。
   - 上限を超えたページは検査せず、「このページは図形が多すぎるため、検査を省きました」とページ番号つきで出す。検査結果の数にも含めない。
   - 上限：【 】（重いページの合成 PDF で測ってから決める）
3. **検査は Web Worker で動かす。** 時間かメモリの上限を超えたら Worker だけを止め、画面は止めない。
4. **結果の一覧**
   - 柱 A と柱 B の結果を1つの一覧で見せる。
   - 見つけた所を、ページ・場所・「なぜ危ないか」1文で示す。
   - 危ない所は、色だけでなく、形と文字でも示す。
5. **片付ける**：選んだ項目を、ファイルから実際に消す。
6. **再検査**
   - 片付けた PDF を検証器と同じ考え方で読み直し、赤い枠が緑に変わるのを見せる。
   - 「黒い四角の下を選んでも何も取れない」ことも見せる。
   - 「残っていません」は、調べた項目についての結果であることを、文言で示す。
7. **容量を縮める**（入口として軽く入れる）
   - 埋め込まれた画像を縮め直して、ファイルを小さくする。
   - 前と後の大きさを見せる。
   - 縮めたあとも、柱 A と柱 B の再検査を通す。
8. 片付けた PDF を保存する。保存は利用者のブラウザでのダウンロードだけ。

画面の文章は、PDF に詳しくない職員が読んでわかる言葉にする（用語集 §6）。見た目は `design/` の決まりに従う。2色と書体は、画面を作る前に決める。

## 6. ほかの入口と、通信を見せる仕組み

- **Claude Code のスキル／MCP**（`skill/`）
  - 検査器と同じ検査を、利用者の手元で動かす。
  - Claude に返すのは、種類と位置だけ。見つけた個人情報は伏せる。
  - 外への送信、コマンドの実行、指定したファイル以外の読み書きをさせない（CLAUDE.md §11-5）。
  - 使う前に、利用者の Claude のデータの設定を確かめるよう促す文言を出す。文言は、作る時点の Anthropic の一次情報で確かめてから書く。
- **通信を見せる拡張機能**（`extension/`）
  - 検査器のページを開いている間に出た通信の数と大きさを、ブラウザの拡張機能で数えて見せる（動画で「送信 0B」を見せるため）。
  - 拡張機能そのものも、外に送らない。

## 7. 守ること（実装の決まり）

- **通信しない**
  - `fetch`・`XMLHttpRequest`・`WebSocket`・`sendBeacon` を使わない。
  - 外部の CDN・フォント・解析タグを入れない。
  - CSP は CLAUDE.md §11-4 の例から始め、使うライブラリ（Worker、WASM を使うか）に合わせて、動作を確かめてから決める。
- **細工された PDF**
  - 壊れた・巨大・深い入れ子・暗号化された PDF で、止まらずにエラーを出す。
  - サイズ・ページ数・時間に上限を設ける。上限は【 】。
- **PDF.js を使う場合**：`isEvalSupported: false` にする。
- **取り出した字の表示**：画面に出すときは `textContent` で入れ、HTML として解釈させない。
- **ライセンス**
  - ソースの先頭に `SPDX-License-Identifier: AGPL-3.0-only` を入れる。
  - 依存の一覧を `docs/` に作る。

## 8. 依存ライブラリ（2026-11-02 承認。足すときに1つずつライセンスを報告する）

| 名前 | 何に使うか | ライセンス |
|---|---|---|
| Vite | 開発サーバーとビルド | 足すときに確かめて報告する |
| Vitest | テスト | 足すときに確かめて報告する |
| TypeScript | 型のある JavaScript で書く | 足すときに確かめて報告する |
| pdf-lib | 片付けた PDF を書き出す。合成 PDF を作る | 足すときに確かめて報告する |
| pdfjs-dist（PDF.js） | 検証器で、字が取り出せるかを、検出ルールとは別の読み方で確かめる | 足すときに確かめて報告する |

- 検出ルールは、コンテンツストリームを自前で順に読む（重いページで必要なものだけ拾うため）。
- 検証器は、それとは別の読み方（PDF.js での字の取り出し）を使い、同じ間違いを共有しないようにする。
- 捨てた案：検出ルールも PDF.js の字の取り出しで作る。図形の多いページで、取り出しが10分で終わらなかった例がある（CLAUDE.md §5）。
- 拡張機能・スキル／MCP・容量を縮める機能で、上にない依存が要るとわかったら、その時点で理由を書いて承認をもらう。

## 9. 決まったこと（2026-11-02）

1. **採点する側の書き方**
   - Claude は、`rubric/`・`verifier/`・`fixtures/` の案を `proposals/` に書く。
   - 人が中身を見て、`git mv` で移すコミットを自分で作る。
   - 検証器は、検出ルールを見ていない別のセッションで書く。
2. **片付け方**：覆われた字だけを消す（§3 の6）。
3. **依存ライブラリ**：§8 のとおり。足すときに、ライセンスを1つずつ報告する。
4. **一致率で測る判断**：「この黒い四角は黒塗りか、デザインか」。正解は、本人が確かめたラベル。
5. **ループが1回に読む公開 PDF の数**：まず 50件。時間と費用を測ってから決める。

## 11. 予定タスクで書き込みの見張りが効くかの試し（11/5）

1. このセッションの中の予定タスク（`/loop` や1回だけの予定）で、「`rubric/x.md` に1行書いて」と頼む。止まることと、ファイルが無いことを確かめる。
2. 手元の非対話の実行（`claude -p`）で、同じことを頼む。
3. クラウドのルーティンで、同じことを頼む。`claude/guard-test` に push させ、ブランチにファイルが無いことを確かめる。クラウドの環境に `node` があるかも確かめる。

## 12. あえてやらないこと

- P6（見せかけの黒塗り）のうち、スキャン画像＋黒い四角の型（画像の層）と、黒い注釈を重ねた型。OCR。
- P3（他組織名の混入）、P7（隠れたテキスト）、P10（画像の位置情報など）。柱 A の4段が一周回ってから足す。
- 柱 B の型を4段のループで育てること（まず決まった手順で作る）。
- 提出条件の確認（○MB 以下・パスワードなし・PDF/A など）。
- 利用者自身の API キーで Claude を使う入口（期間中は作らない。2026-11-02 決定）。
- 結合・分割・パスワードなど、よくある PDF ツールの機能。
- 「比べるための版」（`baseline/one_prompt/`）。別のセッションで本人が頼む。
