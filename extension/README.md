# お守りPDF 通信を数える（Chrome の拡張機能）

お守りPDF のページで、**PDF を入れたあとに、ページが送ったデータの大きさと要求の数**を数えて、ページの右下と拡張機能のボタン（バッジ）に出します。
「送信 0B」を、検査器の外側から目で確かめるための道具です。

- 表示の例：「PDF を入れたあとに送ったデータ　0 B　要求 0 件」
- 送った要求が 1 件でもあると、表示が紅になり、「!」の印が出ます（色だけで示さないため、印と数でも示します）。

> この拡張機能が数えられるのは、ブラウザが拡張機能に見せる要求だけです。大きさは目安です（下の「数え方」）。
> 「0 B」は「この拡張機能が見た範囲で、送った要求がなかった」という意味で、外へ送れないことの保証ではありません。

## 入れ方

1. Chrome で `chrome://extensions` を開く。
2. 右上の「デベロッパー モード」をオンにする。
3. 「パッケージ化されていない拡張機能を読み込む」を押し、このリポジトリの `extension/` フォルダを選ぶ。
4. ツールバーのパズルの形のボタンから「お守りPDF 通信を数える」を固定すると、バッジが見えるようになります。

すでに開いていたお守りPDF のタブは、入れたあとに 1 回読み込み直してください。

## 使い方

1. お守りPDF（`https://omamoripdf.com/`、または手元の `npm run dev`・`npm run preview`）を開く。右下に「PDF を入れると、数え始めます」と出ます。
   ページを開いた時の読み込み（画面の部品）は、数に入れません。
2. PDF を入れる。その時点から数え始めます。
3. 拡張機能のボタンを押すと、同じ数と、数え始めてからの要求の一覧が出ます。
   - **今から数え直す**：押した時から数え直します。PDF の合図がないページでも、これで数え始められます。
   - **ページの隅に出す**：右下の表示を「隠す」で消したあと、もう一度出します。

ページを開き直すと、数は消えて「待っています」に戻ります。2 つめの PDF を入れても数は消しません（その間の通信を隠さないため）。

## 数え方

- **送った**：次のどれかに当たる要求。
  - ページと別のサイトへの要求
  - POST など、本文のある要求
  - URL に「?」のつく要求（URL に字をのせて送れるため）
  - ping・beacon・websocket など、送るための種類の要求
- **読み込み**：ページと同じサイトへの GET（「?」なし、本文なし）。PDF を入れると、検査器は pdf.js と Worker を自分のサイトから読み込みます。これは「送ったデータ」に数えず、別の行に件数を出します。
- 大きさ：要求の 1 行目（メソッドと URL）＋ヘッダー＋本文のバイト数。ブラウザが足すヘッダー（Cookie など）には、拡張機能から見えないものがあるので、実際より少し少なめに出ることがあります。
  本文の大きさをブラウザが渡さないとき（大きすぎる本文・ファイル）は、「大きさが分からない本文 N 件」と出します。
- CSP（ページの決まり）で止められた要求は、ブラウザの外に出ないので、数に入りません。

## 合図（検査のページの側）

検査のページは、PDF を受け取ると `<html>` の属性 `data-omamori-pdf` に番号を入れます（`src/main.ts` の `handle`）。拡張機能はページの中でこの属性を見ているだけです。
合図のための通信はありません。postMessage ではなく属性にしたのは、拡張機能があとから動き始めても、すでに入った合図を読めるためです。

## 権限

| 権限 | 何のためか |
|---|---|
| `webRequest` | 要求を読み取る（止めない・書き換えない） |
| `storage` | 数をタブごとに `chrome.storage.session` に置く。メモリの中だけで、ブラウザを閉じると消え、ディスクには書きません。拡張機能の本体（service worker）は止まることがあり、変数だけでは数が消えるため |
| ホスト `<all_urls>` | **別のサイトへの要求を見るため。** Chrome は、要求の宛先のサイトの権限がない拡張機能には、その要求を見せません。権限を `omamoripdf.com` と `localhost` だけにすると、ページから別のサイトへ送った要求が数に入らず、「0 B」と出てしまいます（`scripts/check-extension.mjs` で試すと、別のサイトへの POST が数えられませんでした） |

- 数えるのは、**ページの URL が `https://omamoripdf.com/`・`http://localhost`・`http://127.0.0.1` のタブだけ**です。ほかのタブの要求は、届いても中を見ずに捨てます（`count.js` の `isWatchedPage`）。
- ページの右下の表示（`content.js`）も、この 3 つのページでだけ動きます。
- 拡張機能は外へ何も送りません。`fetch` などを使っていないこと、拡張機能のページの CSP が `connect-src 'none'` であることを、`tests/extension.test.ts` で確かめています。記録はファイルに保存しません。

## 確かめ方

```
npm test                       # 数え方の決まり・権限・外へ送る仕組みを使っていないこと（tests/extension.test.ts）
npm run build
npm run check:extension        # 本物の Chrome（headless）に入れて動かす
npm run check:extension -- --shots <フォルダ>   # 右下の表示とポップアップのスクリーンショットも撮る
```

`check:extension` は次を確かめます。

1. ビルドした検査器を開くと「待っています」になり、開いた時の読み込みは数に入らない。
2. 合成 PDF（`fixtures/`）を入れると数え始め、送った要求は 0 件・0 B。
3. 確かめのページ（`test-page/`）で、わざと要求を出すと、送った数が増える（同じサイトへの POST・別のサイトへの POST・sendBeacon・「?」つきの画像で 4 件。「?」なしの GET は「読み込み」に 1 件）。
4. 2 つめの PDF の合図では、数が消えない。

### 手で確かめるとき

確かめのページは、宛先が手元のサーバーだけです（外のサーバーには何も送りません）。

1. このリポジトリで `node extension/test-page/serve.mjs` を動かす（`npm run check:extension` と同じ、手元だけのサーバー）。
2. `http://127.0.0.1:8787/` を開き、「PDF を入れたことにする」を押してから、ほかのボタンを押す。押すたびに右下の数が増えることを見る。
