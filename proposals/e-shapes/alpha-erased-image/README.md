# 採点する側に足す案：画像の一部を透明にして消したが、透明な所の元の画素が残る（P6）

CLAUDE.md §2-3 に従い、`fixtures/` に足す合成 PDF と正解データの案をここに置く。Claude は採点する側を書き換えない。人が中身を見て、移すかを決める。

## 何を足すか

| 合成 PDF | 種類 | 中身 |
|---|---|---|
| `e-alpha-01-name-erased-to-transparent` | 漏れ（image/smask）1 件 | RGB の画像（`/FlateDecode`、240×96 画素）に、やわらかい型抜き（`/SMask`。灰色 8 ビット）を付けた。型抜きは氏名の行の所だけ 0（透明）、ほかは 255。RGB の側の透明な所には、元の字の模様がそのまま残る。ページは白い地で、覆いの図形・注釈は無い |
| `e-alpha-02-uniform-and-feathered` | 漏れでない 2 件 | 同じ画像で、透明にした所の RGB を白に塗ってから透明にしたもの。もう1つは、縁 12 画素をやわらかく透明にした写真のような画像（縁の透明な所にも模様が残るが、字ではない） |

作り方：`node build.mjs [出力先]`。出力先を省くと、このフォルダの `out/` に書く。画像の「字」は、字の形をまねた線の模様で、中身は架空。

- 正解データの `cover` に、新しい値 `smask`（型抜きで透明にした所）を使った。移すなら、検証器の形に足すかを人が決める。
- 写真のような画像（`feathered_photo`）は、漏れでないものとして入れたが、扱いはルールを作る段で決める【仮】。

## なぜ漏れか

画像の編集ソフトの消しゴムで透明にして書き出すと、見た目は白く消えている。けれど型抜きを外して画像を取り出すと、透明な所の元の画素で氏名が読める。

- どの道具が、透明な所の RGB を元のまま残して書き出すかは、確かめていない（推測）。
- ふつうのビューアの画面からは取り出せない。画像を取り出す道具が要る。切り抜きで隠した画像（見ないで作るテスト集の T83）を漏れとして扱う方針と同じ考え方で残した。

## 今の型との違い

- `rules/p6-text` の画像の層（`image-layer.ts`）は、覆いの下の画素を測る。型抜きの値は、覆いの下を測るためだけに使い、画像そのものの透明な所の画素は測らない。
- `rules/p7-hidden` の見えない所の画像は、ページの外・切り抜きの外だけを見る。型抜きのある画像は覆いにもしない。
- `rules/unused-images` は描かれない画像だけを見る。
- `fixtures/p6` の `p6-i01〜i05`・`p6-n02` は、覆いの下の画像か、画素を塗った画像。T82（ページの外）・T83（切り抜き）は、型抜きで隠した形ではない。

## ルールを作る段への注意（反証役の注意から）

- 誤検知が起きやすい。背景を消した写真や縁のぼかしは、透明な所に元の背景が残っていて、一様ではない。字かどうかを見分ける手がかりが無いので、確からしさは「確認」【仮】にとどめる。
- `/Mask`（色の範囲で抜くもの・型抜きのストリーム）の変わり型は、別の候補として分ける。

## 捨てた案

- 透明な所の判定を「透明な画素が 1 つでもあれば出す」にする案。縁のぼかしのある飾りの画像で必ず出てしまうので、対照に写真のような画像を入れ、透明な所の模様（インクと紙の色の両方があるか）で見る前提にした。

## 移し方（人が行う）

```
node proposals/e-shapes/alpha-erased-image/build.mjs fixtures/p6
npm run eval
```

- 移すなら、`fixtures/p6/build.mjs` に同じ型を足すか、この build.mjs を置くかを人が決める。`fixtures/p6/index.md`・`hashes.txt` も直す。
- 検証器（`verifier/`）はこの形をまだ見ない。`cover: "smask"` を足すか、検証器を直す案と合わせて人が決める。
