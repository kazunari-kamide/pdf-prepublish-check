# 採点する側に足す案：見た目（/AP）の無い、黒い楕円・手書きの注釈で字を覆う（P6）

CLAUDE.md §2-3 に従い、`fixtures/` に足す合成 PDF と正解データの案をここに置く。Claude は採点する側を書き換えない。人が中身を見て、移すかを決める。

## 何を足すか

| 合成 PDF | 種類 | 中身 |
|---|---|---|
| `e-annot-01-circle-and-ink-without-ap` | 漏れ（text/annotation）2 件 | 氏名「Jiro Kawamoto」の上に、黒い楕円の注釈（`/Subtype /Circle`、`/IC [0 0 0]`、`/C [0 0 0]`）。電話番号の上に、太い黒い手書きの注釈（`/Subtype /Ink`、`/BS << /W 14 >>`、字の中ほどを 2 往復する点の列）。どちらも `/AP` を持たない。下の字はページの中身に残る |
| `e-annot-02-underline-and-margin-circle` | 漏れでない 2 件 | `/AP` の無い黒い手書きの注釈を、字の下に細い線（`/W 1`）で引いた下線。字の無い余白の、`/AP` の無い黒い楕円の注釈 |

作り方：`node build.mjs [出力先]`。出力先を省くと、このフォルダの `out/` に書く。名前・電話番号は架空。注釈に作成者欄（`/T`）は付けない（P8 と混ざらないように）。

- 正解の字数は、実際に覆った字（字の箱の中の 8×8 の点のうち、半分以上が形の中にある字）で数えた。楕円は字の箱を含むように広げたので、前の「t: 」の一部も隠れ、氏名 12 字に 3 字を足した 15 字になる（計。build.mjs が数えた値）。手書きの線は電話番号の 13 字。

## なぜ漏れか

閲覧ソフトは見た目の無い注釈も、色と線の太さから描く。そのため字は黒く隠れて見えるが、下の字はコピー・検索で取り出せる、見せかけの黒塗りになる（ビューアの描き方は一般的な仕様からの推測で、画面では確かめていない。ブラウザは使っていない）。

## 今の型との違い

- `rules/p6-text/annotations.ts` の `scanAnnotations` は、`/AP` の有る注釈は見た目を読む。`/AP` の無い注釈で覆いにするのは Redact・Highlight・Square・Polygon だけで、Circle・Ink の枝は無い。
- `rules/p8-annot` は `/T`・`/Contents`・`/Subj`・`/RC` だけを見るので、作成者欄の無い注釈では出ない。
- `fixtures/p6` の `p6-t09`（Square）・`p6-t10`（Redact）、見ないで作るテスト集の T28・T33-b・T41 は、どれも Square・Highlight・Redact。T26 や `p6-t14` の楕円は、注釈ではなくページの中身の図形。

## 確かめた結果（2026-11-07、Node、このフォルダの build.mjs）

- 2回作って、2つの PDF とも SHA-256 が同じだった（`e-annot-01`：`77cb668b1a9c99dd`、`e-annot-02`：`bf77a2bdfa7289fc`）。

| 合成 PDF | 検出ルール（`node cli/omamori.ts check --format json`） | 検証器 P6（`verifier/cli.mjs`） | P1・P5・P7・P9 の検証器 |
|---|---|---|---|
| e-annot-01（漏れ 2） | **0 件（2 件とも見逃し）** | **1 件**：text/annotation、15 字（楕円の方）。手書きの線の方は **0 件（見逃し）** | 0 件 |
| e-annot-02（対照） | 0 件 | 0 件 | 0 件 |

- 検出ルールは漏れ 2 件中 0 件。検証器は 2 件中 1 件。対照はどちらも 0 件。
- 検証器は PDF.js の描く命令（注釈の見た目を含める設定）を読むので、PDF.js が見た目を作った楕円は覆いになった（推測。PDF.js のどこで作っているかは確かめていない）。手書きの線は、検証器の README の「曲がった太い線・線の端の形は見ない」の範囲に入るかもしれないが、原因は確かめていない。
- つまり今は、検証器が楕円を数え、検出ルールが数えない。この食い違いだけでも、検出ルールの見逃しとして採点に出る。

## ルールを作る段への注意（反証役の注意から）

- Ink は線の重ね方しだいで字が隠れきらない。隠れた割合は、形（楕円・太い線の帯）で測る。`/Rect` で近似すると、楕円の角や Ink の隙間で多く数えすぎる。
- Line・PolyLine・StrikeOut の見た目なしも同じ穴だが、今回の範囲外。

## 捨てた案

- 正解の箱を、氏名の字の箱そのもの（12 字）にする案。楕円は前の字も隠すので、検証器の数え方（覆った字を数える）と合わず、検出率の採点でずれる。実際に覆った字で数えた。

## 移し方（人が行う）

```
node proposals/e-shapes/annot-cover-without-ap/build.mjs fixtures/p6
npm run eval
```

- 移すなら、`fixtures/p6/build.mjs` に同じ型を足すか、この build.mjs を置くかを人が決める。`fixtures/p6/index.md`・`hashes.txt` も直す。
- 手書きの線（L2）は、今の検証器では出ない。移すと検証器の確かめ（selfcheck）が通らないので、検証器を直す案と合わせて人が決める。
