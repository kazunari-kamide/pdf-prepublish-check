# 採点する側に足す案：様式の選ぶ欄（開く一覧）の選択肢に、担当者の名前やメールアドレスが残る（P11）

CLAUDE.md §2-3 に従い、合成 PDF と正解データの案をここに置く。Claude は採点する側を書き換えない。人が中身を見て、移すかを決める。

## 何を足すか

| 合成 PDF | 種類 | 中身 |
|---|---|---|
| `e-choice-01-combo-options-personal` | 漏れ（choice_option）2 件 | `/AcroForm /Fields` に、開く一覧の選ぶ欄（`/FT /Ch`、`/Ff 131072`）を 2 つ。1 つめの `/Opt` は、書き出し用の値と表示する名前の組（`[(k.kitagawa@example.jp) (北川花子)] …` の 3 組）。2 つめの `/Opt` は、ただの字（「窓口 A（内線 1234）」「担当 北川（090-0000-1111）」）。値（`/V`）は無く、ウィジェットの見た目は空 |
| `e-choice-02-fixed-words-and-listbox` | 漏れでない 3 件 | 選択肢が「はい」「いいえ」（組）と「午前」「午後」（ただの字）だけの開く一覧。選択肢（窓口のアドレス）が見た目に描かれて画面に並ぶ、一覧の箱（Combo の無い `/Ch`） |

作り方：`node build.mjs [出力先]`。出力先を省くと、このフォルダの `out/` に書く。名前・アドレス（`example.jp`）・番号は架空。

- `fixtures/` に P11 の合成 PDF の置き場はまだ無い。正解データは `fixtures/p6` の形（`leaks`・`negatives`）にそろえ、`kind`・`field`・`options`（数える選択肢の数）を足した。

## なぜ漏れか

前の担当課で作った様式を流用すると、開かないと見えない選択肢の一覧に、職員の名前や個人のメールアドレスが残る。欄を押すか中身を読めば取り出せるが、ページの見た目には `/V` の値しか出ない。欄の説明（`/TU`。指を置くと出る）を漏れとして数える T66・P11 1.1.0 と同じ考え方。

- 一覧の箱（Combo の無い `/Ch`）は、選択肢が画面に並んで見えるので、見えている情報と同じになる。漏れとは言いにくいので対照にした。

## 今の型との違い

- `rules/p11-forms/index.ts` が見るのは `/V`・`/TU`・`/TM`・署名者名だけで、`/Opt` を読むところは無い。
- `fixtures/p5` の `p5-07`・`p5-20` は字の欄の値の書き直し。見ないで作るテスト集の T84・T85 は `/V`、T66 は `/TU`、T86 は XFA。どれも `/Opt` ではない。

## 確かめた結果（2026-11-07、Node、このフォルダの build.mjs）

- 2回作って、2つの PDF とも SHA-256 が同じだった（`e-choice-01`：`9e6f33f8496b8750`、`e-choice-02`：`87ec5ea490c873e9`）。

| 合成 PDF | 検出ルール（`node cli/omamori.ts check --format json`） | 検証器（P6・P1・P5・P7・P9） |
|---|---|---|
| e-choice-01（漏れ 2） | **0 件（2 件とも見逃し）** | どれも 0 件（P11 の検証器は無い） |
| e-choice-02（対照） | 0 件 | どれも 0 件 |

検出ルールは漏れ 2 件中 0 件。対照は 0 件。P11 の検証器は `verifier/` に無いので、検証器では採点できない。

## ルールを作る段への注意（反証役の注意から）

- 数えるのは、開く一覧（`/Ff` に 131072）の選択肢のうち、`contactLike`（メールアドレス・3けた以上の数字・「様」「内線」など）の字を含むものだけ。都道府県の一覧や「午前・午後」のような、ふつうの選択肢で誤検知しないため。
- 書き出し用の値と表示する名前の組（2要素の配列）と、ただの字の両方を読む。

## 捨てた案

- `/V` に「選んでください」を入れる案。今の P11 は空でない `/V` を値として数えるので、漏れの PDF が別の理由で出てしまい、選択肢の見逃しを確かめられない。`/V` は付けなかった。

- 置き場が決まったら、`index.md`・`hashes.txt` を作り、`npm run eval` で確かめる。
