# 採点する側に足す案：画素は黒く塗ったのに、文字認識の層に氏名が残る（P6）

CLAUDE.md §2-3 に従い、`fixtures/` に足す合成 PDF と正解データの案をここに置く。Claude は採点する側を書き換えない。人が中身を見て、移すかを決める。

## 何を足すか

| 合成 PDF | 種類 | 中身 |
|---|---|---|
| `e-ocr-01-burned-but-text-left` | 漏れ（text/burned_pixels）1 件 | 1ページ全体のスキャン画像（Do で描く画像）。氏名の所の画素を、画像の中で黒く塗った。その上の描き方 3（`3 Tr`）の見えない字（文字認識の層）に、氏名「Hanako Kitagawa」が黒い所と同じ位置で残る。黒い四角の塗り（`re f`）や注釈の覆いは無い |
| `e-ocr-02-burned-and-text-removed` | 漏れでない 5 件 | 同じスキャン画像で、黒い所の上の見えない字も消した。黒い帯に白抜きの字があるスキャンと、その上の文字認識の字（帯の字と同じ）も置く |

作り方：`node build.mjs [出力先]`。出力先を省くと、このフォルダの `out/` に書く。名前・住所は架空。字は Helvetica（埋め込まない標準の字体）。見本として除かれる「山田太郎」は使わない（`rules/pii` の結果と混ざらないように）。

- 正解データの `cover` に、新しい値 `burned_pixels`（画像の画素そのものを塗った所）を使った。今の `fixtures/p6` の `cover` は `fill`・`image`・`annotation` だけなので、移すなら `verifier/schema.json` に足すかを人が決める。

## なぜ漏れか

複合機でスキャンと文字認識をしたあと、画像だけを編集して黒く塗ると、見た目は正しい墨消しになる。けれど見えない字の層に氏名が残り、ふつうのビューアの検索やコピーで取り出せる。

## 今の型との違い

- `fixtures/p6` の `p6-t11` は黒い四角の覆いがある。`p6-n02` は画素を塗ったうえで黒い四角を重ね、文字認識の層は無い。この形はその間にある。
- `fixtures/p7` の `p7-08`・`p7-25` は、画素を塗っていない、ふつうの文字認識の層。
- 見ないで作るテスト集の T39 は覆いがあり、T40〜T42 は画素を塗ったうえで覆いがある対照で、文字認識の層は無い。T62 は画素を塗っていない。
- ルールの側：`rules/p6-text` は覆い（塗り・注釈・あとから描いた画像）を起点にする。画像を覆いにするときは画像全体の濃さで決めるので、紙の地が白いスキャン画像は覆いにならない。`rules/p7-hidden` の judge は、見えない字の中心が画像の箱の中にあれば、画素を見ずに文字認識の層（`excluded: "ocr"`）として除く。

## ルールを作る段への注意（反証役の注意から）

- 出すのは「見えない字の箱の下の画素が、ほぼすべて濃い」ときに限る。合成では、ふつうの行は 0.25、白抜きの帯は 0.744、塗った所は 1.0 だった。閾値は 0.9 以上など【仮】。本物のスキャンの値は測っていない。
- 型は P6（覆いのオブジェクトが無い P6）がよい。P7 の `excluded.ocr` の手前で分けるか、P6 の画像の層に足すかは、ルールを作る段で決める。

## 捨てた案

- 対照を「画像を塗っていない、ふつうの文字認識の層」だけにする案。`p7-08` と同じになり、閾値の上の側（白抜きの帯のような、濃いが字が見えている所）を確かめられないので、帯の対照を足した。
