# 採点する側に足す案：テキストの欄の値（/V）が、圧縮したストリームで入っている（P11）

CLAUDE.md §2-3 に従い、`fixtures/` に足す合成 PDF と正解データの案をここに置く。人が中身を見て、移すコミットを作る。字はすべて架空（山田太郎、○○町1-2-3）。

## 何を足すか

| 合成 PDF | 型 | 中身 |
|---|---|---|
| `p11-s01-value-text-stream` | 漏れ（P11。hidden・text） | `/AcroForm /Fields` に、隠しのウィジェット（`/F 2`）と一体の複数行のテキストの欄（`/FT /Tx /Ff 4096 /T (備考)`）。`/V` は Flate で圧縮したストリームで、中身は UTF-16BE（BOM つき）の「山田太郎　○○町1-2-3」（13 字） |
| `p11-sc01-empty-text-streams` | 漏れでない 2 | `/V` がストリームで、中身が 0 バイトの欄と、空白だけ（UTF-16BE の空白・全角空白・改行）の欄 |

作り方：`node build.mjs [出力先]`。出力先を省くと、横の `out/`（コミットしない）に書く。日時も乱数も使わないので、何度作っても同じバイト列になる。

## なぜ漏れか

ISO 32000 の 12.7.4.3 で、テキストの欄の値は字の並びか、ストリーム（PDF 1.5 から）で入れられる。ストリームでも Flate をほどけば UTF-16BE の字として読める。隠したウィジェットなら画面にも出ない。

## 今の型との違い

- `rules/p11-forms/index.ts` の `valueOf`（71〜92 行）は、字の並び・名前・配列だけを値として読み、それ以外（ストリーム）は `{ skip: "empty" }` にする。そのため見逃すうえに、`notCounted.empty` に「空の欄」として数えてしまう。
- `eval/cases/p11.ts`、`fixtures/p5` の p5-07・p5-20、`proposals/blind` の t84・t85 の `/V` は、どれも字の並び。ほかのルールにも、欄の `/V` のストリームを読むものは無い。

## 確かめた結果（2026-11-07、Node 24.19.0、Windows）

`node build.mjs` を2回（`out/` と `out-again/`）実行し、PDF 2 個と正解データ 2 個の SHA-256 がすべて同じだった。

| 合成 PDF | SHA-256（先頭16桁） | 検出ルール | 検証器（`verifier/` の CLI。呼ぶだけ） |
|---|---|---|---|
| p11-s01-value-text-stream | `b8124efe5e8591b9` | **見逃し**：P11 0 件（`hasForm=true`・`fields=1`。値の入った欄が `notCounted.empty` に 1 と数えられた）。`omamori.ts check` は項目 0・stage `none` | P6・P1・P5・P7・P9 とも 0 件（P11 を見る検証器は無い） |
| p11-sc01-empty-text-streams | `74f9d428572d225a` | 0 件（`notCounted.empty` 2。正しい） | 5 つとも 0 件 |

- 漏れが本物であることの確かめ：pdf-lib で `/V` のストリームをほどくと 28 バイト（BOM `FE FF` ＋ 13 字）だった。
- 実物の PDF でどれくらい出る形かは確かめていない（推測では少ない）。

## 正解の決め方（人の判断）

- 正解は P11 の `hidden`・`text`（ウィジェットが `/F 2` のため）。見えるウィジェットの版（`visible`）も1つ足すとよい（この案には入れていない）。
- 対照の2つは、どちらも `empty` に数えられて見つからないのが正しい。
- 直すときは、ストリームの大きさに上限を設ける（CLAUDE.md §11-3。たとえば 1MB【仮】を超えたら読まずに `limits` に入れる）。

## 捨てた案

- `/V` のストリームを圧縮なしで入れる：Flate の方が、実際の作り手が書く形に近く、「字の並びをそのまま探す」直し方で済ませるのを防げる。圧縮なしの版は、補助として足してもよい。

## 移し方（人が行う）

```
node proposals/e-shapes/p11-value-text-stream/build.mjs fixtures/p11
npm run eval
```

- fixtures に P11 のフォルダは無いので、置き場所は人が決める。`index.md` と `hashes.txt` も足す。
- 検出ルールの直し方の案：`valueOf` で、ストリームなら（上限の中で）ほどき、BOM で UTF-16BE か PDFDocEncoding かを決めて字にし、空白だけなら `empty` にする。
