# 検証器：P5（旧版の残存）

PDF を1つ入れると、いまの版では使っていないのに、ファイルの中に残っている中身を JSON で返す。

```
node verifier/p5-cli.mjs 入力.pdf        # 標準出力に JSON（形は p5-schema.json）
node verifier/p5-selfcheck.mjs           # 合成 PDF と正解データで、検証器そのものを確かめる
```

終了コード：0 ＝ 読めた（残りがあっても 0）、1 ＝ 使い方の誤り、2 ＝ PDF を読めなかった。

## 検査器から独立していること

- `src/`・`rules/` のコードを import しない。この案を書いたセッションは、P5 の検出ルールを書かない（別のセッションが書く）。
- pdf-lib は使わない。pdf-lib は、同じ番号のオブジェクトをいちばん新しいものだけ残して読むため、前の版が見えない。
- PDF.js も使わない。前の版を見せる道具がないため。突き合わせの代わりに、**2つの見つけ方**を持つ。
  1. **xref を版ごとにたどる**：末尾の `startxref` から `/Prev` までたどり、版ごとの xref（表・xref ストリーム・混ぜた形）を分けて読む。いまの版の場所と違う定義を superseded、いまの版で「使っていない」とされた番号の定義を free にする。いまの版の根からたどれないものを unreferenced にする。
  2. **ファイル全体から「N G obj」を探す**：どの版の xref にも載っていない定義を orphan にする。既知のストリームの中身の範囲にあるものは除く。
- バイト列の読み方の部品（値の読み方・ストリームの解き方）は、P9 の検証器の `p9-pdfbytes.mjs` を使う。`verifier/` に移したあとは同じフォルダのもの、`proposals/` にある間は `verifier/` のものを読む。

## 種類の見分け方

- 文書情報：どれかの版の trailer が `/Info` として指した番号。または、`/Type` のない辞書で、文書情報の鍵（Author など）を持つもの。
- 中身：`/Type` のないストリームか、部品（`/Subtype /Form`）で、字を描く命令（`Tj`・`TJ`・`'`・`"`）があるもの。
- 注釈：`/Type /Annot`、または注釈の種類（`/Subtype`）と `/Rect` を持つもの。フォームの欄を兼ねる注釈は、フォームの値として見る。
- フォームの値：`/FT` を持つ（または `/T` と `/V` を持つ）辞書。
- XMP：`/Type /Metadata` のストリーム。画像：`/Subtype /Image`。添付の中身：`/Type /EmbeddedFile`。ファイル指定：`/Type /Filespec`。
- それ以外は骨組み（structure）。

## 確かめた結果（2026-11-03、Node 24.19.0、Windows）

`node proposals/p5/verifier/p5-selfcheck.mjs` の結果：

- 合成 PDF 21 個すべてで、正解データと合った。漏れ 21 件中 21 件を見つけた。漏れでないもの 18 件中 0 件に反応した。正解にない出力は 0 件。漏れでないものは、すべて `not_counted` に同じ番号・種類・場所で出た。
- 壊れた入力 5 種（空のファイル、PDF でないもの、途中で切れた PDF、`/Prev` が自分を指す xref、`/Encrypt` のある trailer）で、止まらなかった。
- 合成 PDF は、手で書いたので、PDF.js で 21 個すべてを開けること、いまの版の字と文書情報が見えることを確かめた。

## できないこと（限界）

- **暗号化された PDF は調べない**（`encrypted`）。前の版の中身も暗号化されているため。P1・P6 の検出ルールの復号（パスワードなしで開けるもの）と同じことを、検証器では書いていない。→ 決めてほしいこと
- 字を描く命令は、文字の並びで探す目安。字の中身が前の版と同じかは見ない（同じでも、残っていれば数える）。
- 種類の見分けは、辞書の鍵での目安。`/Type` を省いた注釈などは、骨組みと見分けられないことがある。
- 圧縮は Flate だけを解く（p9-pdfbytes.mjs）。ほかの圧縮の中身は、字があるか見分けられない（structure、reason `unreadable_stream`）。
- 「線形化（Linearized）」した PDF は、最初のページ用の xref が別にあり、版が2つに見える。そのとき、ヒントのストリームなどが unreferenced の骨組みとして出ることがある（数えない）。合成 PDF ではまだ試していない。
- ファイル全体から「N G obj」を探すのは、20 万個まで。
