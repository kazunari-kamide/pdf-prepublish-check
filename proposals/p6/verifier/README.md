# 検証器：P6（見せかけの黒塗り）

PDF を1つ入れると、「覆っているもの（濃い塗り・濃い画像・注釈）の下に、まだ中身が残っている所」を JSON で返す。PRD §2-3-1 の入出力に合わせている。

```
node verifier/cli.mjs 入力.pdf            # 標準出力に JSON（形は schema.json）
node verifier/cli.mjs 入力.pdf --include-text   # 覆われた字そのものも出す（調べるときだけ。記録やログには使わない）
node verifier/selfcheck.mjs              # 合成 PDF と正解データで、検証器そのものを確かめる
```

終了コード：0 ＝ 読めた（残りがあっても 0）、1 ＝ 使い方の誤り、2 ＝ PDF を読めなかった。

## 検査器から独立していること

- `src/`・`rules/` のコードを import しない。この版を書いたセッションは、`src/` を読んでいない。
- 読み方を変える。検査器は自前でコンテンツストリームを読む。検証器は PDF.js（pdfjs-dist 6.4.299）の描画命令の列（`getOperatorList`）と注釈の一覧（`getAnnotations`）を使う。
- 片付けた側の報告は受け取らない。入力は PDF のファイル1つだけ。
- PDF.js は安全側の設定で使う（`isEvalSupported: false`、`disableFontFace: true`、`useSystemFonts: false`）。

## 判定の考え方

ページは描く命令の並びで、あとに描いたものが上に重なる。命令を順に追い、次の3つを集める。

1. **覆い**：濃い色（明るさ 0.3 以下、不透明さ 0.9 以上）で塗った四角に近い図形。太い直線（マーカーで塗ったような線）。ほぼ全部が濃い画像。注釈の見た目の中の濃い塗り。未適用の墨消し注釈（`/Redact`。見た目がなくても、黒塗りのつもりの所として数える）。
2. **字**：1字ごとの箱（位置・大きさ・何番目に描いたか）。見えない字（描き方 3）も入れる。取り出せることに変わりはないため。
3. **画像**：置いた位置と画素。

- **字の層**：字の箱の半分以上が、その字より**あとに描いた**覆いに隠れていれば、「覆われた字」とする。覆い1つごとに1件にまとめる。字が覆いより**あと**に描かれていれば上に見えているので、数えない（黒い帯の上の白い字など）。
- **画像の層**：覆いの範囲に当たる、先に描いた画像の画素を数える。インク（明るさ 0.5 以下）と紙の色（0.5 以上）が両方あれば、「画像の中身が残っている」とする。
  - 全部が濃い ＝ 画像の画素そのものが塗られている（正しい墨消し）→ 数えない
  - 全部が紙の色 ＝ もともと何も書かれていない → 数えない
  - 文字認識（OCR）はしない。字かどうかは見ず、「何か描かれているか」だけを見る。

## 判定の値と、合成 PDF で測った余裕（2026-11-03）

「測」は検証器の出力から測った値、「計」は合成 PDF の作り方（色・座標）から計算した値。

| 値 | 決めた値 | 合成 PDF での値 |
|---|---|---|
| 塗りを「濃い」とみなす明るさの上限 | 0.3 | 計：漏れの覆いは 0（黒）〜 0.10（#1a1a1a）。漏れでないものは、薄い灰色 0.87、黄色 0.93 |
| 字が「覆われた」とみなす割合 | 0.5 | 計：漏れは 1.0（覆いの中に字が収まる）。下線は約 0.08 |
| 画像の層で「インクがある」とみなす割合 | 0.005 | 測：漏れの覆いの下は 0.106〜0.158（8 件）。計：余白の上は 0 |
| 画像の層で「紙の色がある」とみなす割合 | 0.02 | 計：画素を黒くした所は 0 |
| 画像を「覆い」とみなす濃い画素の割合 | 0.95 | 計：黒い画像は 1.0。暗い写真は約 0.78（明るさ 15〜94 の画素を一様に散らしたもの） |

- どの値も、合成 PDF の上では、漏れと漏れでないものの間に大きな開きがある。そのため、値を少し動かしても結果は変わらない。逆に言えば、合成 PDF だけでは値を細かく決められない。本物の PDF での件数を見て見直す。

## 確かめた結果（2026-11-03、Node 24.19.0、Windows）

`node verifier/selfcheck.mjs` の結果：

- 合成 PDF 26 個すべてで、正解データと合った。
- 漏れ 23 件中 23 件を見つけた。漏れでないもの 16 件には 0 件反応した。正解にない出力は 0 件だった。
- 型ごとの内訳：text/fill 12 件中 12、text/image 1 件中 1、text/annotation 2 件中 2、image/fill 5 件中 5、image/image 1 件中 1、image/annotation 2 件中 2。
- 壊れた入力（空のファイル、PDF でないもの、途中で切れた PDF）では、止まらずに `status: "error"` を返した。

## できないこと（限界）

- **切り抜き（クリップ）は見ない。** 覆いがクリップで実際には描かれていなくても、覆いとして数える。
- **四角でない覆い**（円、斜めに置いた四角、曲がった線）は覆いとして数えない。四角に近い図形（外枠の箱の 90% 以上を埋めるもの）と、縦か横の直線だけを扱う。
- **縦書きの字**は、横書きと同じ箱で近似している。合成 PDF にはまだ入れていない。
- **黒い1ビットの型抜き画像（image mask）** は、覆いとして数えない。
- **白い覆い**（白い四角で字を隠したもの）は数えない。P7（隠れたテキスト）の範囲として扱う。
- **本物のスキャン**は、余白にも点のような汚れがある。インクの割合 0.005 という値は合成のスキャンで決めたもので、本物では誤検知が出るかもしれない。採点用データ（非公開）で件数を見てから見直す。
- 暗号化された PDF は `encrypted` で止める（合成 PDF ではまだ試していない。pdf-lib で暗号化した PDF を作れないため）。
- 1ページの命令が 30 万を超えるときは、そのページを省き、`skipped_pages` に入れる（CLAUDE.md §5 の重いページ対策）。時間の上限は、まだ設けていない。
