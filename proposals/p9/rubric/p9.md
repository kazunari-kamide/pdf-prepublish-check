# 合格基準：P9（添付ファイル）【案】

機械で読む版は `rubric/p9.json`。2つの中身は同じにする。値を決める・変えるのは人だけ（CLAUDE.md §2-3）。

## 1. 合格の条件（案。P6 にならう）

合成 PDF（`fixtures/p9/`）全体で、次の3つを**すべて**満たすこと。

| 条件 | 値 |
|---|---|
| 検出率 | 95% 以上 |
| 誤検知率 | 5% 以下 |
| 片付けたあとに残る情報 | 0 件 |

- 判定は全体の数字で行う。内訳として、場所ごとの件数をいつも並べて出す。

| 内訳（where） | 中身 |
|---|---|
| names | 文書の名前の木（/Names の /EmbeddedFiles）から指されている |
| annotation | ページの添付ファイルの注釈（クリップのしるし）から指されている |
| af | 関連ファイル（文書・ページの /AF）だけから指されている |
| unreferenced | どこからも指されていないが、中身がファイルの中に残っている（名前の木から外しただけ、増分更新で外した、など） |

## 2. 数え方

- **1件** ＝ ファイルの中に残っている、添付の中身（`/EF` が指すストリーム）1つ。
  - 同じ中身を2つの場所が指していても1件（場所は、names → annotation → af の順で先のものにする）。
- **数えないもの**（漏れでないもの。誤検知率の分母）：中身のない（外のファイルを指すだけの）ファイル指定、リンク（URL・外のファイルを開く・別の PDF に飛ぶ）、空の名前の木、画像や XMP のストリーム、JavaScript の名前の木、ページの字に書かれた「EmbeddedFile」の文字。
- **検出率** ＝ 見つけた漏れの数 ÷ 正解データの漏れ（`leaks`）の数
- **誤検知率** ＝ 誤検知の数 ÷ 正解データの「漏れでないもの」（`negatives`）の数
  - 誤検知の数 ＝ 漏れでないものへの報告の数 ＋ 正解のどれにも当たらない報告の数
- **片付けたあとに残る情報** ＝ 片付けたあとの PDF を検証器にかけたときの `items` の数の合計
  - 検証器が「読めない」（`status` が `ok` でない）と返したものは、0 件とは数えない（不合格）。

## 3. 照らし合わせ方

報告と正解データを、次の条件で1対1に結ぶ。

1. 同じファイルであること
2. 同じファイル名であること（名前の木の鍵ではなく、ファイル指定の /UF、なければ /F）
3. 同じ場所（`where`）であること → 決めてほしいこと 2

## 4. 採点の流れ

P6 と同じ（rubric/p6.md §4）。片付けた PDF を `node verifier/p9-cli.mjs` にかけ、`items` の数を数える。

## 5. 採点用データ（非公開）

ループには読ませない。人が手元で回し、件数だけを記録する。合格ラインは設けない。
