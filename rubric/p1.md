# 合格基準：P1（文書情報）【案】

機械で読む版は `rubric/p1.json`。2つの中身は同じにする。値を決める・変えるのは人だけ（CLAUDE.md §2-3）。

## 1. 合格の条件（案。P6 にならう）

合成 PDF（`fixtures/p1/`）全体で、次の3つを**すべて**満たすこと。

| 条件 | 値 |
|---|---|
| 検出率 | 95% 以上 |
| 誤検知率 | 5% 以下 |
| 片付けたあとに残る情報 | 0 件 |

- 判定は全体の数字で行う。内訳として、欄の種類ごと（決まった欄 / 独自の欄）の件数を、いつも並べて出す。

| 内訳 | 中身 |
|---|---|
| standard | 決まった欄：Title・Author・Subject・Keywords・Creator |
| custom | それ以外の、独自の欄（Company・Manager・SourceModified など） |

## 2. 数え方

- **1件** ＝ いまの版の文書情報（trailer の /Info）の、1つの欄（鍵）。
- **数える欄**：値が空でない欄のうち、下の「数えない欄」以外のすべて。
- **数えない欄**（漏れでない。誤検知率の分母）
  - `Producer`（PDF を書き出したソフトの名前）
  - `CreationDate`・`ModDate`（日付）
  - `Trapped`（印刷の設定）
  - 値が空、または空白だけの欄
- **検出率** ＝ 見つけた漏れの数 ÷ 正解データの漏れ（`leaks`）の数
- **誤検知率** ＝ 誤検知の数 ÷ 正解データの「漏れでない欄」（`negatives`）の数
  - 誤検知の数 ＝ 漏れでない欄への報告の数 ＋ 正解のどれにも当たらない欄への報告の数
- **片付けたあとに残る情報** ＝ 片付けたあとの PDF を検証器にかけたときの `items` の数の合計
  - 検証器が「読めない」（`status` が `ok` でない）と返したものは、0 件とは数えない（不合格）。
- 前の版の文書情報（増分更新で残ったもの）は、P1 の分母に入れない（P5 の範囲）。検証器は `previous_info` に数だけを出す。→ 決めてほしいこと 3

## 3. 照らし合わせ方

報告と正解データを、次の条件で1対1に結ぶ。

1. 同じファイルであること
2. 同じ欄（鍵）であること。鍵の `#xx` は解いてから比べる（`Doc#20Owner` ＝ `Doc Owner`）

- 値の字数・文字の書き方（UTF-16BE など）は、合否には使わない。

## 4. 採点の流れ

P6 と同じ（rubric/p6.md §4）。片付けた PDF を `node verifier/p1-cli.mjs` にかけ、`items` の数を数える。

## 5. 採点用データ（非公開）

ループには読ませない。人が手元で回し、件数だけを記録する。合格ラインは設けない。
