# 合格基準：P5（旧版の残存）【案】

機械で読む版は `rubric/p5.json`。2つの中身は同じにする。値を決める・変えるのは人だけ（CLAUDE.md §2-3）。

## 1. 合格の条件（案。P6 にならう）

合成 PDF（`fixtures/p5/`）全体で、次の3つを**すべて**満たすこと。

| 条件 | 値 |
|---|---|
| 検出率 | 95% 以上 |
| 誤検知率 | 5% 以下 |
| 片付けたあとに残る情報 | 0 件 |

- 判定は全体の数字で行う。内訳として、場所（where）ごと・種類（kind）ごとの件数を、いつも並べて出す。

## 2. 数え方

- **1件** ＝ いまの版では使っていないのに、ファイルの中に残っているオブジェクトの定義1つ。
  - 同じ番号を2回書き直していれば、前の定義が2つ残るので2件。
- **場所（where）**

| where | 中身 |
|---|---|
| superseded | 増分更新で、同じ番号のオブジェクトを新しく書き直した。前の定義が残っている |
| free | いまの版の xref が「使っていない」（f）と印をつけた。前の版の定義のバイト列が残っている |
| unreferenced | いまの版の xref には載っているが、いまの版の根（trailer の /Root・/Info・/Encrypt）からたどれない |
| orphan | どの版の xref にも載っていないのに、ファイルの中に「N G obj」として書いてある |

- **数える種類（kind。漏れ）**

| kind | 中身 | 数える条件 |
|---|---|---|
| info | 文書情報（どれかの版の trailer が /Info として指したもの） | P1 で数える欄（Producer・日付・Trapped 以外）に値がある |
| content | ページの中身・部品（Form XObject）のストリーム | 字を描く命令（Tj・TJ など）がある |
| annotation | 注釈 | /Contents・/T・/RC・/Subj のどれかに字がある |
| form_value | フォームの欄 | /V に値がある |
| metadata | XMP のストリーム | いつも |
| image | 画像 | いつも |
| embedded_file | 添付の中身 | いつも（ただし unreferenced は P9 で数える。下の §3） |

- **数えないもの（漏れでないもの。誤検知率の分母）**：ページ・ページの木・文書の根などの骨組み（structure）、字のない注釈、値のない欄、ファイル指定（filespec）、Producer と日付だけの文書情報、P9 で数える添付。
  - xref ストリームとオブジェクトストリームは、場所の入れ物なので、数えない（not_counted にも出さない）。
- **検出率** ＝ 見つけた漏れの数 ÷ 正解データの漏れ（`leaks`）の数
- **誤検知率** ＝ 誤検知の数 ÷ 正解データの「漏れでないもの」（`negatives`）の数
  - 誤検知の数 ＝ 漏れでないものへの報告の数 ＋ 正解のどれにも当たらない報告の数
- **片付けたあとに残る情報** ＝ 片付けたあとの PDF を検証器にかけたときの `items` の数の合計
  - 検証器が「読めない」（`status` が `ok` でない）と返したものは、0 件とは数えない（不合格）。

## 3. ほかの型との分け方（この案で決めること）

同じ残りを、2つの型で二重に数えないようにする。**P1・P9 は、いまの版だけを数える。いまの版で使っていないものは P5 で数える。**

| 残っているもの | 数える型 | P5 での形 | ほかの型での扱い |
|---|---|---|---|
| P1「前の版の文書情報」（同じ番号を書き直した前の Info、新しい番号に差し替えた前の Info） | **P5** | info（superseded・unreferenced） | P1 は分母に入れず、件数だけを出す（rubric/p1.md §2 のとおり）。P5 の検証器は `summary.previous_info` に同じ数を出す |
| P9「増分更新で外した添付」で、中身が**いまの xref にまだ載っている**もの（名前の木から外しただけ） | **P9** | 数えない（not_counted、reason `counted_by_p9`） | P9 の unreferenced（rubric/p9.md） |
| P9「増分更新で外した添付」で、中身を**同じ番号で書き直した**もの | **P5** | embedded_file（superseded） | P9 は数えない |
| P9「xref で使っていないと印をつけただけの中身」（PR #20 の返事の 1） | **P5** | embedded_file（free） | P9 は分母に入れず、件数を別に出す。P5 の検証器は `summary.removed_attachment` に数を出す |
| P6 の覆い・P8 の注釈などで、前の版にだけあるもの | **P5** | 種類ごと | いまの版の型（P6・P8 など）は、いまの版だけを見る |

## 4. 照らし合わせ方

報告と正解データを、次の条件で1対1に結ぶ。

1. 同じファイルであること
2. 同じオブジェクトの番号であること
3. 同じ種類（kind）・同じ場所（where）であること

- 同じ組（番号・種類・場所）が2つあるとき（同じ番号を2回書き直した）は、数を合わせる。
- 版の番号（revision）と字数（chars）は、合否には使わない。

## 5. 採点の流れ

P6 と同じ（rubric/p6.md §4）。片付けた PDF を `node verifier/p5-cli.mjs` にかけ、`items` の数を数える。

## 6. 採点用データ（非公開）

ループには読ませない。人が手元で回し、件数だけを記録する。合格ラインは設けない。
