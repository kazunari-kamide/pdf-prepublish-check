# 検出ルール：P4（ファイルパス・内部ホスト名）`p4-paths`

文書情報・XMP（文書全体と部品）・注釈・リンクや動作の行き先・ファイル指定の名前の中の、パソコンや庁内のサーバーの場所を示す字を見分けて数える。**値そのものは返さない**（種類・場所・字数だけ）。

| 種類（`kind`） | 何か | 字数 | 画面の深刻度【仮】 |
|---|---|---|---|
| `user_path` | ユーザーのフォルダを含むパス（`C:\Users\<名前>\`・`/Users/<名前>/`・`/home/<名前>/`。`file://` の中も） | ユーザーの名前 | 中 |
| `server` | 共有フォルダ（`\\<サーバー>\…`・`smb://`・`file://<サーバー>/`）と、点の無いホスト名・内向きの IP アドレスの http・https の URL | サーバーの名前 | 中 |
| `drive_path` | ドライブ名から始まるパスで、ユーザーのフォルダを含まないもの（`D:\広報\…`） | パス全体 | 低 |

- 同じ値は 1 件にまとめ、`places` に見つけた所の数を添える。場所は最初に見つけた所（リンクの行き先のファイル指定は `link`）。
- 数えないもの：点のあるホスト名の URL、相対パス（`../別紙.pdf`）、ドライブ名の無いファイル名、時刻や比（`10:30`・`3:2`）。

## 確かめたこと

- 合成 PDF 7 件（隠しあり 5・対照 2。`eval/cases/p4.ts`。`npm run eval:new`）：検出 7/7、誤検知 0。
- 今ある合成 PDF 124 件（p1・p5・p6・p7・p9）では、タイトルにパスを入れた P1 の 1 件だけに出た。

## できないこと（限界）

- ページに描かれた字の中のパスは見ない（見えている字なので）。
- `p2-xmp`・`p2-parts` も XMP のユーザーのフォルダのパスを P4 として出すので、同じパスが 2 つのルールで出ることがある。
- 点を含む庁内のホスト名（`fs.example.local` など）は見分けない。
