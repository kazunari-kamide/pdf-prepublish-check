# 検出ルール：P6（見せかけの黒塗り）

PDF を入れると、次の3つを返す（図形の層は 1.13.0 から）。docs/prd.md §3。

- **文字の層**（`layer: "text"`）：字のあとに、その字を覆う濃いもの（塗り・画像・注釈）を重ねている所。黒い四角の下に、選べる・コピーできる字が残っている。1.11.0 から、白・灰・色の不透明な覆いと、型抜きのない画像も覆いにする（`coverTone: "opaque"`）。
- **画像の層**（`layer: "image"`。1.5.0 から）：画像（スキャンした書類など）のあとに、不透明な覆い（黒・白の塗り・注釈・黒い画像）を重ねただけで、覆いの下の元の画素に何か写っている所。覆いを外す・画像を取り出すと、下が読める。
- **図形の層**（`layer: "vector"`。1.13.0 から）：白い不透明な四角の注釈の下に、ページの中身の道（線や形で描いた字など）が多くある所。いつも「確かめてください」（`check`）。

```ts
import { detectP6Text } from "./rules/p6-text/index.ts";
const report = await detectP6Text(bytes);              // 覆われた字の数だけを返す
const report2 = await detectP6Text(bytes, { includeText: true }); // 字そのものも返す（調べるときだけ。記録やログには使わない）

// JPEG・CCITT・JBIG2 の画像も調べるとき（1.5.0 から）：呼ぶ側で読み込んだ PDF.js を渡す
import { createPdfjsImageDecoder } from "./rules/shared/pdfjs-images.ts";
const report3 = await detectP6Text(bytes, { imageDecoder: createPdfjsImageDecoder(pdfjs, { jbig2Url }) });
// Node（採点・テスト）では eval/image-decoder.ts の createNodeImageDecoder() を使う
// 数えない条件で除いた覆いの数も返す（実物で測るときだけ。1.6.0 から）
const report4 = await detectP6Text(bytes, { imageDecoder, explain: true }); // report4.excluded：{"image:repeated": 20, …}
```

## 見るもの・見ないもの（1.5.0）

| 型（層 / 覆っているもの） | 1.0.0 | 1.1.0 | 1.3.0 | 1.5.0 |
|---|---|---|---|---|
| text/fill（字の上に濃い塗り・濃い太い線） | 見る（四角と縦横の線だけ） | 同じ | **形を問わず見る**（楕円・回した四角・角の丸い四角・斜めの線・曲線） | 同じ |
| text/image（字の上に濃い画像） | 見ない | **見る** | 回して置いた画像も見る | 同じ |
| text/annotation（字の上に濃い注釈・未適用の墨消し注釈） | 見ない | **見る** | 同じ | 同じ |
| image/*（スキャン画像の画素が残っている型） | 見ない | 見ない（2026-11-03、人の決定。D60） | 同じ | **見る**（2026-11-04、人の決定。見つける段で見つかった型） |

- 1.2.0 で、パスワードなしで開ける暗号化 PDF も、復号して調べるようになった（「できないこと」の暗号化の項）。
- 1.4.0 で、報告に「どの層を調べたか」（`checkedLayers`）を足した。読めた PDF では、この版が調べる層（`CHECKED_LAYERS`。1.4.0 は `["text"]`、1.5.0 から `["text", "image"]`）を、読めなかった PDF（`status: "error"`）では、何も調べていないので空を返す。見つけるもの・数は変わらない。
  - 画面は、ここに `"image"` がない間、「P6 のうち、画像の下の中身は、読み直しではまだ調べていません」と添える（PR #38 の返事）。画像の層を見る版にしたら、`CHECKED_LAYERS` に `"image"` を足す。画面の一言は、この値を見て外れるので、外し忘れない。
  - 検証器の出力の形（verifier/）は変えない。採点のための変換（`eval/adapters/p6-text.ts`）も、この値を検証器の形に入れない。

- 1.5.0 で、画像の層を見るようにした（下の「画像の層の考え方」）。あわせて、pdf-lib で解けない圧縮の画像（JPEG・CCITT・JBIG2）を、PDF.js で解けるようにした（`imageDecoder`）。文字の層の「黒い JPEG を字の上に貼った型」も、解ければ見つける。

- 1.6.0 で、実物の公開 PDF で反応した「隠したものではない」型を数えないようにした（下の「数えない条件」）。合成 PDF の結果は変わらない。
- 1.7.0 で、数えない条件を足し、画像の層の報告に確からしさ（`confidence`）を足した（下の「数えない条件（1.7.0 で足したもの）」）。合成 PDF の結果は変わらない。
- 1.8.0 で、文字の層の報告にも確からしさ（`confidence`）を足し、覆いの上に何があるかで分けた（下の「文字の層：覆いの上のあり方（1.8.0）」）。合成 PDF の結果は変わらない。
- 1.9.0 で、大きな画像を解けるようにし（要る画像だけを解く・画素の数の上限）、注釈の覆いの下の画像を解けなかったときと、色のある地（地図・航空写真）の上の覆いを「確かめてください」にした（下の「大きな画像と、色のある地（1.9.0）」）。合成 PDF の結果は変わらない。

1.4.0 までは、見ない型（image/*）が合格基準の分母に入っていた（rubric/p6.md §1）ため、全体の検出率で不合格だった（意図したもの）。1.5.0 で、合成 PDF の全体で合格になった（`docs/evolution.md`）。

## 考え方

ページは描く命令の並びで、あとに描いたものが上に重なる。命令を順に読みながら（共通の読み手 `rules/shared/content-lexer.ts` と `page.ts`）、次の2つだけを拾う。図形を全部組み立てることはしない（CLAUDE.md §5）。

1. **覆い**（描いた順番つき）
   - **濃い色で塗った図形**（1.3.0 から、形を問わない）：曲線は 8 本の直線に分け、塗った形そのもの（多角形）を覆いとして持つ。楕円・回した四角・角の丸い四角も覆いになる。
     - 1つの塗りの命令の中で、外枠の箱が重なり合う部分（枠の外と内など）は1つの覆いにまとめ、離れた部分は別の覆いにする。
     - 穴のある形は、塗りの決まりどおりに扱う。ゼロでない決まり（`f`）は向きつきの面積を足す（逆向きの内側は引かれる）。偶奇の決まり（`f*`）は入れ子の深さで足し引きする（外枠の箱の入れ子で見る目安）。字を囲む黒い枠は、字を隠していないので覆いにならない。
     - 1.2.0 までは「四角に近い図形（外枠の箱の 9 割以上を埋めるもの）」だけを覆いにしていた。
   - **濃い色の太い線**：太さが 1pt 以上の線。斜めの線・曲線も見る（1.3.0 から）。直線は1本ずつ、曲線は1本の線をまとめて、線の太さの帯を覆いの形にする。1pt より細い線は、字を半分も隠せないので見ない。
   - **濃い画像**（1.1.0）：画像の画素を読み、濃い画素（明るさが「濃い」の上限以下）が 97% 以上なら、画像を置いた箱を覆いとする（`images.ts`）。黒で塗る型抜き（ImageMask）、色の表（Indexed）、PNG・TIFF の予測、やわらかい型抜き（SMask。透けている画素は濃いと数えない）も見る。
   - **注釈**（1.1.0）：注釈は、ページの中身のあとに重ねて描かれる。そのため、ページのどの字よりもあとの覆いとして扱う（`annotations.ts`）。
     - 見た目（`/AP` の `/N`）があれば、その命令の列を同じように読み、濃い塗り・濃い画像を覆いとする。見た目の座標は、PDF 1.7 §12.5.5 のとおり `/BBox`・`/Matrix` から注釈の箱（`/Rect`）に移す。
     - 見た目のない四角の注釈（`/Square`）は、中の色（`/IC`）が濃ければ、注釈の箱を覆いとする。
     - 未適用の墨消しの注釈（`/Redact`）は、色にかかわらず覆いとする（`/QuadPoints` があればその範囲、なければ `/Rect`）。黒塗りのつもりの所で、まだ下の字が残っているため。
     - 隠した注釈（`/F` の Hidden・NoView）と、半透明（`/CA` が下限より小さい）の注釈は、覆いにしない（墨消しの注釈は除く）。
2. **字**：1字ごとの箱。フォントの幅（`/W`・`/Widths`）と高さ（`/Ascent`・`/Descent`）、字の行列（`Tm`・`Td` など）とページの行列（`cm`）から出す。描いた順番つき。見えない字（描き方 3）も入れる。取り出せることに変わりはないため。

字の箱の半分以上が、その字より**あとに描いた**覆い1つに隠れていれば、「覆われた字」とする。隠れる割合は、覆いの形を字の箱で切り取った面積で測る（形のない覆いは、覆いの箱との重なり）。覆い1つごとに1件にまとめ、覆いの箱と、覆っているものの種類（`fill`・`image`・`annotation`）を返す。字が覆いの**あと**なら上に見えているので数えない（黒い帯の上の白い字など）。

- 部品（Form XObject）の中も、行列（`/Matrix`）をかけて追う。入れ子は 12 段まで。同じ部品を自分の中で呼ぶものは追わない。
- 色は、灰色・RGB・CMYK と、成分の数が分かる ICCBased・CalGray・CalRGB を見る。明るさは 0.299R + 0.587G + 0.114B。CMYK は (1−C)(1−K) などで RGB に直してから。
- 半透明（`/ca`・`/CA`）は、ExtGState（`gs`）から読む。画像の不透明さは `/ca` を使う。
- 解けない画像（JPEG・JPEG 2000・JBIG2・CCITT など、pdf-lib が解けない圧縮）は、覆いとしては数えず、報告の `uncheckedImages` に「調べられなかった画像」として入れる。「問題なし」とはしない。

## 画像の層の考え方（1.5.0）

`image-layer.ts`。命令を読むときに、画像を置いた所（行列つき、描いた順番つき）も集める。

1. **覆い**：画像のあとに描いた、次のもの。
   - 濃い塗り・濃い画像・注釈（文字の層と同じ）。
   - **白っぽい不透明な塗り**（明るさ `lightLuminanceMin` 以上、不透明さ 0.9 以上）。画像に重なるものだけを集め、文字の層では使わない（字の上の白い四角は P7 の範囲）。
   - 見た目のない四角・多角形の注釈は、中の色（`/IC`）が濃いか白っぽければ覆いにする（多角形は 1.5.0 から。注釈の箱で近似）。見た目（`/AP`）のある注釈（Square・Polygon・Ink・FreeText など）は、見た目の中の塗りを読む。
   - 線（太い線）は、画像の層では見ない（写真の縁の飾りの線が、画像の端の上に乗るため）。
   - 中間の色（灰色・色つき）の塗りは、画像の層の覆いにしない（地図の色分けや飾りの帯を数えないため）。
2. **下の画素**：覆いの箱の中に、縦横それぞれ最大 64 点を並べ、覆いの形の中の点ごとに、覆いより前に描いた画像のうち、いちばん上のものの画素を読む（行列の逆で、画像の画素の番号に直す。回した画像も読める）。透けている画素は、その下の画像を見る。
3. **判定**：読んだ画素の明るさの標準偏差（`spread`）が `imageSpreadMin` 以上なら、「下に何か写っている」として1件にする。
   - 下が一様（紙の余白・下の画素も黒く塗った正しい墨消し）なら、標準偏差は 0 に近いので数えない。
   - 覆いの中で、下に画像がある点が `imageUnderFractionMin` より少ない覆いは見ない。
   - 測れた点が 16 点より少ない覆い、下の画像の画素を読めない点が多い覆いは見ない（読めない画像は `uncheckedImages` に入っている）。
4. **白っぽい覆いの上に、あとから字を書いたもの**（年号・誤字の直し、地図の凡例や吹き出しの白い下地）は、直したものとして数えない。字の箱の真ん中が覆いの中にあれば「上に字がある」とする。濃い覆いの上の字（黒塗りの上の札など）では外さない。
5. 返すもの：覆いの種類（`cover`）、色の向き（`tone`：`dark`・`light`）、覆いの箱（`rect`）、ばらつき（`spread`）。下に写っている中身は返さない。

### PDF.js で画像を解く（`rules/shared/pdfjs-images.ts`）

- 画像1つだけを写した小さな PDF を pdf-lib で作り、PDF.js に読ませて、描く命令の一覧から、PDF.js が解いた画素を受け取る。
- PDF.js は、このルールの中では import しない。呼ぶ側が、自分の環境で読み込んだ PDF.js を渡す（ブラウザでは、手を加えずに配る `pdf.min.mjs`。Node では legacy の版）。検査の Worker に PDF.js のコードを混ぜないため（`docs/no-network.md`）。
- PDF.js には、バイト列だけを渡す（`useWorkerFetch: false`、`useWasm: false`、`isOffscreenCanvasSupported: false`、`isImageDecoderSupported: false`）。
- **JPEG**：PDF.js の中の JavaScript だけで解ける。確かめたこと（2026-11-04）：Node 24.19.0（テスト）と、Chrome 156 の Web Worker の中（試しのページ。コミットしていない）で、JPEG のスキャン画像の上の黒い四角を見つけた。
- **CCITT・JBIG2**：PDF.js 6.4.299 では、別の部品（`pdfjs-dist/wasm/jbig2_nowasm_fallback.js`）で解く。`jbig2Url`（その部品のあるフォルダの URL）を渡したときだけ解ける。PDF.js はそこから `import()` で読む（`pdf.worker.mjs` の `WasmImage#getJsModule`）。Node では解けることを確かめた（テストの中で、G4 の符号を手で並べた画像）。ブラウザで使うには、この部品も配る必要がある（下の「できないこと」）。
- 大きさの上限：画素の数 × 4 バイトが `maxImageBytes` を超える画像は、PDF.js に渡さない。PDF.js が失敗した・大きさが辞書と違う画像は「調べられなかった」とする。

## 数えない条件（1.6.0）

P6 1.5.0 を、非公開の場所で実物の公開 PDF 100 個にかけたところ、調べる側が「問題なし」とした 87 個のうち、画像の層が 24 個（報告 4,393 件）、文字の層が 15 個（326 件）で反応した（2026-11-04、見つける段から受け取った種類と件数の一覧。実物の PDF は受け取っていない）。画像の層の誤検知は、すべてページの中身の塗り（4,391 件）と濃い画像（2 件）で、注釈は 0 件だった。下の値の境目（`spread`）を上げても、誤検知と本当の漏れ（0.257〜0.385）は分けられなかった。そこで、形と置き方で除く条件を足した（`rules/p6-text/filters.ts`）。

| 条件 | 層 | かける覆い | 主に除く型（実物の一覧の件数） |
|---|---|---|---|
| 見える範囲の外（`outside_view`）：ページの箱（CropBox ∩ MediaBox）と、切り抜き（`W`・部品の BBox）の外枠の箱の外の所は測らない・数えない | 両方 | すべて | ページの外・見開きの反対側（画像 1,438、文字 10） |
| 細い塗り（`too_small`）：箱の短い辺が `imageCoverMinSide` より短い | 画像 | ページの中身の塗りだけ | アウトライン化した字の点・細い部分 |
| くり返しの模様（`repeated`）：ほぼ同じ大きさで正方形に近い塗りが、1ページに `repeatMinCount` 個以上 | 画像 | ページの中身の塗りだけ | 写真の上の装飾の格子（1,103） |
| 形の詰まり具合（`not_solid`）：形の面積 ÷ 凸包の面積が `minSolidity` より小さい | 両方 | ページの中身の塗りだけ | アウトライン化した字・記号（画像 1,425）、字の輪郭の重ね（文字 155）、影の画像 |
| 上に同じ字（`same_text_on_top`）：覆われた字と同じ字を、覆いのあとに、ほぼ同じ所（小さい方の箱の 50% 以上が重なる）に描き直している | 文字 | すべて | 白抜きの字のうち同じ字のもの、縁取り・影の飾り文字、ずらして重ねた枠 |
| 白い覆いの上に字（`text_on_top`）：1.5.0 からの条件。数えた件数だけ `excluded` に出す | 画像 | 白っぽい覆い | 直し・凡例の下地 |

- **本当の漏れを残すことを、いちばん大事な条件にした。**
  - 注釈の覆いには、見える範囲の条件のほかは、かけない。実物の本当の漏れ（注釈の覆い 2 個）は、どちらも注釈だった。
  - 紙の画像の上の白い塗り（実物で本当に読めた 17 件。字の行の高さ 6〜10pt のふつうの四角、上に字なし）には、どの条件も当たらない見込み（推測。実物での確かめは、人が測り直す）。
  - くり返しの条件は、縦横の比が 0.5〜2 の塗りだけにかける。表の列を隠した横長の同じ大きさの四角は残す（テストで 20 個を確かめた）。
- 条件ごとに除いた数は、`explain: true` のときだけ `excluded` に出す（層と理由ごとの件数。値・字・場所は入れない）。
- 確かめたこと：テストの中で作った PDF（`tests/p6-false-positives.test.ts`、14 件）。合成 PDF の採点（`npm run eval`）は、1.5.0 と同じ 32/32・誤検知 0/21。
- 選ばなかった手がかり：下の画像が紙か写真か（本物の1件は図の凡例の上で、図の画像は写真側に寄るおそれがある）、濃い覆いの上に字があるか（黒塗りの上に札を貼る型を落とす）。

### 数えない条件（1.7.0 で足したもの）

1.6.0 を実物の公開 PDF 100 個で測り直したところ、「問題なし」とされた 87 個で、画像の層の報告は 4,393 → 345 件になった。本当に読めた白い塗り 17 件と、注釈の覆いの本当の漏れ 2 個は、すべて残った。ただし、反応した PDF は 24 → 17 個（画像の層）・15 → 9 個（文字の層）で、PDF の数ではまだ多い（2026-11-04、見つける段の2回目の一覧）。そこで、次を足した。

| 条件 | 層 | かける覆い | 主に除く型（1.6.0 の実物の PDF / 報告） |
|---|---|---|---|
| 縦横の四角だけ（`not_rect`）：形のある塗り（曲線・回した形・多角形）は、画像の層では数えない。1.6.0 の詰まり具合より強い | 画像 | ページの中身の塗りだけ | アウトライン化した字（5 / 21）、影の画像、形のある小さな部品、花びら・ロゴ・図形で描いた見出し文字 |
| まわりに溶け込む白だけ（`not_blending`）：白い塗りの外側 `ringWidth`（3pt）の帯で、下の画像の明るい点（明るさ 0.75 以上）が 6 割より少なければ数えない。帯に画像の点が 8 点より少なければ、測らない（数える） | 画像 | ページの中身の白い塗りだけ | 写真の上の白い札・吹き出し・ラベルの下地、写真の縁の飾り模様（1 / 48）、写真の白い帯 |
| 確からしさ（`confidence`）：濃い塗りで、下の明るい点（明るさ 0.7 以上）が 4 割より少ない（紙らしくない）ものは、落とさずに `check`（確かめてください）にする | 画像 | ページの中身の濃い塗りだけ | 写真の上の黒いラベル・ボタン・帯。写真の上の黒い目隠しも `check` になる（人の決定で、落とさない） |
| 字1つ分の形（`glyph_sized`）：覆った字が1つだけで、覆いの箱が字の箱を縦横 1.2 倍に広げた箱に収まる、形のある塗り | 文字 | ページの中身の塗りだけ | アウトライン化した同じ字（1 / 17） |
| 上に同じ字（`same_text_on_top`）の比べ方：字の中身が読めない字（字の形を読めないフォント）は、フォントと字の番号で比べる | 文字 | すべて | 白抜きの字（7 / 48）・飾り文字のうち、下の字の中身が空のもの（推測） |

- 白い覆いで隠すのは、まわりが白い紙で、覆いが見えなくなるから、と考えた。写真の上の白い札・枠・タイルは、まわりが写真なので目立つ。
- 注釈の覆いには、どの条件もかけない。`confidence` は、注釈・黒い画像・紙らしい画像の上の塗りでは `high`。
- 合成 PDF の画像の層の報告 8 件は、すべて `high`。まわりの明るい点の割合 0.929〜1、下の紙らしさ 0.838〜0.905（2026-11-04、`explain` で測った）。
- `explain: true` のとき、1件ごとに測った値（`metrics`）を返す。画像の層は `ringLight`（まわりの明るい点の割合。測れなければ null）・`underLight`（下の紙らしさ）。文字の層は、覆われた字の高さの範囲・覆いの短い辺・描き方・覆いの上の字のあり方（`textOnTop`）。あわせて `diagnostics` に、文字の層の報告を `textOnTop` ごとに数えた数を返す。どれも数だけで、字・場所は入れない。
- **ルールでは分けられないと考える型**（出し続ける）
  - 図の注記を白で消して差し替えた所：やったことは本当の漏れと同じ。違いは「隠す必要があったか」だけ。
  - 地図・図面・イラストの白っぽい地の上の白い四角：白い紙の上の塗りと区別できない。
  - 番号札・見出しの差し替え（下に古い版の字が本当に残っている）、表の見出しの濃い網掛け（字が実際に見えない）。
  - 傾けた見本書類の絵の罫・枠：いまは手がかりが足りない。`metrics` の字の高さ・覆いの太さを測ってから決める。

### 文字の層：覆いの上のあり方（1.8.0）

1.7.0 を実物の公開 PDF 100 個で測り直したところ、「問題なし」とされた 87 個で、文字の層は 9 個・135 件のまま減らなかった（2026-11-04、見つける段の3回目の一覧）。
- 白抜きの字 48 件：`textOnTop` は different 24・unknown_hidden 13・none 11。
- 傾けた見本書類の絵 63 件：字の高さ 0.449〜1.249pt。

文字の層の報告ごとに、覆いの上のあり方（`rules/p6-text/text-top.ts`）を決める。

| 覆いの上のあり方 | 扱い |
|---|---|
| 何もない（`none`） | `high` |
| 札の言葉の字（`label`）：上の字から記号・括弧・空白を除いた中に「不開示」「非開示」「非公開」「黒塗り」「マスキング」「墨消し」「秘匿」「伏せ字」「REDACTED」など（`LABEL_WORDS`）を含む | `high`（黒い四角の上に札を書いた本当の漏れを弱めない。2026-11-04、人の決定） |
| 下の字が、どれも上の字の中にある（`same_chars`。並び・場所は違う） | 数えない（`same_chars_on_top`）。下の字は、どれも上に見えている |
| 下と違う字（`different`）・下の字に中身の分からない字がある（`unknown_hidden`） | `check`（見出しの帯・番号札の形。下に別の字が残っていること自体は本当なので、落とさない） |
| 字はないが、濃くない色の、曲線を含む塗り（`shapes`）がある。アウトライン化した白抜きの字 | `check` |

- 覆われた字の箱の高さが、どれも `tinyGlyphHeightMax`（2pt）より小さいときも `check`（傾けた見本書類の絵の中の字の形。縮めた書類の絵の中の字も、取り出せれば本当の漏れと同じ形なので、落とさない）。
- 字を比べる前に、字の中身をそろえる（`normalizeGlyphText`）。NFKC で正規化（康熙部首の「⾏」とふつうの「行」、全角と半角）。印字できない字（制御・書式・私用領域・幅のない空白など）だけの字は、中身の分からない字とする。
- 「白抜きの字」で上に違う字（different）が多い理由は、次の3つとみた（推測。実物では確かめていない）：同じ字でも Unicode が違う（上の NFKC で直す）、下の字が印字できない字（上で直す）、1バイトのフォントで ToUnicode がなく、字の番号を ASCII として読んでいる（ルールでは本当の字が分からない）。
- 合成 PDF の文字の層の漏れ 24 件は、どれも `none`・`high`（字の高さ 11〜14pt。2026-11-04、`explain` で測った）。
- `explain` の `metrics` に、`hiddenRotated`（覆われた字に回した字があるか）・`coverLuminance`（覆いの明るさ）・`hiddenNonPrintable`（印字できない字の数）を足した。`diagnostics` に、`text:hidden_nonprintable`（印字できない字のある報告の数）・`text:check_tiny`（小さい字だけで `check` にした報告の数）を足した。
- **ルールでは分けられないと考える型**（`high` のまま出し続ける）：表の見出しの濃い網掛け、アウトライン化した同じ字の残り、図形の外枠の箱、上に何もない飾り文字。

### 大きな画像と、色のある地（1.9.0）

1.8.0 を、調整に使っていない実物の公開 PDF 100 個にかけたところ、本当の漏れ（スキャンした紙の上に白い四角の注釈を置いたもの）2 個を、0 個しか捕まえなかった（2026-11-04、見つける段の「見ていない 100 件の一覧」）。ページの画像（600dpi の A4 のカラー JPEG）が、解く大きさの上限（64MB）を超えていたため。また、「問題なし」の 78 個のうち 13 個で、地図・航空写真の上の凡例・区画の色塗り・注記の下地・駅名の札が high で出た。

**大きな画像**
- **要る画像だけを解く。** 濃い画像（字の上に貼った黒い画像）かを確かめるのは、先に描いた字か画像に重なる画像だけにした。ほかの画像は、画像の層で覆いの下になったときに初めて解く（`createPixelSource`）。覆いのないスキャンのページでは、画像を解かない。
  - PDF.js を渡したとき、一度も解かなかった画像（覆いの候補にかかわらない画像）は、`uncheckedImages` にも入れない（調べる必要がないため）。渡さないときは、今までどおり `unsupported_filter` として入れる。
  - pdf-lib で解ける画像は、解かずに読めそうかだけを確かめ（`probeImagePixels`）、読めない色・大きすぎるものを `uncheckedImages` に入れる。解いてみて壊れていたものは、解いたときに足す。
- **上限は画素の数（`maxImagePixels`、7,200 万画素）。** 600dpi の A3（約 7,000 万画素）まで入る。pdf-lib で解く画像のバイト数の上限（`maxImageBytes`）は、256MB にした。
- **解いたら、明るさと色の濃さだけの小さな形に写し、PDF.js の画素を手放す**（`rules/shared/pdfjs-images.ts` の `compactReader`）。1,600 万点を超える画像は、縦横を同じ間隔で間引く（600dpi の A4 は、縦横 2 つおき）。
- **JPEG は、覆いの範囲だけを解く・縮めて解くことはできない。** JPEG は、符号を頭から順に読まないと途中の場所に行けない（区切りの目印 restart marker がない限り）。段階的な JPEG は、すべての段を読まないと、どの画素も決まらない。PDF.js の公開の使い方にも、範囲や縮める大きさを指定する道がない。自分で JPEG を解く部品を書くのは、今回はしない。
- **注釈の覆いの下の画像を解けなかったときは、「確かめてください」で報告する**（`reason: "under_unreadable"`、`spread: null`、`confidence: "check"`）。大きすぎる・読めない色・読めない圧縮のどれでも。実物で、注釈の覆いの誤検知は、これまで 0 件だった。ページの中身の塗りの下の画像を解けないときは、今までどおり報告しない（`uncheckedImages` に残る）。

測った値（合成 PDF。`.tmp` の試し。600dpi のカラー JPEG、上に白い四角の注釈。2026-11-04）：

| PDF | Node 24（時間 / メモリの山 maxRSS） | Chrome 156 の Worker（時間 / プロセスのメモリの山） |
|---|---|---|
| A4（3,480 万画素）1 ページ、注釈なし | 12ms / 114MB（解かない） | 9ms / 124MB |
| A4 1 ページ、注釈あり | 527ms / 328MB（+214MB） | 498ms / 350MB |
| A4 10 ページ、注釈なし | 59ms / 155MB | 47ms / 167MB |
| A4 10 ページ、注釈あり | 4.7 秒 / 406MB（溜まらない） | 5.7 秒 / 732MB |
| A4 30 ページ（PDF 64MB）、注釈あり | — | 15.8 秒 / 821MB |
| A3（6,960 万画素）1 ページ、注釈あり | 843ms / 531MB（+417MB） | 913ms / 535MB |

- Node は、PDF.js が JPEG を解くとき、1画素あたり約 6 バイトを一度に使う（A4 で +214MB、A3 で +417MB）。
- Chrome では、ページごとに手放したメモリがすぐには戻らず、10 ページで 732MB、30 ページで 821MB になった（増え方はゆるやかになる）。画面の上限（200MB の PDF）でどこまで増えるかは、まだ測っていない。
- 時間は 1 ページ約 0.5 秒（注釈のあるページだけ）。検査の時間の上限（60 秒）では、注釈のある 600dpi のページが約 110 ページを超えると、検査が止まる。

**色のある地（地図・航空写真）**
- 覆いの下とまわりの帯の画素のうち、色のある点（色の濃さ＝RGB の最大と最小の差が 0.2 以上）が 2 割以上なら、`check`。ページの中身の塗りと、黒い画像の覆いにかける。注釈にはかけない。
- なぜ分かれるか：書類の紙は、白か薄い灰色の地に黒い字で、色がほとんどない（カラーで読み取った紙の黄ばみも、色の濃さは小さい）。地図・航空写真は、地そのものに色がある（緑の地・青い川・色分けした区画）。本当の漏れは、どれもスキャンした紙・公文書・図の上だった。
- 合成 PDF の画像の層の漏れ 8 件は、色のある点が 0（灰色の画像）で、すべて `high`。
- `explain` の `metrics.colored` に、色のある点の割合を返す。
- 赤い印鑑のすぐ上の黒塗り、色つきの用紙のスキャンの上の黒塗りは、`check` になることがある（落とさない）。

**字1つ分の黒い画像（文字の層）**
- 覆った字が1つで、黒い画像の箱が字の箱の 1.2 倍に収まるもの（字の形の型抜きの画像を、同じ字の上に重ねたもの）は `check`（数えなくはしない。2026-11-04、人の決定）。`diagnostics` の `text:check_glyph_image` に数を返す。

### 白い覆いの上に、あとから描いたもの（1.10.0）

片付けたあとの読み直しで、漏れでないのに出る1件があった（片付けの担当が、実物の本当の漏れ 5 個を片付けて読み直したうちの1件。2026-11-04）。形は、CCITT の白黒スキャンの上に白い不透明な注釈（札）を置き、その札の中に、あとから濃い注釈（Ink など）を書いたもの。濃い線の一部は、札からはみ出している。片付けは、札の下の画素を白く、はみ出した濃い線の下の画素を濃く塗る。その結果、白い札の下の画素に濃い線の形が残り、1.9.0 は「白い注釈の下に何かある」（high）と出していた。元の中身は消えていて、見えているのは上に描いた濃い注釈と同じ形。

- **白い覆いを測るときだけ、その覆いのあとに不透明に描いたものの形の下にある点を数えない。** その点では上に描いたものが見えていて、下にある中身は、上のもの自身の問題になる。濃い覆いの測り方は変えない。
  - 対象は、塗りと線（色・太さを問わない。注釈もページの中身も）と、あとから描いた濃い覆い（画像の層でそれ自身が測られるもの。黒い画像・見た目のない四角の注釈も含む）。
  - 太さ 1pt 未満の線は覆いにならない（`minStrokeWidth`）が、ここには入れる。Ink の線は細いことが多いため。
  - 塗りのうち、自分自身（と、同じ塗りの命令で描いた覆い）の形は入れない。
- **縁のゆとり。** 線は、両端を太さの半分だけ延ばす（端の丸み・角を含めるため）。どの形も、下の画像の画素1つ分だけ広げて見る（片付けで塗った画素の丸めの分）。
  - 合成 PDF（144dpi）で、片付けが線の形を外へ1画素ふくらませて塗った形は、ゆとりなしでは spread 0.133 で出て、ゆとりありでは出なかった。2画素ふくらませた形は、ゆとりがあっても出る（spread 0.131。境目 0.05 は低く、縁に少し濃い画素が残るだけで超える）。
- **上に描いたものの形を集める数には上限がある**（`maxOverPaintPerPage`、1ページ 2 万【仮の値】）。超えたページは、数えない点を作らず、1.9.0 までの測り方に戻す（人の決定）。`diagnostics` の `image:over_paint_overflow` に、戻したページの数を返す。
- **数えなかったため測れる点が足りなくなった（16 点未満）白い覆い**（人の決定）：
  - 数えなかった点の大半（半分より多く）が、あとから描いた濃い覆いの下にあるとき：その濃い覆いで見つかるので、報告を省く（`excluded` の `image:under_later_cover`）。
  - それ以外（白い札の上に細い線を密に引いた形など）：`check` で出す（`reason: "under_later_paint"`、`spread: null`）。白い札の上に線を引くだけで、下の漏れが消えないようにするため。ただし、数えなかった点も含めて下が一様（ばらつきが境目より小さい）なら、何も隠していないので出さない。ページの中身の白い塗りは、まわりの帯の条件（`not_blending`）もかける。
- `explain` の `metrics.laterPaintPoints` に数えなかった点の数を、`diagnostics` の `image:with_later_paint` に、数えなかった点のある報告の数を返す。
- 合成 PDF の画像の層の漏れ 8 件は、上に何も描いていないので、値は変わらない（すべて `high`）。

### 覆いの下の字は、色によらず P6（1.11.0）

見ないで作るテスト集（`eval:blind`）で、白い四角・灰色の四角・白い四角の注釈・あとから重ねた写真の下の字を、P6 が出さず P7（`covered_light`・`covered_image`）が出していた（T27・T31・T32・T34・T37）。人の決定（2026-11-05）：**覆いの下の字は、色によらず P6**。

- **濃くない覆い（`tone: "opaque"`）を、字の層でだけ使う。** 濃い覆い（明るさ 0.35 以下）でない、次のもの：
  - 塗り：不透明（0.9 以上）・ふつうの重ね方（`/BM` が Normal か Compatible）・やわらかい型抜き（ExtGState の `/SMask`）なし。形の詰まり具合などの数えない条件は、濃い覆いと同じ。
  - 画像：型抜き（ImageMask・`/Mask`・`/SMask`）がなく、不透明・ふつうの重ね方で置いたもの。**色や、解けるかどうか（JPEG など）にかかわらない。** PDF.js で解いて濃いと分かった画像は、これまでどおり濃い覆い。
  - 注釈：見た目の中の塗りと画像（上と同じ）、見た目のない四角・多角形の注釈の濃くない `/IC`。
- 描き方 3・7（塗りも輪郭もしない）の字は、濃くない覆いの下では数えない。スキャン画像と文字認識の層は、どちらの順番で描いても出さない。濃い覆いの下では、これまでどおり数える。
- 画像の層は、これまでどおり濃い覆いと白っぽい覆いだけを使う（濃くない覆いは使わない）。
- 報告には `coverTone: "opaque"` を付ける（濃い覆いには付けない）。画面では「上に重ねた図形（画像・注釈）の下に、字が残っています」と出す【文言は仮】。
- 画面（`src/inspect/rules.ts`）では、P7 の `covered_light`・`covered_image` を出さない（同じ字を2つの型で出さないため）。P7 の検出ルールの報告には残す（P7 の正解データと検証器は、これらを P7 として数える）。
- **黒い蛍光ペンの注釈**（見た目なし、`/Highlight` の `/C` が濃い）を覆いにする（T33）。蛍光ペンは乗算で重ねて表示されるので、濃くない色の蛍光ペンは覆いにしない。
- **縦書き**（CMap の名前が `-V` で終わる Type0）の字の箱（T38）：字は縦の原点から、横は幅の半分ずつ左右に、縦は原点から下へ広がる（PDF 1.7 §9.7.4.3。`DW2` を読む。字ごとの `W2` は読まない）。送りは下へ進む。`rules/shared/fonts.ts` の `vertical`。

これまでのテストのうち、5 件は「濃くない覆いは見つけない」と決めていたので、新しい決まりに合わせて直した（`tests/p6-text-rule.test.ts` の薄い色の四角、`tests/p6-text-cover-kinds.test.ts` の写真のような画像・解けない JPEG・薄い色の四角の注釈、`tests/p6-image-layer.test.ts` の黒い JPEG）。

### 埋め込み画像・模様の覆い（1.12.0）

- **埋め込みの画像**（ページの中身に直接書いた画像）を、外の画像（XObject）と同じに扱う。幅・高さ・色・中身から濃さを測り、濃ければ濃い覆い、型抜きがなく不透明なら濃くない覆い。読み手（`rules/shared/content-lexer.ts`）が画像のバイト列も返し、`rules/shared/inline-image.ts` で画像の流れにする（短い名前 `W`・`H`・`CS`・`BPC`・`F` などを長い名前に直す）。
- **模様**（`rules/shared/patterns.ts`）：
  - タイルの模様：1つのタイルの四角の塗りが、タイルの送りを 9 割以上埋めるときだけ覆いにする（細い斜線・網の模様は、下の字が透けるので覆いにしない）。明るさは塗りの色の明るい方。色のない模様（PaintType 2）は `scn` の色。四角でない道・画像・部品のあるタイルは、読み切らないので覆いにしない。
  - シェーディングの模様・`sh`：すき間なく塗る。明るさは関数の両端の色（`FunctionType 2` の `C0`・`C1`）の明るい方。分からなければ濃くない覆い。`sh` は、いまの切り抜きの中（`/BBox` があれば、その中）を塗ったものとする。切り抜きも範囲もない `sh` は、覆いの形が決まらないので見ない。
  - 字を描く命令のあるタイルの模様で塗ったときは、塗った所にタイルを並べ（1回の塗りで 64 枚まで）、タイルの中の字も字として持つ。あとから覆いを重ねれば、ほかの字と同じに見つける。
- 合成 PDF のすべて（401 個）で、P6・P7 の報告は 1.11.0 と同じ（この型の PDF はまだない）。採点用の合成 PDF の案は `proposals/a-p6-inline-pattern/`。

### 図形の層：白い四角の注釈の下の、パスで描いた字（1.13.0）

見つける段の3回目で、パスで描いた字（アウトライン化した字。曲線のない、直線だけの道。塗りと線の両方）の上に、白い不透明な四角の注釈（/Square）を重ねただけの型を見逃していた（2つの文書）。字ではないので文字の層に入らず、画像でもないので画像の層にも入らなかった。注釈を外すと、下の字が見える。

- **覆い**：白い四角の注釈（`whiteSquareAnnots`）。/Subtype が Square、中の色（/IC）の明るさが `lightLuminanceMin`（0.9）以上、隠していない（/F の Hidden・NoView でない）、不透明（/CA が 0.9 以上）。見た目（/AP）の有無は問わない。
- **数えるもの**：ページの中身（部品の中も。注釈の見た目は除く）で、白くない色で不透明に描いた道（塗り・線の命令1つを1本とする）。道の外枠の箱の半分以上が注釈の箱に入れば「下にある」とする。面積のない縦横の線は、真ん中で見る。道そのものは持たず、注釈ごとに道の数と線分の数だけを数える（図形の多いページで、メモリを使わないため。CLAUDE.md §5）。
- **出す線**：道が `vectorMinPaths`（15）本以上、または線分が `vectorMinSegments`（500）以上（2026-11-05、人の決定）。`layer: "vector"`、いつも `check`（確かめてください）。道が字か、罫線・図かは、ルールでは分けきれないため。
- **出さないもの**：道が少ないもの（`vector:few_paths`。罫線1本だけの白い四角など）。同じ注釈の下の字を、文字の層ですでに出したもの（`vector:text_layer_found`。同じ所を2度出さない）。ページの中身の白い塗りは、図形の層では見ない（アウトライン化した字の上の白い塗りは、デザインでよく使う形のため。1.6.0 の実物の測り方）。
- 見つける段の数（注釈 12 個。注釈の下の道の数で 380・373・83・27・126・334・31・26・17・9・8・2）では、道の数だけで見ると 9 個を出し、9・8・2 本の 3 個は見逃す（この 3 個の線分の数は聞いていないので、線分の線で出るかは分からない）。下に道が1本しかない白い四角の 4 個は出さない。数は見つける段の回が測ったもので、このブランチでは実物を読んでいない。

## 画面の深刻度（2026-11-05）

実物の公開 PDF（依頼元のセッションが手元で測ったもの。漏れなしと判定された 245 件のうち 44 件で P6 が「高」）で、注釈の四角や塗りの誤検知が「高」で多く出た。検出ルールの報告は変えず、画面（`src/inspect/rules.ts` の `p6Item`）で深刻度を分ける。

- 「高」：覆いの下に拾えるもの（字、または取り出せる画像の中身）があると言い切れるとき（`confidence: "high"` の文字の層・画像の層）。
- 「高」（例外）：読み解けない画像の上に濃い四角を重ねたもの（画像の層の `reason: "under_unreadable"`・`tone: "dark"`）。スキャン画像の上の黒塗りの型で、取り出せる危険が大きいため（人の決定。デモの議事録の3件もこの型）。
- 「中」：図形の層と、そのほかの「確かめてください」（`confidence: "check"`）。
- 合成した型：`tests/p6-severity.test.ts`。
- 見ないで作るテスト集の隠しの PDF で、P6 が「高」から「中」になったのは T37（隠したい字の上に白い四角、その上に別の見える字。言い切れない「確かめてください」）の1件。

## できないこと（限界）

- 画像の層（1.5.0）
  - **ブラウザの検査器では、まだ使っていない。** 検査の Worker で PDF.js を読み込み、`imageDecoder` を渡す作りは、画面の側（src/）の仕事。渡さなければ、JPEG などは今までどおり `uncheckedImages` に入る。
  - **CCITT・JBIG2 をブラウザで解くには、`jbig2_nowasm_fallback.js` も配る必要がある。** このファイルには、Emscripten の `fetch` のコードが1か所ある（`.wasm` を取り寄せる道。`useWasm: false` では呼ばれない）。いまの `scripts/check-dist.mjs` は、PDF.js の2つのファイルだけを例外にしているので、このファイルを配ると止まる。例外を広げるかは、人が決める（docs/no-network.md）。
  - 判定は画素のばらつきだけで見る。下に写っているのが字か絵か（写真・地図・飾り）は見分けない。写真の上に置いた白い札（上に字がないもの）、画像の上の黒いデザイン帯は、漏れとして数える（合成 PDF にこの型の「漏れでないもの」はまだない）。
  - 白っぽい覆いの「上に字がある」は、字の箱の真ん中で見る。上の字が画像（スキャン）として描かれているときは、字があるとはみなさない。
  - 線（太い線）の覆いは、画像の層では見ない。太いペンで画像の上を塗った型は見逃す。
  - 見た目のない FreeText・Ink の注釈は、画像の層の覆いにしない（色の決まりがはっきりしないため）。見た目のあるものは読む。
  - 標準偏差は、間引いた点（最大 64×64）で測る。細い字の一部だけが覆いの下にあると、値がずれることがある。
  - ページの命令の中に直接書いた画像（`BI … ID … EI`）は、画像の層の下地としても見ない。
- 図形の層（1.13.0）：白い四角の注釈（Square）だけを見る。中の色（/IC）のない注釈（見た目だけが白いもの）、白い FreeText・Polygon・Stamp・Widget の注釈、白くない色の不透明な注釈は見ない。道の数が線より少ない覆い（字が数個だけ）は見逃す。切り抜きの外の道も、下にあるものとして数える。下の道が字か、表の罫・図かは見分けない（いつも check）。
- 曲線は 8 本の直線で近似する。偶奇の決まりの穴は、外枠の箱の入れ子で見る目安で、形が交差するものは正しく測れないことがある。
- 太い線の継ぎ目（角）の形（線の端・角の丸め）は見ない。線の太さの帯だけで測る。
- 1ページの命令が 300 万、または先に描いた字に重なる濃い塗りが 10 万を超えるページは、調べずに「省いた」と返す（`too_many_operations`・`too_many_covers`）。省いたページの漏れは、採点では見逃しとして数える（PR #12 の返事）。
- `node eval/measure-p6-text.ts` の画像の一覧は、1.3.0 から、先に描いた字に重なる画像だけになった（字に重ならない画像は、読むときに捨てるため）。上の表の画像の値は、1.1.0 で測ったもの。
- 切り抜き（クリップ）は、1.6.0 から外枠の箱で近似して見る。形のある切り抜き（円で切り抜いた写真など）は、外枠の箱の中ならどこでも見えるとみなす。字を描くことで切り抜く型（`Tr` 4〜7）は見ない。注釈の見た目の BBox も、切り抜きとしては見ない。
- 1.9.0 で、次の本当の漏れは「確かめてください」（`check`）になる（落とさない）：色のある地（赤い印鑑のそば・色つきの用紙のスキャン・地図）の上の、ページの中身の塗りや黒い画像の覆い。字1つだけを黒い画像で隠した黒塗り。注釈の覆いの下の画像を解けなかったもの。
- 1.10.0 で、白い覆いの上にあとから描いた不透明なもの（細い線も）の下にある点は数えない。濃い線の下だけに残った中身は、誰も測らない（線は、もともと画像の層で測らないため）。片付けが線の形を外へ2画素以上ふくらませて塗ると、片付けたあとでも白い覆いが出ることがある。上に描いたものの形が1ページ 2 万を超えるページは、1.9.0 までの測り方に戻す。
- 1.9.0 でも、7,200 万画素を超える画像（1200dpi の A4 など）の上の、ページの中身の塗りの覆いは調べない（`uncheckedImages` の `too_large`）。注釈の覆いなら `check` で報告する。
- 1.8.0 で、次の本当の漏れは「確かめてください」（`check`）になる（落とさない）：黒い四角の上に、札の言葉でない字や、字の形の塗り（アウトライン化した札）を描いた黒塗り、2pt より小さい字の上の黒塗り。札の言葉の一覧にない言い方（「個人情報のため省略」など）の札も `check` になる。次の型は数えない：上の字に、下の字がすべて含まれるもの。
- 1.7.0 の条件で、次の本当の漏れは見逃す：画像の上の、回した四角・角の丸い四角など形のある塗りの覆い（注釈を除く）、写真など明るくない地の上の白い塗りの覆い（注釈を除く）、字1つだけを形のある塗りで隠した黒塗り。字の詰まった濃い行（行の中の黒い点が 4 割を超えるなど）の中に置いた細い白い塗りも、まわりの帯が暗くなり、見逃すことがある。
- 1.6.0 の数えない条件で、次の本当の漏れは見逃す：アウトライン化した字の形のまま黒く塗った覆い、凸でない形（L の形など）で塗った黒塗り、画像の上の 4pt より細い塗りの覆い（注釈を除く）、1ページに同じ大きさの正方形に近い塗りが 20 個以上ある黒塗り（画像の層）、上に同じ字を描き直した覆い（下の字は見えているので、隠したことにならない）。
- 文字の層の「白抜きの字」の型のうち、下に別の字がある（古いページ番号・古い見出し）ものは、いまも数える。傾けて置いた見本書類の絵の罫・枠が、絵の中の小さな字に重なる型は、まだ見分けない。
- 字の形を読めないフォントの字は、中身のない字として数える（`rules/shared/fonts.ts`）。報告の字の数が、見た目の字の数と合わないことがある。漏れを落とさないため、1.6.0 では変えていない。
- 模様（Pattern）・特色（Separation・DeviceN）・Lab の色は、濃いかどうかを見分けない（覆いとして数えない）。画像でも同じ。
- JPEG などの解けない圧縮の画像は、濃いかどうかを見分けない（`uncheckedImages` に入れる）。黒い JPEG を字の上に貼った型は見逃す。
- ページの命令の中に直接書いた画像（`BI … ID … EI`）は、覆いとして見ない。
- 画像の濃い画素は、縦横を間引いて最大 256×256 点で数える。細い線の画像では割合がずれることがある。
- 画像の大きさの上限は、画素の数から計算した大きさで見る。圧縮を解いた結果が上限よりずっと大きくなる細工（解凍爆弾）は、このルールの中では止めない。画面では Worker のメモリと時間の上限で止める。
- 注釈の見た目の中の字も、字として集める（あとの注釈に覆われれば数える）。
- 2つ以上の覆いで半分ずつ隠れた字は、どの覆いにも「半分以上」でなければ数えない。
- 縦書きの字は、横書きと同じ箱で近似している。
- 決まった字の対応表のうち、90ms-RKSJ-H/V・90msp-RKSJ-H/V・RKSJ-H/V・UniJIS-UCS2-H/V・UniJIS-UCS2-HW-H/V・UniJIS-UTF16-H/V（12 個）は、Shift-JIS・Unicode として区切って字を読み、幅は `/W` の CID で引く（2026-11-06 から。`rules/shared/predefined-cmaps.ts`）。CID は、字のある全部のコードで Adobe の対応表と同じになることを確かめた（PDF.js と比べて作る例外の表で直す）。字の中身はコードの決まりのまま読むので、PDF.js と一部の記号・異体字で違う（例：RKSJ の 0x5C は「\」、PDF.js は「¥」）。
- それ以外の CMap（83pv・90pv・Add・Ext の RKSJ、UTF8・UTF32 の Unicode の表、ほかの言語の表など）を使うフォントは、いまも 2 バイトずつ区切り、幅は `/W` の CID ではなくコードで引く。字の中身は分からず、幅がずれることがある。
- 字の幅と高さは、P7 と同じ共通の読み方（`rules/shared/fonts.ts`。1.3.1 から）で引く。
  - 幅：`/Widths` → 標準の書体（ラテン文字の12書体と、Arial などの別名）なら pdf-lib が持つ寸法（WinAnsi の範囲の字だけ）→ `/MissingWidth` → 0.5em。
  - 高さ：`/Ascent`・`/Descent` → `/FontBBox` → 標準の書体の寸法 → 0.8em・−0.2em。
  - 1.3.0 までとの違い：`/Widths` はあるが表の外の字や、`/FontDescriptor` のない標準の書体の高さ（0.8・−0.2 → Helvetica なら 0.718・−0.207）。合成 PDF の採点の数字と、報告の箱・字数は、どれも変わらなかった（2026-11-03）。
- 暗号化された PDF（読み込みは共通の入口 `rules/shared/load.ts`。P1 の検出ルールと同じ）
  - **パスワードなしで開ける暗号化**（利用者のパスワードが空。印刷・編集の禁止だけをかけたもの）は、復号して中まで調べる（1.2.0 から）。対応する形：標準のセキュリティハンドラの RC4（R2・R3）、AES-128（R4）、AES-256（R5・R6）。報告の `decrypted` に、どの暗号化だったかを入れる。
  - **パスワードが要る PDF**、標準でないセキュリティハンドラ（公開鍵など）、鍵の材料（`/O`・`/U`）が壊れたものは、`encrypted` で止め、中身は調べない。検査器はパスワードを聞かない。
  - 確かめた形（2026-11-03、テストの中で作った合成 PDF。PDF.js でも開けることを確かめた）：4 方式 × 表の xref・オブジェクトストリームごと × パスワードあり・なし の 16 種と、暗号化のしるしだけのもの。
  - 1.1.0 までは、pdf-lib の EncryptedPDFError を instanceof で見分けられず、「読めない」と返していた。1.1.1 は、パスワードなしの暗号化も含めて `encrypted` で止めていた。
  - 復号は、検査のために pdf-lib の中だけで行う。利用者のファイルは書き換えない。復号のあと、暗号化のない PDF として書き出して読み直すので、暗号化された PDF では読み込みに少し時間がかかる。
  - 復号に失敗した文字列・ストリームは、そのまま（読めない中身）にして数え、`decrypted.failedObjects` に出す。
  - 埋め込みファイルだけの暗号化（`/EFF`）、文字列とストリームで違う暗号の組み合わせ（`/StrF` と `/StmF` が違う）は、合成 PDF でまだ試していない。
- 時間の上限はこのルールの中にはない。画面では Worker の時間の上限（src/inspect/limits.ts）で止める。
