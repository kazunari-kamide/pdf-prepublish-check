# 検出ルール：P6（見せかけの黒塗り）の文字の層

PDF を入れると、「字のあとに、その字を覆う濃いもの（塗り・画像・注釈）を重ねている所」（黒い四角の下に、選べる・コピーできる字が残っている所）を返す。docs/prd.md §3。

```ts
import { detectP6Text } from "./rules/p6-text/index.ts";
const report = await detectP6Text(bytes);              // 覆われた字の数だけを返す
const report2 = await detectP6Text(bytes, { includeText: true }); // 字そのものも返す（調べるときだけ。記録やログには使わない）
```

## 見るもの・見ないもの（1.1.0）

| 型（層 / 覆っているもの） | 1.0.0 | 1.1.0 |
|---|---|---|
| text/fill（字の上に濃い塗り・濃い太い線） | 見る | 見る |
| text/image（字の上に濃い画像） | 見ない | **見る** |
| text/annotation（字の上に濃い注釈・未適用の墨消し注釈） | 見ない | **見る** |
| image/*（スキャン画像の画素が残っている型） | 見ない | 見ない（2026-11-03、人の決定。D60） |

見ない型（image/*）は、合格基準の分母には入っている（rubric/p6.md §1）。そのため、この版も全体の検出率では不合格になる。これは意図したもの。

## 考え方

ページは描く命令の並びで、あとに描いたものが上に重なる。命令を順に読みながら（`lexer.ts`・`page.ts`）、次の2つだけを拾う。図形を全部組み立てることはしない（CLAUDE.md §5）。

1. **覆い**（描いた順番つき）
   - 濃い色で塗った、四角に近い図形（外枠の箱の 9 割以上を埋めるもの）。濃い色の、縦か横の直線（線の太さの分を箱にする）。
   - **濃い画像**（1.1.0）：画像の画素を読み、濃い画素（明るさが「濃い」の上限以下）が 97% 以上なら、画像を置いた箱を覆いとする（`images.ts`）。黒で塗る型抜き（ImageMask）、色の表（Indexed）、PNG・TIFF の予測、やわらかい型抜き（SMask。透けている画素は濃いと数えない）も見る。
   - **注釈**（1.1.0）：注釈は、ページの中身のあとに重ねて描かれる。そのため、ページのどの字よりもあとの覆いとして扱う（`annotations.ts`）。
     - 見た目（`/AP` の `/N`）があれば、その命令の列を同じように読み、濃い塗り・濃い画像を覆いとする。見た目の座標は、PDF 1.7 §12.5.5 のとおり `/BBox`・`/Matrix` から注釈の箱（`/Rect`）に移す。
     - 見た目のない四角の注釈（`/Square`）は、中の色（`/IC`）が濃ければ、注釈の箱を覆いとする。
     - 未適用の墨消しの注釈（`/Redact`）は、色にかかわらず覆いとする（`/QuadPoints` があればその範囲、なければ `/Rect`）。黒塗りのつもりの所で、まだ下の字が残っているため。
     - 隠した注釈（`/F` の Hidden・NoView）と、半透明（`/CA` が下限より小さい）の注釈は、覆いにしない（墨消しの注釈は除く）。
2. **字**：1字ごとの箱。フォントの幅（`/W`・`/Widths`）と高さ（`/Ascent`・`/Descent`）、字の行列（`Tm`・`Td` など）とページの行列（`cm`）から出す。描いた順番つき。見えない字（描き方 3）も入れる。取り出せることに変わりはないため。

字の箱の半分以上が、その字より**あとに描いた**覆い1つに隠れていれば、「覆われた字」とする。覆い1つごとに1件にまとめ、覆いの箱と、覆っているものの種類（`fill`・`image`・`annotation`）を返す。字が覆いの**あと**なら上に見えているので数えない（黒い帯の上の白い字など）。

- 部品（Form XObject）の中も、行列（`/Matrix`）をかけて追う。入れ子は 12 段まで。同じ部品を自分の中で呼ぶものは追わない。
- 色は、灰色・RGB・CMYK と、成分の数が分かる ICCBased・CalGray・CalRGB を見る。明るさは 0.299R + 0.587G + 0.114B。CMYK は (1−C)(1−K) などで RGB に直してから。
- 半透明（`/ca`・`/CA`）は、ExtGState（`gs`）から読む。画像の不透明さは `/ca` を使う。
- 解けない画像（JPEG・JPEG 2000・JBIG2・CCITT など、pdf-lib が解けない圧縮）は、覆いとしては数えず、報告の `uncheckedImages` に「調べられなかった画像」として入れる。「問題なし」とはしない。

## 判定の値と、合成 PDF で測った値

`node eval/measure-p6-text.ts` で、判定をゆるめて「先に描いた字に重なる塗り」と「すべての画像」を集め、正解データと照らして測った。

| 値（`settings.ts`） | 決めた値 | 合成 PDF で測った値 |
|---|---|---|
| 塗りを「濃い」とみなす明るさの上限 | 0.35 | 漏れに重なる塗り・線・墨消しの注釈：0.000〜0.102（15 件）。字に重なる薄い色のマーカー（漏れでない）：0.870・0.886（2026-11-03） |
| 字が「覆われた」とみなす割合 | 0.5 | 漏れの覆い：1.000（14 件）。ほかに、四角の注釈の縁の線が 0.083（同じ注釈の中の塗りが 1.000 なので、注釈としては見つける）。字に重なる濃い塗りで漏れでないもの（下線・ラベルの箱・正しい墨消しの横の字）：0.078〜0.125（4 件）（2026-11-03） |
| 画像を「覆い」とみなす、濃い画素の割合（1.1.0） | 0.97 | 黒い画像：1.000（2 個。うち字を覆うもの 1 個）。暗い写真（漏れでない。字は写真のあと）：0.938。スキャン画像：0.045〜0.080（7 個）（2026-11-03） |
| 塗りを「隠している」とみなす不透明さの下限 | 0.9 | 合成 PDF に半透明の塗りがないため、測っていない（テストで 0.3 を見逃すことだけ確かめた） |
| 塗りを「四角に近い」とみなす割合 | 0.9 | 合成 PDF に四角でない覆いがないため、測っていない（テストで円を見逃すことだけ確かめた） |
| 1ページの命令の数の上限 | 20 万 | 【仮の値】。重いページの合成 PDF がまだないため、測っていない |
| 解く画像の大きさの上限（1.1.0） | 64 MB | 【仮の値】。合成 PDF でいちばん大きい画像は約 0.8 MB（744×1053、灰色 8 ビット） |

- どの値も、合成 PDF の上では、漏れと漏れでないものの間に大きな開きがある。そのため、値を少し動かしても結果は変わらない。逆に言えば、合成 PDF だけでは値を細かく決められない。本物の PDF での件数を見て見直す。
- **画像の割合は開きが小さい**（黒い画像 1.000 と暗い写真 0.938）。暗い写真の上に字を描く向き（字が写真のあと）なら、この値にかかわらず見つけない。暗い写真を字の上に重ねた PDF があると誤検知になりうる。合成 PDF にその例はない。

## できないこと（限界）

- スキャン画像の画素が残っている型（image/*）は見ない（上の表）。
- 四角でない覆い（円・斜めの四角・曲線）は見ない。斜めの太い線も見ない。斜めに置いた画像も見ない。
- 切り抜き（クリップ）は見ない。覆いがクリップで実際には描かれていなくても、覆いとして数える。
- 模様（Pattern）・特色（Separation・DeviceN）・Lab の色は、濃いかどうかを見分けない（覆いとして数えない）。画像でも同じ。
- JPEG などの解けない圧縮の画像は、濃いかどうかを見分けない（`uncheckedImages` に入れる）。黒い JPEG を字の上に貼った型は見逃す。
- ページの命令の中に直接書いた画像（`BI … ID … EI`）は、覆いとして見ない。
- 画像の濃い画素は、縦横を間引いて最大 256×256 点で数える。細い線の画像では割合がずれることがある。
- 画像の大きさの上限は、画素の数から計算した大きさで見る。圧縮を解いた結果が上限よりずっと大きくなる細工（解凍爆弾）は、このルールの中では止めない。画面では Worker のメモリと時間の上限で止める。
- 注釈の見た目の中の字も、字として集める（あとの注釈に覆われれば数える）。
- 2つ以上の覆いで半分ずつ隠れた字は、どの覆いにも「半分以上」でなければ数えない。
- 縦書きの字は、横書きと同じ箱で近似している。
- Identity 以外の CMap（UniJIS-UCS2-H など）を使うフォントは、2バイトずつ区切り、幅は `/W` の CID ではなくコードで引く。字の幅がずれることがある。
- `/Widths` のない1バイトのフォント（標準の14書体など）は、字の幅を 0.5em とみなす。
- 暗号化された PDF（読み込みは共通の入口 `rules/shared/load.ts`。P1 の検出ルールと同じ）
  - **パスワードなしで開ける暗号化**（利用者のパスワードが空。印刷・編集の禁止だけをかけたもの）は、復号して中まで調べる（1.2.0 から）。対応する形：標準のセキュリティハンドラの RC4（R2・R3）、AES-128（R4）、AES-256（R5・R6）。報告の `decrypted` に、どの暗号化だったかを入れる。
  - **パスワードが要る PDF**、標準でないセキュリティハンドラ（公開鍵など）、鍵の材料（`/O`・`/U`）が壊れたものは、`encrypted` で止め、中身は調べない。検査器はパスワードを聞かない。
  - 確かめた形（2026-11-03、テストの中で作った合成 PDF。PDF.js でも開けることを確かめた）：4 方式 × 表の xref・オブジェクトストリームごと × パスワードあり・なし の 16 種と、暗号化のしるしだけのもの。
  - 1.1.0 までは、pdf-lib の EncryptedPDFError を instanceof で見分けられず、「読めない」と返していた。1.1.1 は、パスワードなしの暗号化も含めて `encrypted` で止めていた。
  - 復号は、検査のために pdf-lib の中だけで行う。利用者のファイルは書き換えない。復号のあと、暗号化のない PDF として書き出して読み直すので、暗号化された PDF では読み込みに少し時間がかかる。
  - 復号に失敗した文字列・ストリームは、そのまま（読めない中身）にして数え、`decrypted.failedObjects` に出す。
  - 埋め込みファイルだけの暗号化（`/EFF`）、文字列とストリームで違う暗号の組み合わせ（`/StrF` と `/StmF` が違う）は、合成 PDF でまだ試していない。
- 時間の上限はこのルールの中にはない。画面では Worker の時間の上限（src/inspect/limits.ts）で止める。
