# 検出ルール：P7（隠れたテキスト）

PDF を入れると、取り出せるのに、画面では見えない字を返す（rubric/p7.md §2）。1件 ＝ 1回の字を描く命令（`Tj`・`TJ`・`'`・`"`）の中で、同じ理由で続く見えない字のまとまり。**字そのものは返さない**（字数と箱だけ）。

```ts
import { detectP7Hidden } from "./rules/p7-hidden/index.ts";
const report = await detectP7Hidden(bytes);                         // 字数と箱だけ
const report2 = await detectP7Hidden(bytes, { includeText: true }); // 字そのものも返す（調べるときだけ。記録やログには使わない）
```

出力の形は `rules/p6-text` にそろえた（`rule`・`status`・`error`・`pages`・`findings`・`skippedPages`）。読み込みは共通の入口（`rules/shared/load.ts`）を使うので、パスワードなしで開ける暗号化 PDF は復号して調べる。

| 項目 | 中身 |
|---|---|
| `findings[].reason` | 見えない理由（下の表） |
| `findings[].rect` | 見えない字の箱。ページの既定の座標（ポイント、左下が原点、`/Rotate` はかけない） |
| `findings[].chars` | 見えない字の数（空白を除く） |
| `skippedPages` | 調べられなかったページ（命令が多すぎる・読めない）。「問題なし」ではない |
| `excluded` | 見えないが P7 では数えなかった字の数。`p6`＝濃い覆いの下（P6 で数える）、`ocrLayer`＝画像と重なる見えない字（文字認識の層） |

## 見えない理由（1字ごとに、上から順に最初に当たったもの）

| reason | 判定 | 値（`DEFAULT_SETTINGS`） |
|---|---|---|
| hidden_layer | 表示しないレイヤーの中（`BDC /OC` の入れ子と、部品の `/OC`。`/OCProperties` の `/D` の `/OFF`・`/ON`・`/BaseState`、OCMD の `/P`） | — |
| off_page | 字の箱の半分以上が、見える範囲（CropBox と MediaBox の重なり）の外 | 0.5 |
| clipped | 字の箱の半分以上が、切り抜きの外（切り抜きは道の箱で近似。部品の `/BBox` も切り抜き） | 0.5 |
| invisible | 描く色（下の注）がどれも不透明さ 0.1 未満。描き方 3・7 は描く色がないので invisible。ただし、字の中心がどれかの画像の箱の中なら、描く順番に関係なく文字認識の層として数えない（PR #22 の返事の 4） | 0.1 |
| tiny | 字の箱の高さが 1.0 ポイント未満 | 1.0 |
| squashed | 横の伸縮（字の横の長さ ÷ 縦の長さ。`Tz` と文字行列・`cm` をすべてかけたもの）が 0.1 未満。回した字・裏返した字は長さで比べるので当たらない（1.1.0 から） | 0.1 |
| （覆い） | 字のあとに、不透明（0.9 以上）・ふつうの重ね方・四角に近い（外枠の箱の 9 割以上を埋める）塗りが、字の箱の半分以上を隠す。塗りの明るさが 0.3 以下なら P6（`excluded.p6`）、それより明るければ **covered_light** | 0.9・0.9・0.5・0.3 |
| covered_image | 字のあとに、型抜き（ImageMask・SMask・Mask）のない画像を、不透明（0.9 以上）・ふつうの重ね方で置き、字の箱の半分以上を隠す。画像全体の 97% 以上が濃い（P6 と同じ数え方）なら P6（`excluded.p6`）。解けない画像（JPEG など）は濃さが分からないので covered_image（1.1.0 から） | 0.9・0.5・0.97 |
| same_color | 字の色の明るさと、字の中心の下（先に描いた、いちばん上の不透明な塗り。なければページの白）の明るさの差が 0.1 未満 | 0.1 |
| same_color_image | 字の中心の下がいちばん上に画像のとき、字の箱の中に 7×7 の点を並べて画像の画素を読み、9 割以上の点で字の色との明るさの差が 0.1 未満。写真の上の白い説明文のように字の色と違う点が多ければ当たらない。解けない画像（JPEG など）・型抜きのある画像では判定しない（1.1.0 から） | 0.1・0.9 |

見える字（上のどれにも当たらない字）には、続けて次の3つを見る（1.1.0 から。取りこぼし 26 項目の 15〜17）。

| reason | 判定 |
|---|---|
| remapped | 字の対応表の書き換え。1バイトの書体（Type1・TrueType。ToUnicode のあるもの）で、文字コード → 字形の名前（`/Encoding`・`/Differences`）から引いた見た目の字と、ToUnicode から取り出される字が、NFKC でそろえても違い、取り出される字に字か数字が入っている。合字（fi・f_f_i）・異体字（a.sc）・uniXXXX は名前から字を引いてそろえる（`remap.ts`）。記号の書体・2バイトの書体・Type3・名前から字が決まらない字形は比べない |
| hidden_codepoint | 見えない文字コード。取り出される字に、幅 0 の字（U+200B〜200D・2060〜2064・FEFF・180E）、向きの制御（U+200E・200F・202A〜202E・2066〜2069・061C）、書式の制御（U+206A〜206F）、タグ文字（U+E0000〜E007F）、C1 制御文字（U+0080〜009F）が入っている。数えるのは、その文字コードの数。やわらかいハイフン（U+00AD）は数えない |
| overdrawn | 違う字の重ね描き。同じ所（始まりの点が字の高さの 15% 以内）に、同じ大きさ（0.9 倍以上）・同じ向きで、違う1字（字か数字）があとから描かれている。先に描いた字を数える。太字のための同じ字の2度描き・記号の重ね打ち・大きさの違うふりがなは当たらない |

- 描く色（1.1.0 から）：描き方 0・4 は塗り、1・5 は輪郭、2・6 は塗りと輪郭の両方。それぞれ不透明さ（塗りは `ca`、輪郭は `CA`）と色を持つ。描き方 2・6 は、塗りと輪郭のどちらかが見えれば見える字で、same_color は見える描く色がすべて下の色と同じときだけ。1.0.2 までは、描き方 2 の字を塗りだけで見ていたので、塗りが透明で輪郭が黒い字を invisible と誤って出していた。
- 文字認識の層（1.1.0 から）：文字認識の層として数えなかった字があるページを `ocrLayerPages` に返す。危険の発見（findings）には入れない。画面で「お知らせ」に使う。

- 値は rubric/p7.json の `thresholds` と同じ数にした。PR #22 の返事の 1 で決まった値。
- 色の明るさは 0.299R + 0.587G + 0.114B。CMYK は (1−C)(1−K) などで RGB に直す。描き方 1・5（ふちだけ）の字は、線の色と線の不透明さで見る。
- 下の塗りは、形を問わず、字の中心が形の中にあるかで見る（曲線は4つの直線に分ける）。乗算などの重ね方の塗りと、半透明の塗りは、下の色にも覆いにもしない。

## 読み方

検証器（`verifier/`）は PDF.js の描画命令の列を読む。検出ルールは、それと別に、**pdf-lib でページの中身を取り出し、自分で書いた命令の読み手（`rules/shared/content-lexer.ts`。P6 と同じもの）で読む**。

1. ページの命令を順に読み、字（1字ごとの箱・色・描き方・不透明さ・レイヤー・切り抜き）、塗り（形・色・不透明さ・重ね方）、画像（置いた箱）を、描いた順番つきで集める。部品（Form XObject）の中も、行列（`/Matrix`）と切り抜き（`/BBox`）をかけて追う（入れ子 12 段まで。自分を呼ぶ部品は追わない）。
2. 集め終わってから、1字ごとに理由を決める。画像と重なる見えない字を、描く順番に関係なく文字認識の層とするため、ページ全体の画像を先に知っておく必要がある。
3. 同じ理由で続く字を1件にまとめる。同じ命令の中か、命令をまたいでも同じ行ですぐ隣に続く字（同じ向き、行に直交するずれが字の高さの 3 割以内、前の字の終わりからのすき間が字の高さ以内。1.1.0 から。1字ずつ別の命令で置いた白い字を1件にする）。間に見える字があれば分ける。箱の幅か高さが 1 ポイント未満なら、画面で見えるよう 1 ポイントまで広げる（横につぶれた字のため。1.1.0 から）。字の箱は、書体の幅と高さから出す。幅と高さは、P6 と同じ共通の読み方（`rules/shared/fonts.ts`。1.0.1 から）で引く。
   - 幅：`/Widths`・`/W` → 標準の書体なら pdf-lib の寸法 → `/MissingWidth` → 0.5em。
   - 高さ：`/Ascent`・`/Descent` → `/FontBBox` → 標準の書体の寸法 → 0.8em・−0.2em。
   - 空白は、1バイトのコード 32 のほか、ToUnicode で空白になる字（全角の空白など）も数えない（1.0.1 から。P6 と同じ）。
   - 1.0.0 との違い：高さの最後の既定の値（0.75・−0.25 → 0.8・−0.2）、Symbol・ZapfDingbats の幅を pdf-lib の寸法で引かない（コードから字を引けないため）、Type3 の倍率を正の値にする。合成 PDF の採点の数字と報告は変わらなかった。変わったのは、合成 PDF（P6 の t11）の、数えない文字認識の層の字数（参考の値）だけで、全角の空白1字を数えなくなったため 13 → 12 字。
- 注釈は描かない（注釈の中の字は P8 の範囲）。

## 埋め込み画像・模様（1.3.0、2026-11-05）

- 埋め込みの画像（ページの中身に直接書いた画像）の画素を、外の画像と同じに読む。覆い（covered_image）と、画像と同じ色の字（same_color_image）に使う。これまでは置いた箱だけを持ち、型抜きのある画像として扱っていた。
- 模様で塗った四角は、すき間なく不透明に塗り、明るさの分かる模様だけを、下の色・覆いの色にする（`rules/shared/patterns.ts`。P6 と同じ読み方）。`sh` は、いまの切り抜きの中を塗ったものとする。
- 字を描くタイルの模様で塗ったときは、塗った所にタイルを並べ（64 枚まで）、タイルの中の字も字として見る（白い地の模様の中の白い字は same_color）。

## 読める本文か（1.5.0、2026-11-05）

実物の公開 PDF（依頼元のセッションが手元で測ったもの。漏れなしと判定された 245 件のうち 104 件で P7 が「高」）で、表の体裁・罫線・白い字の飾りのような、まとまって出る型が「高」で多く出た。そこで、字の報告ごとに `readable`（読める本文か）を付ける。画像の報告（`image_off_page`・`image_clipped`）には付けない。

- `readable: true` の条件：1件の中の字か数字が `readableLettersMin`（4）以上、種類が `readableDistinctMin`（3）以上で、次のどれにも当たらないこと【値は仮】。
  - 同じ理由・同じ型（空白を除き、数字を `#` にならした字の並び）の報告が、文書の中に `templateRepeatMin`（3）以上ある。表のセルごとの隠し字、ページごとの欄外の字など。
  - 字の対応表の書き換え（`remapped`）で、そのページの見える字の `remappedPageShareMin`（50%）以上が書き換わっている。書体の対応表の不具合で、隠したものではない。
- 4 字にしたのは、日本語の人名が 2〜4 字だから。最初は 8 字にしたが、見ないで作るテスト集の T60（5 字の重ね描き）が「中」に落ちたので下げた。
- 画面の深刻度（`src/inspect/rules.ts`）：`readable: false` は「中」。`true` は、これまでどおり理由ごとの深刻度（見えない文字コードは「中」、ほかは「高」）。
- 合成した型：`tests/p7-readable.test.ts`（白い字の1文・4 字の名前・ページの外の1文・本文の中の1語の書き換えは「高」。白い罫線・同じ字のくり返し・数字1つ・3 字の番号・表のセルごとの同じ型・ページごとの欄外の字・ページの大部分の書き換えは「中」）。
- 限界：3 字以下の隠し字（2〜3 字の名前など）は「中」になる。同じ型の隠し字が3つ以上あれば、本当の隠しでも「中」になる。字の対応表がなく字を取り出せない書体の隠し字は、字の数を数えられないので「中」になる。

## 画面に出さない理由（2026-11-05）

覆いの下の字は、色によらず P6 で出す（人の決定。`rules/p6-text/README.md` の 1.11.0）。画面（`src/inspect/rules.ts`）では、`covered_light`・`covered_image` を P7 に出さない。この検出ルールの報告には残す（P7 の正解データ `p7-11`・`p7-12` と検証器は、これらを P7 として数えるため）。合成 PDF のすべてで、P7 のこの2つ 10 件のうち 9 件は P6 にも出た。出なかった1件は、帯の上に同じ字を描き直した対照（F06）で、P6 が正しく除いたもの。

また、文字認識の層のあるページ（`ocrLayerPages`）を、画面の「お知らせ」（`kind: "info"`）として出す（T62）。

## できないこと（限界）

- 画像の色は、このルールで解ける画像（Flate など。P6 と同じ `rules/p6-text/images.ts`）だけを見る。JPEG など解けない画像の上の字は same_color_image にしない（暗い写真の上の白い字を誤って報告しないため。代わりに、JPEG の写真と同じ色の字は見逃す）。画面の Worker には JPEG を解く道具を渡していない（P6 と同じ）。
- 画像の色は明るさだけで比べる。明るさが同じで色の違う字（緑の地の赤い字など）を same_color_image と出すことがある。
- 字の対応表の書き換え（remapped）は、1バイトの書体で、字形の名前から字が決まるものだけ。日本語の書体（2バイト。Identity-H）は、埋め込みの書体の中の表を読まないと見た目の字が分からないので、比べない。
- 違う字の重ね描き（overdrawn）は、字の箱（書体の高さ）と始まりの点で比べる。実際の字の形（インク）は見ない。
- 見えない文字コード（hidden_codepoint）は、日本の公開 PDF の束では確かめていない（束はこのルールの作業の場所にない。PR の「できなかったこと」）。
- 切り抜きは箱で近似する。円などで切り抜いた外の字は、箱の中なら見逃す。
- 下の色は、字の中心の1点で見る。模様（Pattern）・グラデーション・特色（Separation・DeviceN）・Lab の色は、明るさを決めない（same_color も覆いも判定しない）。
- 線（`S`）で隠したものは見ない。字の上に別の字を重ねたものは、同じ所に同じ大きさで違う1字を描いたもの（overdrawn）だけを見る。
- 2バイトの書体（Type0）は、2バイトずつ区切る。Identity 以外の CMap で1バイトの字を混ぜる書体は、字の区切りと幅がずれる。
- 字の数は、1バイトの書体では空白（32）を除いたバイトの数、2バイトの書体では字の数。
- 縦書き（CMap の名前が `-V` で終わる Type0）は、1.7.0（2026-11-06）から P6 と同じ箱と送りで見る（`rules/shared/fonts.ts` の `glyphExtent`・`glyphAdvance`・`tjShift`）。字は縦の原点から、横は幅の半分ずつ左右に、縦は原点から下へ広がり、下へ送る（`DW2` を読む）。字ごとの `W2`、縦書きの `Tw` は見ない。1.6.0 までは縦の列の字を右へ送っていたので、縦書きの紙面で、隣の列の字との「違う字の重ね描き」と、右の端の列の「ページの外」を、たくさん誤って出していた。
- 縦書きと横書きの字は、進む向きが違うので、重ね描きでは比べない（同じ所に縦と横の違う字を重ねたものは見逃す）。
- 1ページの命令が 300 万を超えるページは省く（`skippedPages`）。1.0.2 から、P6 と画面と同じ値（#32）。1.0.1 までは 30 万。
- 暗号化された PDF のうち、復号できないもの（パスワードが要るものなど）は `encrypted` で止める。
- 時間の上限はこのルールの中にはない。画面では Worker の時間の上限で止める。
