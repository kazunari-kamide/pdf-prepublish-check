# 検出ルール：P7（隠れたテキスト）

PDF を入れると、取り出せるのに、画面では見えない字を返す（rubric/p7.md §2）。1件 ＝ 1回の字を描く命令（`Tj`・`TJ`・`'`・`"`）の中で、同じ理由で続く見えない字のまとまり。**字そのものは返さない**（字数と箱だけ）。

```ts
import { detectP7Hidden } from "./rules/p7-hidden/index.ts";
const report = await detectP7Hidden(bytes);                         // 字数と箱だけ
const report2 = await detectP7Hidden(bytes, { includeText: true }); // 字そのものも返す（調べるときだけ。記録やログには使わない）
```

出力の形は `rules/p6-text` にそろえた（`rule`・`status`・`error`・`pages`・`findings`・`skippedPages`）。読み込みは共通の入口（`rules/shared/load.ts`）を使うので、パスワードなしで開ける暗号化 PDF は復号して調べる。

| 項目 | 中身 |
|---|---|
| `findings[].reason` | 見えない理由（下の表） |
| `findings[].rect` | 見えない字の箱。ページの既定の座標（ポイント、左下が原点、`/Rotate` はかけない） |
| `findings[].chars` | 見えない字の数（空白を除く） |
| `skippedPages` | 調べられなかったページ（命令が多すぎる・読めない）。「問題なし」ではない |
| `excluded` | 見えないが P7 では数えなかった字の数。`p6`＝濃い覆いの下（P6 で数える）、`ocrLayer`＝画像と重なる見えない字（文字認識の層） |

## 見えない理由（1字ごとに、上から順に最初に当たったもの）

| reason | 判定 | 値（`DEFAULT_SETTINGS`） |
|---|---|---|
| hidden_layer | 表示しないレイヤーの中（`BDC /OC` の入れ子と、部品の `/OC`。`/OCProperties` の `/D` の `/OFF`・`/ON`・`/BaseState`、OCMD の `/P`） | — |
| off_page | 字の箱の半分以上が、見える範囲（CropBox と MediaBox の重なり）の外 | 0.5 |
| clipped | 字の箱の半分以上が、切り抜きの外（切り抜きは道の箱で近似。部品の `/BBox` も切り抜き） | 0.5 |
| invisible | 描き方 3・7、または字の不透明さが 0.1 未満。ただし、字の中心がどれかの画像の箱の中なら、描く順番に関係なく文字認識の層として数えない（PR #22 の返事の 4） | 0.1 |
| tiny | 字の箱の高さが 1.0 ポイント未満 | 1.0 |
| （覆い） | 字のあとに、不透明（0.9 以上）・ふつうの重ね方・四角に近い（外枠の箱の 9 割以上を埋める）塗りが、字の箱の半分以上を隠す。塗りの明るさが 0.3 以下なら P6（`excluded.p6`）、それより明るければ **covered_light** | 0.9・0.9・0.5・0.3 |
| same_color | 字の色の明るさと、字の中心の下（先に描いた、いちばん上の不透明な塗り。なければページの白）の明るさの差が 0.1 未満 | 0.1 |

- 値は rubric/p7.json の `thresholds` と同じ数にした。PR #22 の返事の 1 で決まった値。
- 色の明るさは 0.299R + 0.587G + 0.114B。CMYK は (1−C)(1−K) などで RGB に直す。描き方 1・5（ふちだけ）の字は、線の色と線の不透明さで見る。
- 下の塗りは、形を問わず、字の中心が形の中にあるかで見る（曲線は4つの直線に分ける）。乗算などの重ね方の塗りと、半透明の塗りは、下の色にも覆いにもしない。

## 読み方

検証器（`verifier/`）は PDF.js の描画命令の列を読む。検出ルールは、それと別に、**pdf-lib でページの中身を取り出し、自分で書いた命令の読み手（`rules/shared/content-lexer.ts`。P6 と同じもの）で読む**。

1. ページの命令を順に読み、字（1字ごとの箱・色・描き方・不透明さ・レイヤー・切り抜き）、塗り（形・色・不透明さ・重ね方）、画像（置いた箱）を、描いた順番つきで集める。部品（Form XObject）の中も、行列（`/Matrix`）と切り抜き（`/BBox`）をかけて追う（入れ子 12 段まで。自分を呼ぶ部品は追わない）。
2. 集め終わってから、1字ごとに理由を決める。画像と重なる見えない字を、描く順番に関係なく文字認識の層とするため、ページ全体の画像を先に知っておく必要がある。
3. 同じ命令の中で同じ理由で続く字を1件にまとめる。字の箱は、書体の幅と高さから出す。幅と高さは、P6 と同じ共通の読み方（`rules/shared/fonts.ts`。1.0.1 から）で引く。
   - 幅：`/Widths`・`/W` → 標準の書体なら pdf-lib の寸法 → `/MissingWidth` → 0.5em。
   - 高さ：`/Ascent`・`/Descent` → `/FontBBox` → 標準の書体の寸法 → 0.8em・−0.2em。
   - 空白は、1バイトのコード 32 のほか、ToUnicode で空白になる字（全角の空白など）も数えない（1.0.1 から。P6 と同じ）。
   - 1.0.0 との違い：高さの最後の既定の値（0.75・−0.25 → 0.8・−0.2）、Symbol・ZapfDingbats の幅を pdf-lib の寸法で引かない（コードから字を引けないため）、Type3 の倍率を正の値にする。合成 PDF の採点の数字と報告は変わらなかった。変わったのは、合成 PDF（P6 の t11）の、数えない文字認識の層の字数（参考の値）だけで、全角の空白1字を数えなくなったため 13 → 12 字。
- 注釈は描かない（注釈の中の字は P8 の範囲）。

## 合成 PDF で測った値（2026-11-03、`npm run eval`）

- 検出率 100.0%（20 件中 20 件）。誤検知率 0.0%（16 件中 0 件）。字数もすべて正解と同じ。内訳は `docs/evolution.md`。
- 確かめ（合否には使わない）：P6 の合成 PDF 33 個にかけると、報告は d03（薄い色のマーカー）の covered_light 2 件だけだった。検証器の説明（verifier/P7.md）と同じ。読めなかった PDF は 0 個（暗号化したものも読めた）。省いたページは 1 つ（重いページ h01。命令の上限を超えたため）。

## できないこと（限界）

- 画像の色は見ない。字の下が画像のときは、same_color にしない（暗い写真の上の白い字を誤って報告しないため。代わりに、写真と同じ色の字は見逃す）。
- 切り抜きは箱で近似する。円などで切り抜いた外の字は、箱の中なら見逃す。
- 下の色は、字の中心の1点で見る。模様（Pattern）・グラデーション・特色（Separation・DeviceN）・Lab の色は、明るさを決めない（same_color も覆いも判定しない）。
- 字の上に別の字を重ねて隠したもの、線（`S`）で隠したものは見ない。
- 2バイトの書体（Type0）は、2バイトずつ区切る。Identity 以外の CMap で1バイトの字を混ぜる書体は、字の区切りと幅がずれる。
- 字の数は、1バイトの書体では空白（32）を除いたバイトの数、2バイトの書体では字の数。
- 縦書きは、横書きと同じ箱で近似する。
- 1ページの命令が 30 万を超えるページは省く（`skippedPages`）。
- 暗号化された PDF のうち、復号できないもの（パスワードが要るものなど）は `encrypted` で止める。
- 時間の上限はこのルールの中にはない。画面では Worker の時間の上限で止める。
