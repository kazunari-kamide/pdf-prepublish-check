# 検出ルール：見える文字の個人情報らしい字（`rules/pii`、番号 P13 は【仮】）

公開・提出の前に、**見える文字の中に、個人情報らしい字が残っていないか**を、**黒塗りの候補**として示す。決めるのは利用者（目視の確認での見落としを防ぐ補助）。決まったルールだけで、ブラウザの中で動く（AI・送信なし）。

**字の中身は、既定では返さない。** 返すのは、型・ページ・場所（箱）・確からしさ・手がかりの種類・字数・件数だけ。設定 `includeText`（ほかのルールと同じ名前と形。0.1.3 から）を渡したときだけ、見つけた字そのものを 1 件ごとに `text` として返す（画面が、頭の 2 字だけを出して伏せるため）。コマンドの道具・スキル・記録・報告書は、渡さない。

```ts
import { detectPii, countsOnly, findPiiInContent, findPiiInText } from "./rules/pii/index.ts";
const report = await detectPii(bytes);            // 候補の一覧（型・ページ・箱・確からしさ）
const counts = countsOnly(report);                // 件数だけ（実物で測るとき）
```

| 項目 | 中身 |
|---|---|
| `findings[].type` | `name`（氏名）・`address`（住所）・`phone`（電話番号）・`my_number`（マイナンバー）・`bank_account`（口座番号）・`birth_date`（生年月日）・`email`（メールアドレス）・`card_number`（カード番号） |
| `findings[].page`・`rect` | ページと、候補の字の箱（ページの既定の座標。ポイント、左下が原点、`/Rotate` はかけない）。黒塗りの候補の枠にそのまま使える |
| `findings[].confidence` | `high`（高）＝前後の語・表の見出しが型を指している、または型そのものが強い手がかり（携帯電話の番号など）。`check`（確認）＝形は合うが手がかりが弱い |
| `findings[].basis` | 手がかりの種類：`label`（前後の語）・`column_header`（表の見出し）・`honorific`（「様」などの呼び方）・`pattern`（字の形）・`check_digit`（番号の検査用の数字） |
| `findings[].chars`・`vertical` | 字数（空白を除く）、縦書きか |
| `counts` | 型ごと・確からしさごとの件数 |
| `excluded` | 形は合ったが候補から除いたもの（理由ごとの数）：見本の値・役職名・団体名・見出しの語・団体の窓口・フリーダイヤル・法人番号・日付の並び |
| `skippedPages` | 調べなかったページ（命令が多すぎる・読めない・ページ数の上限） |
| `unreadable` | 中身を引けない字（ToUnicode のない書体など）のあったページと字数。そこは探せていない |

## 読み方

1. ページの描く命令を順に読み、1字ごとに「字の中身（ToUnicode）」「箱」「進む向き」を集める（`text.ts`）。図形は組み立てない。部品（Form XObject）の中も読む。書体は P6・P7 と同じ共通の部品（`rules/shared/fonts.ts`）で読む。
   - 縦書き：書体の CMap の名前が `-V` で終わるか、CMap の `/WMode` が 1 のとき、字を下へ進める（既定の縦の寸法 `[880 −1000]`）。
   - 描き方は区別しない（白い字・見えない字も読む）。文字認識の層（スキャンの上の見えない字）は、見えている紙の字と同じ中身なので、ここで探す意味がある。見えない字そのものは P7 が別に数える。
2. 字を行（縦書きは列）にまとめる（`lines.ts`）。字の間があけば空白、大きくあけば区切り（表の別の欄）を入れる。太字の2度描きは1字にする。
3. 行ごとに、型ごとの決まりで探す（`patterns.ts`）。全角の英数字は半角に、漢数字（〇〜九、十・百）は数字として読む。
4. 表：横書きの欄の上に「氏名」「住所」「電話番号」「生年月日」などの見出しがあれば、その欄の値を、見出しの型として確かめる（確からしさは高）。

## 型ごとの決まり

| 型 | 候補にするもの | 確からしさ | 候補にしないもの（除いたものとして数える） |
|---|---|---|---|
| 氏名 | 「氏名」「フリガナ」「申請者」「保護者」などのあと（高）、「担当」「作成者」などのあと・役職のあと・「様」「殿」「さん」「氏」の前（確認）、表の「氏名」の列（高） | 上のとおり | 役職名だけ（委員長）、役職で終わる並び（総務課長）、団体・課の名前（総務課、企画政策部、みどり市）、見出しの語、見本の名前（山田太郎 など）・〇〇、「各位」「お客様」「利用者様」「同氏」 |
| 住所 | 市区町村（都道府県は任意）＋番地（丁目・番・号・ハイフン。数が2つ以上） | 「住所」「現住所」「自宅」「送付先」などのあと・表の「住所」の列で高、ほかは確認 | 「所在地」「会場」「本社」などのあと、団体の窓口の行、〇〇の入った見本、条文の番号（第12条第3項） |
| 電話番号 | 0 で始まる 10 けた（固定）・11 けた（070・080・090・050）。区切りのない並びは、前に電話を指す語があるときだけ | 携帯・IP 電話は高（団体の窓口の行では確認）。固定は「自宅」「携帯」「緊急連絡先」などのあとで高、ほかは確認 | 0120・0800・0570 などの 10 けた、団体の窓口の行（代表・問い合わせ・FAX・課・係・センター・内線）の固定電話、市内局番が 1 で始まる並び（図番など）、0 や同じ数字ばかりの見本 |
| マイナンバー | 12 けた（4・4・4 の区切りか、区切りなし）で、**検査用の数字が合う**もの | 「個人番号」「マイナンバー」のあとで高、ほかは確認 | 合わない 12 けた、法人番号（13 けた、検査用の数字が合うもの・「法人番号」のあと）、日付と時刻の並び（202611051303 など）、1234… などの見本 |
| 口座番号 | 「口座番号」「普通」「当座」などのあとの 7 けた、ゆうちょの記号（5 けた）・番号（8 けた） | 高。「振込先」の行では確認（団体の口座のことが多い） | 見本の数字 |
| 生年月日 | 和暦（明治〜令和、M・T・S・H・R、元年、漢数字）・西暦の日付で、前に「生年月日」「誕生日」があるか、あとに「生」「生まれ」がつくもの、表の「生年月日」の列 | 高 | ふつうの日付（作成日・施行日・会議の日時） |
| メールアドレス | 英数字の @ のあるもの | 「個人」「本人」「自宅」のあとで高、ほかは確認。例示用のドメイン（example.com・example.jp など）は、前の語があっても確認にとどめる（0.1.1） | sample・test などの見本の名前、「記入例」などの行、info・contact などの窓口の名前、団体の窓口の行。例示用のドメインだけでは除かない（架空の人の資料も例示用のドメインで作るため。0.1.1） |
| カード番号 | 14〜16 けた（4 けたずつの区切りか区切りなし）で、Luhn と番号の頭が合うもの | 「カード」「クレジット」のあとで高、ほかは確認 | 日付の並び、よく知られた試験用の番号 |

- 行に「記入例」「見本」「【例】」などがあれば、その行の候補は見本の値として除く。
- 名字の終わりにもなる語尾（部・村・町・市・所・室 など。阿部・中村・田所・氷室）は、並びが 4 字以上か、前が部署の語（総務・企画 など）か、かなで始まるときだけ団体名とみなす。

## 前の版の中も調べる入口（26 項目の 21）

`findPiiInContent(ctx, content, resources)` は、ページ1つぶんの描く命令の列（ほどいたもの）と、その版の資源の辞書から、**型ごとの件数だけ**を返す。P5（旧版の残存）の側で、前の版の中身（`kind: "content"`）にかけ、「前の版に個人情報らしい字」を出すために使う。つなぐのは P5 の担当と相談する。

`findPiiInText(text)` は、場所のない字（文書情報の欄・注釈の中身など）から件数だけを返す（改行で行に分ける）。

## 実物で測る入口

`npm run eval:pii-count -- <フォルダ>`（または環境変数 `PII_COUNT_DIR`）。フォルダの中の PDF を全部かけ、型ごとの件数・除いたものの数・時間だけを出す。ファイル名・場所・字の中身は出さない。

## 速さ（2026-11-04、Node 24.19.0、Windows。`tests/pii-rule.test.ts`）

- 100 ページ（1ページ 60 行、表と文。候補 3,000 件）：268〜300 ms。
- 100 ページ（1ページ 3,000 字の詰まった文、合計 30 万字）：349 ms。
- 1ページの命令は 300 万まで（画面では P6 と同じ上限）。字は 1ページ 20 万字まで読む（超えたら途中までと知らせる）。

## できないこと（限界）

- **字の中身を引けない書体は探せない。** ToUnicode のない日本語の書体（定義済みの CMap だけのもの）や、字の形だけの書体は、字の中身が分からない。そのページは `unreadable` で知らせる。
- **画像の中の字（スキャン）は探さない**（文字認識の層があれば、その字は探す）。
- **氏名は、前後の語・表の見出し・呼び方がないと見つけない。** 文の中の名前だけ（「…と朝霧が述べた」）は探さない。辞書を持たないため。
- 表の見出しは横書きだけ。縦書きの表、見出しが左にある縦の並び（見出しと値が別の行）は、行の中の前後の語でだけ見る。
- 1行（1列）をまたぐ住所・氏名は、行ごとに別に見る（つながらない）。
- 確からしさの高・確認は、決まった語で決める。公表された委員の名前か、一般の人の名前かは見分けない（利用者が決める）。
- 電話番号の判定は、固定電話の市内局番が 0 で始まる並びも候補にする（実際には使われないが、合成 PDF で架空の番号にするため。実物では起きない）。
- パスワードが要る暗号化 PDF は読まない。パスワードなしで開ける暗号化は、共通の入口（`rules/shared/load.ts`）で復号して読む。
