# 描かれていない資源に残る画像 `unused-images`

墨消しを適用したあとも、塗る前の元の画像が、ページの資源（`/Resources /XObject`）に名前つきで残り、どこからも描かれていない型。いまの版から指されているので、P5 の「使っていない定義」（どこからも指されていないオブジェクト）には当たらない。型は P5（旧版の残存）の仲間【仮】。

## 見つけ方

1. 文書全体で、実際に描かれた画像を集める。ページ・描かれた部品（フォーム XObject）・注釈の見た目の中の `Do` で、部品の中もたどる。
   ページどうしで資源の辞書を共有する PDF（ほかのページで描く画像が並ぶ）でも誤検知しないよう、文書全体で集める。
2. 各ページの資源と、そこから届く部品の資源の `/XObject` にある画像のうち、文書のどこでも描かれていないものを出す。
3. 同じページで描かれた画像に、同じ大きさ（幅・高さ）のものがあれば、画素を比べる（明るさか色の濃さの差が 0.1 より大きい点を「違う点」とする。大きな画像は間引いて 100 万点まで）。
   - 違う点の割合が 0 より多く 5% 以下：`similar`（墨消し前の元の画像のおそれ）。画面では高【仮】。
   - 同じ大きさだが、画素を読めなかった：`uncompared`。中【仮】。
   - まったく同じ（`identical`）・大きく違う（`different`）・同じ大きさのものが無い（`no_same_size`）：低【仮】。
   - JPEG などは、画面（Worker）では PDF.js で解いて比べる。

値（画素）は返さない。ページ・大きさ・違いの割合だけ。

## 確かめたこと

- 合成 PDF 5 件（隠しあり 3・対照 2。`eval/cases/unused-images.ts`）：検出 3/3、誤検知 0。
- 今ある合成 PDF 370 件にかけて出たのは、P9 の対照 1 件（`p9-n05`。描かれない画像のストリームが実際にある。低）だけ。
- 片付け（`sanitize` 0.7.0）は、ページの資源の描かれない画像を外す。描かれた部品の資源の中に残るもの（`ui-l02`）は、まだ外さない。

## できないこと（限界）

- 模様（パターン）・Type3 の書体・型抜き（SMask）の中から使う画像は、描かれたとみなさないことがある（その資源の辞書は見ない）。
- 大きさの違う元の画像（切り抜く前など）は、比べずに低で出す。
- 日本の公開 PDF の束での誤検知は、まだ測っていない。
