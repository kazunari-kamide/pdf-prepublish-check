# xmp-thumbnail：文書全体の XMP に埋め込まれた縮小画像（0.1.0）

カタログの `/Metadata`（文書全体の XMP）の `xmp:Thumbnails` に入った縮小画像（base64 の JPEG など）を、**数と大きさ**で返す。型は P2（XMP メタデータ）の仲間【仮】、画面の深刻度は中【仮】。画面では、いつも「確かめてください」として出す。

作ったときの 1 ページ目の見た目が入り、ページを直したり黒塗りしたりしても、作り直されずに前の見た目のまま残ることがある。

## 今あるルールとの分け方

- `extras`：ページの `/Thumb` だけを見る。XMP の中の縮小画像は見ない。
- `p2-xmp`：字の欄（人名・題・パス・履歴・GPS）だけを見る。縮小画像の欄は数えない。
- `p10-exif`：JPEG の画像の Exif の中の縮小画像だけ。
- `p2-parts`：部品ごとの XMP で、カタログの XMP は見ない。

## 見るもの

- `xmpGImg` の名前空間（`http://ns.adobe.com/xap/1.0/g/img/`）に結んだ接頭辞の `image` の欄。要素の形と属性の形の両方。接頭辞の名前は問わない。
- base64 は、XML の数値の参照（`&#xA;` など）と空白を外して解く。圧縮あり（Flate）・なしの両方。
- 1件 ＝ 縮小画像 1 つ。返すのは、形（jpeg・png）・書いてある幅と高さ・解いたバイト数だけ。**画像の中身は返さない。**

## 数えないもの（`notCounted`）

- `empty`：画像の欄が空。
- `not_image`：base64 を解けない、または解いても JPEG・PNG の頭でない。

## まだしないこと

- いまのページの見た目とは比べない（JPEG を解く道具をこのルールは持たないため）。同じ見た目の縮小画像も出す。`extras` のように比べるのは次の版の候補。

## 合成 PDF

`eval/cases/xmp-thumbnail.ts`：隠しあり 3（要素の形・属性の形と圧縮・接頭辞を変えた 2 つ）、対照 4（縮小画像なし・中身が空・画像でない字・ページの `/Thumb` だけ）。中身はすべて架空。
