# 検証器：P1（文書情報）

PDF を1つ入れると、いまの版の文書情報（Info 辞書）に残っている欄を JSON で返す。

```
node verifier/p1-cli.mjs 入力.pdf                    # 標準出力に JSON（形は p1-schema.json）
node verifier/p1-cli.mjs 入力.pdf --include-values   # 値そのものも出す（調べるときだけ。記録やログには使わない）
node verifier/p1-selfcheck.mjs                       # 合成 PDF と正解データで、検証器そのものを確かめる
```

終了コード：0 ＝ 読めた（残りがあっても 0）、1 ＝ 使い方の誤り、2 ＝ PDF を読めなかった。

## 検査器から独立していること

- `src/`・`rules/` のコードを import しない。検出ルールは pdf-lib で書く予定なので、検証器は **pdf-lib を使わない**。
- 読み方を2つ持つ。
  1. **バイト列を自分で読む**（主）：末尾の `startxref` から、xref（表・ストリーム・混ぜた形の `/XRefStm`）を `/Prev` までたどる。新しい版の場所を優先して、オブジェクトの番号 → 場所の表を作る。いまの版の trailer の `/Info` を、その表で引く（オブジェクトストリームの中、trailer の中に直接書いた辞書も読む）。
  2. **PDF.js（pdfjs-dist 6.4.299）の `getMetadata`**（突き合わせ）：安全側の設定（`isEvalSupported: false` など）で使う。
- どちらか片方で値があれば「残っている」とする（安全側）。食い違いは `cross_check` に鍵の名前だけを出す。
- 捨てた案：PDF.js だけで読む。前の版の文書情報の数を出せないため。

## 判定

- 数えない欄（`Producer`・`CreationDate`・`ModDate`・`Trapped`、空・空白だけの値）は `not_counted` に理由つきで出す。それ以外で値がある欄を `items` に出す。
- 値は、UTF-16BE（BOM）・UTF-16LE（BOM）・UTF-8（BOM）・PDFDocEncoding を読み分ける。16 進の文字列（奇数桁は 0 を足す）、`( )` の中のエスケープ・行の継続、UTF-16BE の中の言語のしるし（ESC で囲んだもの）も扱う。鍵の `#xx` は解く。
- 前の版の文書情報（P5 の範囲）は、`previous_info` に数だけを出す。数え方：古い trailer が別の番号の Info を指していれば1つ、いまの Info と同じ番号の定義がファイルの中に2つ以上あれば、その余りの数。

## 確かめた結果（2026-11-03、Node 24.19.0、Windows）

`node proposals/p1/verifier/p1-selfcheck.mjs` の結果：

- 合成 PDF 18 個すべてで、正解データと合った。漏れ 22 件中 22 件を見つけた。漏れでない欄 20 件中 0 件に反応した。正解にない出力は 0 件。数えない理由も、すべて正解と同じ。
- 2つの読み方が食い違った PDF は 0 個。
  - 途中で、独自の欄が PDF.js の側から取れていなかった。原因は、pdfjs-dist 6.4.299 が独自の欄（`Custom`）を Map で返すのに、こちらがふつうのオブジェクトとして読んでいたこと（`node_modules/pdfjs-dist/legacy/build/pdf.worker.mjs` の 66038〜66055 行）。Map として読むように直した。
- 壊れた入力（空のファイル、PDF でないもの、途中で切れた PDF、入れ子が 5000 段の配列、`/Encrypt` のある trailer）で、止まらなかった。空・PDF でない・深すぎる入れ子は `error`、暗号化は `encrypted` を返した。

## できないこと（限界）

- **XMP（P2）は見ない。** 同じ作成者名が XMP に残っていても、P1 では数えない。
- **値の中身は判定しない。** 個人名か課の名前か、パス（P4）が入っているかは見ない。値があれば数える。
- 文書情報の値が、別のオブジェクトへの参照で、その先が文字列でないもの（配列など）は、値なしとして `empty` に入れる。
- 圧縮は Flate だけを解く（xref ストリーム・オブジェクトストリームに使われるのは、ほぼ Flate のため）。ほかの圧縮のときは、PDF.js の読み方だけになる（`cross_check.bytes_unreadable`）。
- 暗号化された PDF は `encrypted` で止める。中身は読まない。
- 前の版の数え方は目安。オブジェクトの番号を、ファイル全体の文字から探して数える。ストリームの中の文字にたまたま同じ並びがあると、多く数えることがある（合否には使わない）。
- 時間の上限は、PDF.js の読み方に 20 秒。バイト列の読み方には時間の上限はなく、xref の区切りを 1000 個まで、入れ子を 64 段まで、解いたストリームを 64 MB までで止める。
