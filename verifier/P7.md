# 検証器：P7（隠れたテキスト）

PDF を1つ入れると、取り出せるのに画面では見えない字を JSON で返す。

```
node verifier/p7-cli.mjs 入力.pdf                  # 標準出力に JSON（形は p7-schema.json）
node verifier/p7-cli.mjs 入力.pdf --include-text   # 字そのものも出す（調べるときだけ。記録やログには使わない）
node verifier/p7-selfcheck.mjs                     # 合成 PDF と正解データで、検証器そのものを確かめる
```

終了コード：0 ＝ 読めた（残りがあっても 0）、1 ＝ 使い方の誤り、2 ＝ PDF を読めなかった。

## 検査器から独立していること

- `src/`・`rules/` のコードを import しない。この案を書いたセッションは、P7 の検出ルールを書かない（別のセッションが書く）。
- pdf-lib は使わない。PDF.js（pdfjs-dist 6.4.299）の描画命令の列（`getOperatorList`）を読む。表示するレイヤーかは `getOptionalContentConfig` で引く。
- PDF.js は安全側の設定で使う（`isEvalSupported: false`、`disableFontFace: true`、`useSystemFonts: false`）。
- 注釈は描かずに読む（`annotationMode: DISABLE`）。注釈の中の字は P8 の範囲のため。
- P6 の検証器（`verifier/p6.mjs`）とは、コードを分けた。P6 の読み方は、字の色・描き方・切り抜き・レイヤーを追わないため。

## 判定の考え方

1字ごとに、次の順で、最初に当たった理由1つにする。

1. **hidden_layer**：表示しないレイヤーの中（マーク付きの中身 `BDC /OC …` の入れ子を追う）
2. **off_page**：字の箱の半分以上が、ページの見える範囲（PDF.js の `page.view`。CropBox、なければ MediaBox）の外
3. **clipped**：字の箱の半分以上が、切り抜きの外。切り抜きの範囲は、切り抜きに使った道の箱で近似し、入れ子は箱どうしを重ねる。部品（Form XObject）の `/BBox` も切り抜きとして扱う
4. **invisible**：描き方が 3（見えない）か 7（切り抜きだけ）、または字の不透明さが 0.1 未満。ただし、字の中心に画像が重なっていれば、文字認識の層として数えない（`excluded.ocr_layer`）。画像を字の前に描いても後に描いても同じ（0.2.0、PR #22 の返事の 4。画像の前に見えない字を書く道具があるため）
5. **tiny**：字の箱の高さが 1.0 ポイント未満
6. 字のあとに、不透明で四角に近い塗りが字の箱の半分以上を覆っていれば、その塗りが濃い（明るさ 0.3 以下）なら P6（`excluded.p6`）、濃くなければ **covered_light**
7. **same_color**：字の色の明るさと、字の中心の下にあるもの（先に描いた不透明な塗り・画像。なければページの白）の明るさの差が 0.1 未満

- 下にあるものは、形を問わず、字の中心が形の中にあるかで見る（曲線は4点に分けて近似）。上に重ねた覆いとして数えるのは、四角に近い形（外枠の箱の 9 割以上を埋めるもの）だけ。
- 色は PDF.js が RGB に直した値で、明るさは 0.299R + 0.587G + 0.114B。描き方 1・5（ふちだけ）の字は、線の色で見る。
- 乗算（Multiply）などの重ね方の塗りは、下が透けるので、覆いにも地にもしない。

## 確かめた結果（2026-11-03、Node 24.19.0、Windows）

`node proposals/p7/verifier/p7-selfcheck.mjs` の結果：

- 0.2.0（差し替えたあとの形を `.tmp/` に組み立てて測った）：合成 PDF 25 個すべてで、正解データと合った。漏れ 20 件中 20 件、漏れでないもの 17 件中 0 件に反応、正解にない出力 0 件、字数もすべて正解と同じ。足した p7-25（見えない字を先に書き、あとから画像を重ねた）は、0.1.0 では invisible と誤り、0.2.0 では数えなかった。
- 0.2.0 で、P6 の合成 PDF（差し替えたあとの 37 個）にもかけた。報告は 0 件（作り直した d03 の半透明・乗算のマーカーも報告しない）。開けなかったのは、パスワードつきの e03 だけ。
- 以下は 0.1.0 のときの結果。
- 合成 PDF 24 個すべてで、正解データと合った。漏れ 20 件中 20 件を見つけた。漏れでないもの 16 件中 0 件に反応した。正解にない出力は 0 件。字数もすべて正解と同じ。
- 理由ごと：same_color 7 件中 7、off_page 4 件中 4、tiny 2 件中 2、invisible 3 件中 3、hidden_layer 1 件中 1、clipped 1 件中 1、covered_light 2 件中 2。
- 壊れた入力 3 種（空のファイル、PDF でないもの、途中で切れた PDF）で、止まらなかった。
- P6 の合成 PDF（`fixtures/p6/`、33 個）にもかけた。P7 が報告したのは d03（薄い色のマーカー）の 2 件だけで、covered_light と判定した（README の決めてほしいこと）。
  - 黒い塗り・黒い画像で覆った字は、P7 では出さず `excluded.p6` に数えた。注釈で覆った字（t09・t10）は、P7 は注釈を見ないので、見える字として扱った（報告しない）。
  - スキャン画像の上の見えない字（t11）は `excluded.ocr_layer` に数えた。
  - 途中で、P6 の d09（黒い楕円の上の白い字）を same_color と誤って判定した。楕円を下の塗りとして数えていなかったため。下の塗りは形を問わず見るように直し、同じ形の合成 PDF（p7-24）を足した。

## できないこと（限界）

- **パスワードが要る暗号化 PDF は読めない**（`encrypted`）。パスワードなしで開ける暗号化は、PDF.js が開くので調べる。
- 画像と重なる見えない字は、本当に文字認識の層か（画像の中の字と同じ内容か）を見ない。写真などの上に、隠すつもりで見えない字を置いたものも数えない（0.2.0 の決まり。文字認識はしないため）。
- 切り抜きは箱で近似する。円などで切り抜いた外の字は、箱の中なら見逃す。
- 下の色は、字の中心の1点で見る。模様（Pattern）・グラデーション（shading）は、下の色として数えない（地を白とみなす）。
- 画像の色は平均の明るさで見る。白い所と黒い所が混ざった画像の上の字は、same_color を見誤ることがある。
- 字の色は、字の形（グリフ）が実際に塗る所を見ない。白い字の形の中に黒いふちがある書体などは、見誤ることがある。
- 字の高さは、書体の箱（FontBBox）から出す。書体によっては実際の字より大きく、tiny を見逃すことがある。
- 字の上に別の字を重ねて隠したもの（黒い字の上に、同じ位置の白い四角の字など）は見ない。
- 1ページの命令が 30 万を超えるページは省く（`skipped_pages`）。
